# darepedia デザインコンポーネント集

ユーザー提供の記事①②から抽出したHTML装飾部品。固定テンプレートを機械的に流用するのではなく、記事の内容・トーンに合わせて配色や文言を調整して使う。**同じ型を記事内で3回以上繰り返さない**。

## 技術ルール（共通）

- 装飾用の`<style>`ブロックは記事冒頭・summary-card直前に1回だけ配置する
- スマホ表示を想定し、固定pxでの横幅指定は避け、`width:100%`・`box-sizing:border-box`を基本にする
- すべての`<aside>`・カード状`<div>`/`<section>`に`role="region" aria-label="..."`相当の意味づけ（`aria-label`）を付与する
- スマートクォート（U+201C/201D/2018/2019）を混入させない
- **この記事のブロック全体（`<style>`〜装飾HTML）を`<!-- wp:html -->`〜`<!-- /wp:html -->`で囲む。**darepedia.comはshira-treat.comと同じWordPress構成のため、Gutenbergブロックコメントは必須（`wordpress_output_rules.md`参照。2026-08-26訂正：旧版は「ブロックコメント不要」としていたが誤りだった）

## 1. 冒頭summary-card（記事①②で使用）

記事冒頭・リード文の直前に置く要約ボックス。`.summary-card`クラスで、青系グラデーション背景・角丸・影付き。内部に`.summary-row`を2〜3行（見出し語＋説明文のペア）配置し、末尾に関連記事への`.summary-link`を1本添えてよい。

用途：
- 時事速報・炎上考察型では**必須**（「何があった？」「対応」「影響」等のキー情報を先出しする）
- プロフィールWiki型では任意（記事が長い・情報量が多い場合に使う）

## 2. 2カラムgrid要点カード（3バリエーション）

`<section style="display:grid;grid-template-columns:repeat(2,1fr);gap:10px;...">`で複数の`<article>`要点カードを並べる形式。本文の理解を助ける箇所（依頼内容の整理・論点の整理・対応まとめ等）に使う。

| バリエーション | 特徴 | 使いどころ |
|---|---|---|
| シンプル型 | 背景色のみで区切る（`#f7f9ff`/`#fbfbff`/`#f7fffb`の3トーンをローテーション） | 基本的な事実整理 |
| 番号付きアイコン型 | 見出しに①②③の丸アイコンを付与、グラデーション背景 | 複数の理由・要因を順序立てて示す時 |
| ハイライト強調型 | 左ボーダー太め＋グラデーション背景、絵文字アイコン付き見出し | SNS予想・候補比較など対比を見せたい時 |

同じバリエーションを1記事内で使うのは2回までを目安とし、3回目以降は別バリエーションに切り替える。

## 3. SNS埋め込み

X（Twitter）・InstagramのURLを、単独の`wp:paragraph`ブロック内に生URLとしてそのまま配置する（例：`https://x.com/xxxx/status/xxxx`）。技術フォーマット（生URL/埋め込みコードの書き方）は`wordpress_output_rules.md` §6が唯一の正。

- 埋め込みURL・埋め込みコードは事実確認済みの一次情報・公式発表・本人発信に限定する（出典不明の転載・二次拡散ポストは避ける）。SNS投稿の埋め込みはユーザーから資料として受け取る運用とし、自動リサーチはしない（`.claude/commands/darepedia-article.md` Step 0）
- 1記事あたりの埋め込み数は本文の長さに応じて2〜4本程度を目安にする。2本以上使う場合は連続配置せず、本文セクションを挟んで分散させる
- 人物の顔写真が写っている投稿は、記事末尾に専用見出しでまとめず、最初の見出し直下やプロフィール表の直前など「本人の姿を見せる意味がある場所」に配置する

## 4. プロフィール表（プロフィールWiki型で必須）

生年月日・出身・所属事務所等を`<table>`または簡易`<div>`グリッドで表形式にする。不明な項目は空欄にせず「非公表」「不明」と明記する（捏造禁止）。
