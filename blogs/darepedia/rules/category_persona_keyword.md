# darepedia カテゴリ・ペルソナ・キーワード設計

## サイトの位置づけ

darepedia（https://darepedia.com/）は「ドラマ・動画・ニュースなどで話題になった人物が誰なのか、どんな人なのか」を検索した読者に即答する、人物特化型Wikiまとめブログ。1本の記事で人物の全属性を網羅するのではなく、**1人物×1属性（プロフィール／彼氏・旦那／学歴／裏垢…）＝1記事**でロングテールの検索意図ごとに面を広げる設計。

## カテゴリ（4種・category-sitemap.xml確認済み）

| カテゴリ | スラッグ | 対象 |
|---|---|---|
| 芸能人 | `celebrity` | 俳優・タレント・YouTuber/インフルエンサー含む |
| スポーツ選手 | `sports` | フィギュアスケート選手等 |
| 専門家等 | `expert` | 番組コメンテーター等 |
| その他 | `others` | 政治家家族など、上記に当てはまらない話題人物 |

新記事のカテゴリ判定に迷う場合はユーザーに確認する（憶測で新カテゴリを作らない）。

## 想定ペルソナ

- テレビ・ニュース・SNSで見た人物の名前や関係性が気になり、**Google検索で単発的に流入**する一般ユーザー
- サイトへの帰属意識・ブランド認知は低く、「答えが早く分かればいい」という即時解消型のニーズ
- モバイル比率が高いと想定（トレンド人物検索は反射的な検索が多い）
- 滞在は短時間・単発訪問が基本。リピート化よりも検索流入量の最大化が生命線

## キーワード調査の進め方

1. **一次資料確認を最優先する**（`article_pipeline.md`工程1の前提）。ユーザーから提供された放送内容・公式発表・SNS投稿等があれば、それを事実情報の基盤にする。
2. 一次資料が無い、または裏取りが必要な場合のみWebSearch/WebFetchで補完する。ただし個別の詳細情報（家族構成・所属事務所の内部情報等）はWebSearchでは限界があることを前提に、判明した範囲で提示し不足があればユーザーに追加資料を依頼する（shira_note `shira-keyword-article.md` Step0と同じ精度限界の前提）。
3. 同一人物の既存記事が`internal_links.md`にあれば、その記事のスラッグ命名・見出し構成パターンを踏襲する。
4. 想定される派生キーワード（同一人物の別属性記事の可能性）を洗い出し、将来的な連載展開の候補としてメモする。

## キーワード選定の判断基準（2026-08-26確定・ユーザーとの実地検証で確立）

タイトル・スラッグを決める前に、必ず候補キーワード（2〜3語目安）を実際にWebSearchし、1ページ目の構成を見て判定する。**推測・一般論だけで難易度を判断しない。**

### 判断の軸

| 軸 | 見るポイント |
|---|---|
| ①競合の"顔ぶれ" | 大手ニュース／公式アカウント／Wikipedia等が上位を占めていないか |
| ②競合の"中身の種類" | 大手が出ていても、それが単発ニュース・SNS投稿・動画など「網羅的なWiki型まとめ記事」ではないなら、実質的な競合にはならない（darepediaと同じ土俵の競合＝個人ブログ・まとめサイトの数で難易度を測る） |
| ③検索意図の性質 | 「〇〇 インスタ／Twitter／X」のような**固有名詞＋プラットフォーム名**は、たとえ記事競合が薄くても避ける。Googleが本人の実アカウントを優先表示するナビゲーショナル型の意図であり、記事が上位に入ってもクリックされにくい構造的な弱点がある |
| ④コンテンツの厚み | 競合が薄くても、事実が一点（例：出身地だけ）で終わる語は単体記事として薄くなりすぎる。材料の量と合わせて判断する |
| ⑤バランス | ①〜④を踏まえ、「上位表示のしやすさ」と「見込めるアクセス（検索需要・コンテンツの厚み）」の両方が高い語を優先する。上位表示しやすいだけの語（thin content）を機械的に選ばない |

### 判定の考え方（原則を誤って硬直運用しないための補足）

「大手・ニュースサイトが1つでも出たら即除外」という単純な二択にはしない。例えば「〇〇 歯」でYahoo!ニュース・地方紙記事が1本ヒットしても、それが単発ニュースの転載であり、同じ切り口を扱う個人ブログのまとめ記事がまだ無ければ、白地（狙う余地）が残っていると判断してよい。逆に、同テーマを扱う個人ブログが複数すでに存在する場合は、大手の有無に関わらず差別化が必要になる。

## 捏造禁止
