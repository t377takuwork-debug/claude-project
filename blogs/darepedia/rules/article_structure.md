# darepedia 記事構成テンプレート（H2/H3設計）

記事タイプごとのH2/H3構成。使用するのはH2とH3のみ（H1＝確定タイトルは本文に含めない）。

## 共通ルール（両タイプ）

- 最低1つのH2は質問形にする
- FAQはまとめ直前に必ずH2として設置し、内部はH3で3〜4問
- 最後は必ず「H2 まとめ」で締め、まとめにH3は付けない
- タイムテーブル・発表内容が未確定の場合は「現時点で分かっている範囲」「発表されている範囲」など断定・誤解を避ける表現を見出しに使う
- 整理済み素材にない事実は見出しにも本文にも追加しない（捏造禁止）

---

## 1. プロフィールWiki型

「〇〇は何者？」に答えるストック型記事。既存サイトの`uchiboritaro-wiki`記事構成を踏襲。

| 見出し | 役割 | 目安 |
|---|---|---|
| リード文 | 検索意図への即答＋記事で分かることの要約 | 3〜5文 |
| H2: 〇〇は何者？プロフィール・経歴（まとめ） | 冒頭に**プロフィール表**（生年月日・出身・所属等、判明分のみ）を設置し、概要を1段落で示す | 400字程度 |
| H2: 〇〇のプロフィール・経歴詳細 | 経歴の詳細。H3で節目ごとに分割してよい（例：デビューのきっかけ／代表作） | H3は220〜280字 |
| H2: 〇〇の出演作・活動（対象トピック） | 今回の記事のきっかけとなった出演作・活動内容を深掘り | H3で個別作品/エピソードに分割可 |
| H2: 〇〇のSNS・現在の活動 | 判明している範囲のSNS運用・直近の活動 | 未公表なら「非公開」「情報なし」と明記 |
| H2: 〇〇に関するよくある質問（FAQ） | H3×3〜4問。属性記事（彼氏/学歴等）で聞かれやすい質問を想定 | 各Q&Aは簡潔に |
| H2: まとめ | 記事全体の要点を2〜3文で総括 | H3なし・400字目安 |

属性特化記事（`-kareshi`/`-danna`/`-gakureki`等）の場合は、上記の「出演作・活動」H2を対象属性のセクションに差し替える（例：`-kareshi`なら「H2: 〇〇の彼氏は誰？噂の真相」）。

## 2. 時事速報・炎上考察型

放送・報道直後の出来事を整理する記事。ユーザー提供の記事①（ヤングケアラー騒動）を構成モデルとする。

| 見出し | 役割 | 目安 |
|---|---|---|
| リード文＋summary-card | 何があったか・現在の状況・関連記事への導線を3行程度の要約ボックスで先出し（`design_components.md`のsummary-card使用） | 3〜5文 |
| H2: 〇〇「出来事名」何があった？ | 出来事の概要と経緯。H3で時系列の節目に分割 | H3は220〜280字 |
| H2: なぜ話題/炎上した？理由 | 反響が広がった背景・論点。視聴者/読者が引っかかったポイントを整理 | 表・カード形式推奨 |
| H2: （該当があれば）象徴的な場面・発言の深掘り | 特に拡散した発言・シーンがある場合のみ設置。無ければ省略可 | 任意 |
| H2: 〇〇疑惑・論点は本当？定義や背景を解説 | 社会的文脈（制度・定義等）の整理。断定を避け、公的な定義と今回のケースの論点を分けて書く | 表形式推奨 |
| H2: 対応・反応まとめ（行政/公式/SNS） | 公式声明・行政対応・SNS上の賛否両論を事実ベースで整理。誹謗中傷助長を避ける書き方（`writing_tone_and_ethics.md`） | H3で分割可 |
| H2: よくある質問（FAQ） | H3×3問 | 簡潔に |
| H2: まとめ | 誰かを断定的に断罪する結び方を避け、社会的な論点として締める | H3なし |

## 使い分けの目安

- 情報が確定している人物属性の解説 → プロフィールWiki型
- 放送・報道直後で情報が流動的、賛否が分かれている出来事 → 時事速報・炎上考察型
- どちらに当たるか迷う場合はユーザーに確認する
