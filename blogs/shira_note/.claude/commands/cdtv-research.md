# CDTV リライト用 資料①②リサーチ

`/cdtv-rewrite` で資料①（または資料①②とも）が渡されなかった回に、本編リライトへ入る前に実行するリサーチ手順。

**このファイルを読むのは「資料が渡されなかった回」だけ。** 資料が渡された回は `cdtv-rewrite.md` の「リライト手順」1へ直行する（このファイルは読まない）。

完了条件：整形した資料①②を `tools/output/cdtv_material.md` に保存し、チャットでユーザー承認を得ること。承認前に `cdtv-rewrite.md` のリライト手順へ進まない。

番組の固定情報（放送局・公式サイト・公式X・進行など）は `cdtv-rewrite.md`「番組基本情報（固定）」を正とする。ここで扱うのは毎回変わる情報だけ。

## 資料① リサーチ手順

1. **主① THE FIRST TIMES まとめ記事を WebFetch。** プロンプトは「**次回『CDTVライブ！ライブ！』の 放送日・放送開始時刻・放送時間（通常/2時間SP/3時間SP）・チャンネル／全出演アーティスト／各アーティストの全歌唱曲／初披露・コラボ・特別企画・特別編成名／出演順・タイムテーブルの記載があればそれも を抽出。記事に無い項目は『記載なし』。憶測で補わない。この記事が定期更新のまとめ記事か（最終更新日）も確認**」。ここで放送日・出演者・曲がほぼ揃う。
2. **主② Yahoo!ニュース検索を WebFetch。** プロンプトは「**『CDTVライブ！ライブ！』の放送回に言及する記事だけを放送日ごとに列挙（見出し・配信元・配信日時・記事URL）。CDTV以外（他番組・グッズ等）は除外。今日以降で最も近い次回放送を報じる最新記事を明示。本文要約は不要。記事URLは `news.yahoo.co.jp/articles/...` 形式で**」と絞る（返り値を小さく＝トークン節約）。この一覧が「実際の放送カレンダー」になり、飛んだ週・特番週・日曜特番の判定と『直近の放送回の特定』（下記）に使う。
3. **主①と主②で拾った出演者・曲を突き合わせる。** 検索結果ページのサマリーに並ぶ出演者・曲名は単体では信用しない（別日のゲストや密着記事の名前が混ざる）。**曜日ラベルもWebFetchが誤ることがある**（月曜放送を「日」と書く等。放送日の数値を正とする）。食い違い・欠落がある項目だけ、**個別記事（歌唱曲一覧付きの本文）を1〜2本 WebFetch して確定**する。確定する抽出項目：
   - 放送日・**放送開始時刻・放送時間（通常 / 2時間SP / 3時間SP など）**・チャンネル
   - 全出演アーティスト
   - **各歌唱曲（曲名を省略・要約せず全曲そのまま）**
   - 初披露・テレビ初披露・フルサイズ初披露・世界初パフォーマンス・コラボ・特別企画・VTR企画（「名曲ライブ！ライブ！」等）
   - **特別編成名（◯時間スペシャル等）と、SP回のタイムテーブル**（下記手順6）
   - **マンスリーライブ枠の有無**：ある場合はアーティスト名・第◯週・披露予定曲。**無い回もある**ので「記載なし」を許容する
   - **記事にない項目は「記載なし」とし、憶測で補わない。**
4. **曲のタイアップ・背景注記**が記事にない曲は、**明らかな定番曲を除き最大2曲まで**、その曲を報じる記事を1本ずつ追いフェッチする。3曲以上不明なら追わず、該当カードは「◯◯を披露。」の最小記述にする。
5. 放送枠（開始・終了時刻）を確定する。**「通常回は19:00〜20:55」と思い込まない**（2時間でも開始が18:30〜など前後する回がある）。取得順は「主①まとめ記事の記載 → `tools/output/programs.md` を Read → どちらも無ければ記事記載の開始時刻＋通常枠を仮置きし、承認提示時に**終了時刻＝要再確認**と明示」。**bangumi.org EPG は放送の約8日前からしか載らない**ので、それより先のリライトでは EPG を試さない（404になるだけ）。**特別編成・時刻変更が判明している回だけ**、放送8日前以降に EPG（bangumi.org）で開始〜終了を確定する。確定した「HH:MM〜HH:MM」と放送時間（通常 / 2時間SP / 3時間SP）は、`cdtv-rewrite.md` の後半時間帯ラベル（`20:00〜20:55` / `20:00〜22:00`）・放送時間傾向パラグラフ・FAQ・JSON-LD で共通利用する。
6. **スペシャル放送（◯時間SP）の場合はタイムテーブルの事前発表を確認する。** 通常回は分刻みタイムテーブルが事前公開されないが、SP回は公式・記事で出演順やタイムテーブルが先出しされることがある。主②の検索結果に「タイムテーブル」「出演順」を含む見出しがあれば、その記事を1本 WebFetch して転記する。事前タイムテーブルが取れた回は、`cdtv-rewrite.md` 手順8（実際の出演順）に暫定として反映でき、放送後の資料②Grokの負担が減る。**発表が見当たらなければ「事前タイムテーブル発表なし」と明記**し、通常運用（出演順は放送後更新）にする。
7. 主②の検索が取得不可の場合のみ、THE FIRST TIMES キーワード一覧 → それも不可なら公式サイト／公式X を Claude in Chrome で確認する。どうしても出演者が確認できなければ「出演者未発表」として扱い、その旨を承認提示に明示して `cdtv-rewrite.md` のプレースホルダー運用（歌唱曲は後日発表 等）に切り替える。

> **資料①の完了条件**：全出演者・全歌唱曲が確定していること。放送日時・放送時間（通常/SP）が確定していること。マンスリーライブ枠の有無が確定していること（ありなら週数・アーティスト・曲）。SP回は事前タイムテーブルの有無を確認し、あれば転記していること。揃わない項目は承認提示時に赤字相当で明示する。

## 直近の放送回の特定（資料②の前に必須）

「先週の月曜」を機械計算しない（CDTVは毎週放送とは限らず、飛ぶ週・特番週・日曜特番がある）。次の手順で確定する。

1. `draft_cdtv.txt` の**現在のメイン記事の放送日**を読む（＝前回リライトが用意した回）。これを直近放送回の第一候補とする。
2. その日付が **今日より前**なら、放送済み＝直近放送回の候補として確定に進む。今日以降（未放送）なら、直近放送回は「実際の出演順【放送後更新】」テーブル（`cdtv-rewrite.md` 手順8）の日付。
3. 資料① 手順2（Yahoo検索）で得た「放送日ごとの記事一覧」を照合し、**候補より後・今日より前に別のCDTV放送日がないか**確認する。あれば最も新しいその日を直近放送回に更新する。
4. **「実際の出演順【放送後更新】」テーブル（`cdtv-rewrite.md` 手順8）の日付と照合**：
   - テーブル日 ＝ 直近放送回 → 資料②は取得済み。**Grokをスキップ**しテーブル内容を流用。
   - テーブル日 ＝ 直近放送回のちょうど1回前 → 正常。**Grokを実行**（下記）。
   - テーブル日が2回以上前（サイクルスキップ）→ 直近放送回でGrok実行。間の回は granular データ欠落として承認提示時に明示。
5. 上記で直近放送回が一意に確定できない場合は、**Grokを回さず「直近の放送回は◯月◯日で合っていますか」とユーザーに確認**してから進む。

> **`cdtv-rewrite.md` 手順1②'（退避データ）との取り違え注意**：「実際の出演順」テーブルの現在の中身は**前々回**のデータで、今回の資料②で上書きされる。資料②＝ここで特定した**直近放送回**のデータ。②'（前々回）は手順10で過去一覧へフルカード化する別物。混同しない。

ここで確定した日付・（特番なら）特別編成名を、下のGrokプロンプトに実際に埋め込む。

## 資料② リサーチ手順（Grok 主 ＋ TVer 補正）

資料②は**直前回（＝上で特定した直近放送回）の実出演順・時間帯・SNS反応**。

- **組み立ての基準は Grok の X実況分析**（下記 A）。real-clock の時間帯（19時台／20時台の割り振り）・SNS反応（投稿爆発の瞬間・Key_Insight）はGrokでしか取れない。
- **TVer のチャプター（B）は「登場順・歌唱曲の確実な裏取り」**。2026-09-08 の実地テストで Grok と TVer の曲順が完全一致することを確認済み。**順番の食い違いが出たら TVer を正として Grok を見直す**。ただし TVer の `MM:SS` はCM抜き・Part分割なので、**実放送時刻への機械換算はしない**（時間帯は「この2組の間隔をもう少し開ける/詰める」程度の相対補正だけ）。
- 配信期間切れ等で B が取れない回は A だけで確定してよい。

**実行するのは**「直近の放送回の特定」手順4で **Grokを実行** と判定した場合のみ。スキップ判定ならこの節を飛ばし、「実際の出演順」テーブルの内容を資料②として使う。

**事前情報の抽出（プロンプトへ差し込む。ドラフト上書き前に実施）**
「直近の放送回の特定」で確定した回のデータは、**上書き前の `draft_cdtv.txt` の現メイン記事**から吸い出す。

| プロンプトの欄 | 供給元（draft_cdtv.txt 内） |
|---|---|
| 放送日 | 現メイン記事ヘッダー／H2タイムテーブルの日付 |
| 分析対象期間（19:00〜21:00 の置換値） | **資料①で確定した放送開始〜放送終了＋約1時間**（例：18:30開始の2時間回→`18:30〜21:30`／3時間SP→実終了＋約1時間）。放送枠は aside BROADCAST ／ H2放送概要サブテキストから取る |
| 出演アーティスト＆全歌唱曲 | `cdtv-rewrite.md` 手順5の出演者カードグリッド（＝全組・全曲。JSON-LD `mentions` / BroadcastEvent `performer` でも可） |
| 長尺企画・特別編成の有無 | aside 注目バナー・見どころカード・「プラチナライブ」等のコーナー名・「◯時間SP」バッジ |

### A. Grok（基準データ）

**取得手順**（`env_grok_chrome_automation.md` の回避策に準拠）
1. `mcp__claude-in-chrome__tabs_context_mcp` で状態確認 → 新規タブ → `grok.com` へ navigate（ログイン済みChromeが前提。未ログイン・拡張不可なら下の「フォールバック」へ）。
2. ページ確認・要素操作は **`javascript_tool` のみ**（`screenshot`/`read_page`/`get_page_text` は常時通信SPAでタイムアウトするため使わない）。
3. 入力欄 `.tiptap.ProseMirror`（contenteditable）へ **`DataTransfer` ＋ `ClipboardEvent('paste')` を合成**してプロンプトを一括投入（`computer.type` は改行で誤送信される）。送信は `button[aria-label="送信"]` をクリック。
4. **完了検知**：`.message-bubble.relative.rounded-3xl` 最終要素の `innerText` を **1回あたり20秒**の `setTimeout` 待ちでポーリングし（`javascript_tool` の1呼び出しは約30秒でCDPタイムアウトするので45秒待ちなどにしない）、**テキスト長が2回連続で不変** かつ 末尾が「`Ns 作業しました`／`作業内容: Ns`」または「`N sources`」で終わっていれば完了。`button[aria-label="停止"]` が消えていることも併用してよい。**上限7分**（2026-09-08 実地テストの通常回は約1分・ポーリング2回で足りた）。
   **抽出は最終 innerText を丸ごと1回だけ**。冒頭のツール検索ログ（「検索した𝕏 for …」の連続）を捨て、`ヘッダー`以降（出演者＋全歌唱曲リスト／時系列表／登場順まとめ／補足）を採用する。**時系列表を「19:11以降」「20:09以降」のように分割して複数回 slice 取得しない**（2026-09-08 はこれで抽出コールが5回に膨らんだ。1回で切れるほど長い時だけ2回に分ける）。
5. Grokプロンプト（1回・改行あり）。**`[ ]` は事前情報の抽出で得た実値に置換してから投入**（プレースホルダーのまま送らない）。**`[分析対象期間]` は 19:00〜21:00 固定ではなく、上表で置換した実際の放送枠**にする：

### B. TVer（登場順・曲順の裏取り／時間帯のバランス調整）

TVerの各エピソードページに、**コーナーごとのチャプター（`【MM:SS】曲名・アーティスト` 形式）が載る**。2026-09-08 の実地テストで、Grokの登場順とTVerのチャプター順が**完全一致**することを確認した。**曲順・出演順の一次確認はTVerが確実**（Grokは real-clock 時刻とSNS反応を足す役割）。ただしTVerの `MM:SS` は **Part.1/2/3 に分割された動画ごとの経過秒でCM抜き**なので、実放送時刻への機械換算はしない。時間帯は「この2組の間隔はもっと開く/詰まる」程度の相対補正にとどめる。

**取得手順**（`tver.jp` は WebFetch 不可＝SPAで空シェル。Claude in Chrome のみ。2026-09-08 実地テスト済み。**Chrome往復は series 1 ＋ Part 3 =計4回以内**に収める）
1. `https://tver.jp/series/sr2cbxi72h` を navigate → 3秒待つ → `javascript_tool` で `a[href*="/episodes/"]` を集めると、直近放送回の Part.1〜3（各 `epXXXXXXXX`）が「32分【Part.1】…9月7日(月)放送分」の形で並ぶ。放送日ラベルで直近回の Part を特定する。
