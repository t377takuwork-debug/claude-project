- **差分EditのみでWriteしない**：Grepで行番号取得 → offset/limitで最小範囲Read → Edit

## リライト手順

### 1. タイトル・メタ

先頭のプレーンテキスト行をEditする（WPブロックなし）。

| 要素 | 内容 |
|---|---|
| タイトル | `1億2000万人のありがとう 歌の感謝祭タイムテーブル【{月}月{日}日】出演者・出演順まとめ` |
| メタ | 90〜120字。放送日時・「秋冬編」等の回次名称（あれば）・出演組数・「出演順」を含める |

**数値を焼き込まない原則の例外**：番組公式名称に含まれる「1億2000万人」はタイトル固有名詞の一部なので削らない。出演組数（「12組」等）はタイトルに入れず、メタでのみ使ってよい。

### 2. 冒頭文

| 段落 | 内容 |
|---|---|
| 1段落目 | 「日本テレビ系音楽特番「1億2000万人のありがとう 歌の感謝祭」の放送日程やMC、出演アーティスト、タイムテーブルをまとめています。」（固定文言、変更不要） |
| 2段落目 | **放送形式の変更点のみ**。前回との時間枠の違い（3時間⇔4時間等）がある回はここに書く。無い回はこの段落を省略するか「前回と同じ◯時間構成で放送されます。」に差し替える |

### 3. 速報ガイドaside（`aria-label="歌の感謝祭 速報ガイド"`）

| 更新要素 | 内容 |
|---|---|
| SCHEDULE行 | `YYYY.MM.DD (曜) HH:MM - HH:MM` |
| MC行 | 今回のMC名（毎回変わりうる。第1回は渡辺翔太・波瑠、第2回は渡辺翔太・比嘉愛未） |
| ARTISTS行 | 代表アーティスト名2〜4組＋「他、全◯組」 |
| SPECIAL行 | 今回の目玉企画1〜2行 |
| Update日付 | 更新作業日 |

### 4. 締め文（`[nopc][mokujimae][/nopc]` 直後）

1文のみ。具体企画名の詳述はせず、最新情報の確認を促すだけに留める（例文は現draft参照）。

### 5. H2：歌の感謝祭 タイムテーブル

- H2直下リード文（1文）と「各時間帯内の細かい出演順は非公開」の注記文を更新
- 時間帯ごとのaside（`aria-label="歌の感謝祭 タイムテーブル（◯時台）"`）を今回の時間帯数だけ用意する。**時間帯数は放送枠に応じて変わる**（第2回は19〜22時台の4ブロック）
- 各カードは「時間帯＋アーティスト名＋曲名」を基本とし、タイアップ等の周辺情報が判明している場合のみ1文追記する（捏造禁止。判明していない情報は書かない）
- `[nopc][originalsc][/nopc]` は時間帯asideの間（既存draftでは20時台と21時台の間）に配置。他のショートコードと隣接させない

### 6. H2：歌の感謝祭 出演アーティスト・歌唱内容一覧

- グリッドaside（`aria-label="歌の感謝祭 出演アーティスト・歌唱曲一覧"`）を今回の出演者数分のカードで更新
- 1アーティストが複数曲披露する場合はカード内に「」区切りで曲名を列挙する（例：`「曲A」「曲B」`）
- ゲスト（歌唱なしの出演者）が判明していればカード群の下に1行でまとめる

### 7. H2：出演時間は何時頃？構成傾向【目安】

- 手順5で確定した時間帯ブロックごとに、出演者名の要約＋一言コメントのカードを更新する（同じ曲名列挙を繰り返さない。11-1のセクション重複排除ルール準拠）
- 下の3段落（総枠時間・進行形式・MC楽曲への言及）を今回の情報に更新

### 8. H2：よくある質問（FAQ）

計4問（固定枠ではなく毎回内容が変わる想定）。

| 問 | 内容 |
|---|---|
| Q1 | タイムテーブル事前発表の有無（定型文言に近いが、情報源に応じて微調整） |
| Q2 | 今回固有の特別企画についての質問 |
| Q3 | 今回固有の注目楽曲・コラボについての質問 |
| Q4 | 見逃し配信の有無（**推測で「あり/なし」を断定しない**。公式サイト・TVerでの確認を促す文言に留める） |

### 9. H2：まとめ

放送日・MC・出演者・見どころを3〜5段落で要約する。主観形容詞は避け、事実ベースで書く（`rewrite_common_rules.md` 1章）。

## JSON-LD

ファイル末尾（`MANUAL_JSONLD` マーカー直後）。`draft_star.txt` の構造を踏襲した `@graph`（BlogPosting / BroadcastEvent / ItemList / FAQPage / BreadcrumbList）。

> **ユーザーがタイトル・メタディスクリプションを直接編集した場合は、次のやり取りで必ずJSON-LDの`headline`／`description`を再同期する（聞かれる前に自分から確認する）**。2026-09-23の初回運用で、ユーザーがタイトル・メタを手直しした際にJSON-LD側の更新を忘れ、`qa_draft.py`が「メタディスクリプションとJSON-LD descriptionが不一致」のERRORを検知する事態が実際に発生した。メタの文字数表記（`メタディスクリプション（n字）：`の`n`）も実測し直すこと。

### 毎回更新

| フィールド | 内容 |
|---|---|
| `description` | メタと**一字一句同じ**文字列 |
| `dateModified` | 更新日時（YYYY-MM-DDTHH:MM:SS+09:00） |
| `keywords` | 今回の出演者名・放送月日等 |
| BroadcastEvent `name`／`startDate`／`endDate` | 今回の放送情報 |
| BroadcastEvent `performer` | 出演者全員（`MusicGroup`/`Person`の型判定は `generate_jsonld.py` のルールに準拠） |
| ItemList `numberOfItems`／`itemListElement` | 出演者数・一覧（performerと同じ並び） |
| FAQPage `mainEntity` | 記事本文Q&Aと**一字一句一致** |

### 変更時のみ更新

| フィールド | タイミング |
|---|---|
| `headline` | タイトル変更時 |
| `image`／`thumbnailUrl` | 新アイキャッチURL提供時 |

### 固定（変更不要）

`@id` / `url`・`author`・`publisher`・`about`・`articleSection`。ただし `about[0].sameAs` は公式サイトURLが変わった場合のみ更新。

**BreadcrumbListの `item`（歌の感謝祭カテゴリURL）は未確認の推測値**（`https://shira-treat.com/category/musictv/kanshasai/`）。WP側の実際のカテゴリURLが判明したら修正する。
