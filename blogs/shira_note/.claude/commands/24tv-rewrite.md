## リライト手順

### 1. タイトル・メタディスクリプション

`rewrite_common_rules.md` 3章準拠（数値を焼き込まない・誇張語NG・年号は「24時間テレビYYYY」の形式）。
メタディスクリプションに「出演順」「順番」のいずれかを必ず含める。

- **書き換え前に現行タイトル・メタを控え、既存の検索KWを落とさない**（`rewrite_common_rules.md` 3章「年次更新でタイトル/メタを書き換えるとき」）。この記事の必須KW＝**「24時間テレビ タイムテーブル」（番組名の直後に隣接）／出演者／スケジュール／順番・出演順**。1語でも削るなら理由を添えて提案してから消す
- 状態変化リライト（未発表→発表済み等）でも、変わるのは「随時更新」等のステータス語だけ。KW本体は据え置く

### 2. リード文・aside「最新情報」

- リード文2文（1文×2段落）：放送日程・テーマの紹介＋更新告知（更新告知は入れない。`rewrite_common_rules.md` 2章準拠）
- 冒頭2段落目は「放送形式の変更点」枠。配信形式・会場・放送時間の変更があればここに書く（無ければ従来文を維持）
- asideのSTATUS/ARTISTS/TIMETABLE行を今年の判明情報に更新
- 💡見どころ行を今年の目玉企画に更新
- **配信形式に変更があった年（例：TVer全編リアルタイム配信）は横断更新**：リード文2段落目・aside・手順8（見逃し配信H2）・FAQ Q3・JSON-LDの`BroadcastEvent.description` の5箇所をまとめて直す

### 3. H2：最新タイムテーブル

- **未発表時**：「未発表」バッジ＋通知文のまま維持し、判明済み傾向（過去実績）のみ更新
- **発表後**：既存draft内の「予想の流れ」グラデーション枠カード（日別2枚）をそのまま流用して組み替える。①ステータスボックスのバッジ「未発表(赤)」→「発表済み(緑 #1B8A3E)」＋通知文を発表版へ ②カードの `予想` バッジ→`TIME TABLE`、aria-label・見出しの「予想の流れ」→「タイムテーブル」 ③行は**1時間帯＝1行**（複数企画は「／」で連結）。時刻表記は資料の粒度に合わせ、分刻みが無ければ「19時台」等のまま ④触るので行の `font-size` は `clamp()` 化（12章） ⑤末尾の「※上記は予想です」注記を「※時間帯は目安／生放送のため前後・分刻みは放送後に更新」へ
- 30時間表記（「26時台」等）は `rewrite_common_rules.md` 15-2 に従い「26時台（翌◯時ごろ）」と併記し、資料の表記どおり初日カードへ置く

### 4. H2：出演者一覧・企画一覧

- 出演者table（総合司会／チャリティーパートナー／スペシャルサポーター／チャリティーランナー／スペシャルドラマ等）を最新の発表に更新
- 企画・コラボtableに新規発表分を追加
- **グループ名と個人名の表記統一**（`rewrite_common_rules.md` 13章準拠）
- **前回資料から分類が変わった出演者**（例：「ドラマ主演」→「スペシャルサポーター」、企画出演→パートナー昇格）は、旧記載を上書きしてよいか・旧情報の扱いをユーザーに確認する。最新資料に記載のない旧情報（主演・脚本名など）は断定で残さない
- **タイムテーブル発表後は企画・コラボtableがタイムテーブルと情報重複する**。表の役割を「企画→出演者」から「出演者→主な担当企画」へ寄せる／グループをメンバー単位に分解する等の再編を行う場合は、`rewrite_common_rules.md` 11章に従い**実施前に提案して承認を得る**（2026-08-29リライトで無断再編しユーザー確認が事後になった）

### 5. H2：出演時間は何時頃？【目安】

**現行draftにこのH2は通常存在しない**（過去のセクション統合で削除済み）。Grepで見つからなければこの手順はスキップする。
将来タイムテーブル未発表運用でこの節を復活させる場合のみ：「前回は〜でした」の事実ベース表現を維持し断定調にしない（`rewrite_common_rules.md` 10-3準拠）。発表後は確定時間へ差し替えるか節ごと削除。

### 6. H2：順番の傾向

4カードの内容を今年の企画構成に合わせて更新する。番組の実情に応じて絵文字・見出し文言を差し替えてよい。

### 7. H2：実際の出演順【放送後更新】

**直前回（前年）のデータのみ**をここに掲載する（`rewrite_common_rules.md` 11-1準拠）。今回の放送が終わったら、このセクションを今回の実況データに差し替え、旧・直前回データは手順9の過去一覧へ移動する。

**Xポストのタイムスタンプ再構成データを使う場合、放送尺を超える時間帯が含まれていないか必ず確認する。**

### 8. H2：見逃し配信・再放送はある？

配信有無が確認できない場合は「公式サイトでご確認ください」の保留表現を維持する（推測で「なし」「あり」と書かない）。

### 9. H2：過去のタイムテーブル一覧

直前回より前の回のみ掲載。テーマ・出演者の詳細が未確認の年は、放送開始日など確証のある情報のみ記載し、不確かな内容を書き足さない。

### 10. H2：FAQ

5問固定（Q1:事前発表有無／Q2:番組概要・固定／Q3:見逃し配信／Q4:前回放送内容／Q5:放送時間）。Q2は内容が変わらなければ書き換え不要。
- タイムテーブルが発表されたら**Q1**を「発表された」旨へ更新（放送枠HH:MM〜HH:MMは残す）
- 配信形式が変わった年は**Q3**も更新（`rewrite_common_rules.md` 10-1の固定可判定：episode固有情報を含まない配信案内は固定可だが、配信形式そのものが変わった年は更新）
- FAQ本文を直したら**JSON-LD `FAQPage.mainEntity` の該当textも一字一句同期**（この記事のFAQはdiv形式のためqa_draft.pyの本文⇔JSON-LD同期チェックはスキップされる＝手動確認必須）

### 11. H2：まとめ

放送日・テーマ・判明済み出演者・今後の更新見通しを3段落程度で更新する。

### 12. 構造化データ（JSON-LD）の更新

JSON-LDは常にファイル末尾の固定ブロック。

#### 毎回更新する箇所

| フィールド | 更新内容 |
|---|---|
| `description`（BlogPosting） | メタディスクリプションと同じ文字列 |
| `dateModified` | 更新日（ISO形式：YYYY-MM-DDTHH:MM:SS+09:00） |
| `keywords` / `mentions` | 今年の出演者・企画に更新 |
| `ItemList.itemListElement` | 出演者一覧と同期 |
| `FAQPage.mainEntity` | 記事本文のQ&Aと**一字一句一致**させる（5問） |

#### 変更がある場合のみ更新する箇所

| フィールド | 更新タイミング |
|---|---|
| `headline` | タイトルを変更した場合 |
| ImageObject `url` | 新しいアイキャッチ画像URLが提供された場合 |
| `BroadcastEvent.startDate`/`endDate` | 放送日時が確定・変更された場合 |
| `BroadcastEvent.performer` | 出演者確定情報が増えた場合 |

#### 固定箇所（変更不要）

- `@id` / `url`（記事URL：`https://shira-treat.com/24tv-timetable/`）
- `author` / `publisher`
- `about`

#### アーティストの型判定

`tools/generate_jsonld.py`のルールに準拠（グループ・バンド→MusicGroup／ソロ→Person／お笑いコンビ等の芸能グループ→PerformingGroup）。
