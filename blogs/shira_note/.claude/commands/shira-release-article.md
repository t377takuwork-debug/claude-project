# shira_note CD/DVDリリース記事 制作コマンド

CD・DVD・Blu-ray等のリリース情報（発売日・特典・予約先）を扱う、1リリース＝1記事の単発記事制作フロー。
番組タイムテーブル速報（`draft_XXXX.txt`）・キーワード起点記事（`/shira-keyword-article`）とは別枠。

「予約記事を作りたい」「〇〇のCD/DVD発売の記事を作って」「リリース情報の記事を作りたい」と言われたら、このコマンドの手順に従う。

**目的は検索上位表示そのものより「商品リンク経由の購入」を最大化すること。** 判断に迷ったら、この目的を優先する。

設計判断の詳細な根拠・確定履歴は `rules/system_shira_release_article.md`（唯一の正）を参照。本ファイルは実行手順。

---

## Step 0. 資料インプット確認

ユーザーから以下を受け取る（無ければ質問する。捏造禁止・不明点は資料提供を求める）。

| 項目 | 必須 | 備考 |
|---|---|---|
| 商品名・アーティスト名 | ✅ | |
| 形態（CD/DVD/Blu-ray、初回盤/通常盤等の仕様） | ✅ | |
| 発売日 | ✅ | |
| 各仕様の価格 | ✅ | WebSearch/WebFetchで裏取りしてよい（Step0-1参照） |
| 収録内容（曲目・収録公演・演出内容等） | ✅ | |
| 各仕様の特典内容（封入特典・特典映像等） | ✅ | 全仕様共通の特典と、仕様ごとに異なる特典を分けて聞く |
| 購入先URL（公式サイト・楽天ブックス・セブンネット・Amazon・タワーレコード等） | 商品ページ執筆までに必須 | Step6参照。無くても構成設計までは進められる |
| SNS上の購入・予約傾向データ（任意） | 任意 | Step5-3参照。あれば購入導線セクションの根拠に使う |
| アイキャッチ画像URL | 本文完成までに必須 | JSON-LDに反映 |

### Step 0-1. WebSearch/WebFetchでの裏取りの注意

同一アーティストの類似リリース（前年の同時期ツアーグッズ、同時期発売の別形態商品等）と混同しやすい。特に発表直後は該当商品のページが検索エンジンに未反映のことがある。

- 発売日・価格等をWebSearch/WebFetchで確認する際は、**取得した情報の商品名・発売日が資料と一致するか必ず照合する**
- 確度高く特定できない場合は、**推測でリンク・数値を提示せず、ユーザーに直接URLの提供を求める**
- 公式サイト・タワーレコード・セブンネットの商品ページはWebFetchで中身を確認してから使う
- **Amazon・楽天ブックスはWebFetchでの自動検証を最初から試みない**（ボット対策で正常なページでも404/503相当の誤判定が返ることがある）。この2サイトはユーザーに目視確認を依頼する

## Step 1. キーワード整理

必須3要素：①商品名・アーティスト名 ②形態 ③どこで買う・どれを選ぶ（購入導線 or 比較決定）。

- 「予約」「特典」等の単体高ボリューム語**だけ**は狙わない（公式・EC占有で到達性が低い）。「どこで買う」「違い」等と**組み合わせて**タイトル・見出しに含めるのは可
- 「どこで買う」「どっちがいい/どれがいい」は主軸キーワードとして積極採用する（公式サイトが自社目線の訴求文言でしか最適化しておらず、口語の疑問形を拾える余地があるため）
- 比較対象を曖昧にしない（「Blu-ray/DVD、どっちがいい？」は形態比較と誤読されるため、実際の比較対象＝初回盤/通常盤等を明示する）

キーワード拡張整理（主軸/副軸/周辺の3層）を箇条書きでユーザーに提示し、確認を取ってから次に進む。

## Step 2. ペルソナ・検索意図確認

`/shira-keyword-article` Step2と同様、以下をAskUserQuestionまたは提示で確認する。

- 検索意図の分類（比較検討中か、購入直前か等）
- 想定ペルソナ（1〜2パターン）
- この記事の結論（冒頭で言い切ること）

## Step 3. タイトル設計

5パターンで生成する（`/shira-keyword-article`の10パターンをこのジャンル向けに絞り込んだもの）。

| # | パターン | 特徴 |
|---|---|---|
| 1 | 比較優先型 | 「違い」が主役、購入は軽く添える |
| 2 | 購入導線優先型 | 「どこで買うべきか」が主役、比較は軽く添える（**目的が購入最大化なら基本この型を採用**） |
| 3 | 疑問統合型 | 比較＋購入を1つの疑問文で統合 |
| 4 | 断定解説型 | 疑問形を使わず「〜を解説」で言い切る |
| 5 | ライト層向け型 | 初めて購入する層向けの平易な表現 |

**ルール**
- 速報統合型（発売日を焼き込む型）は不採用（陳腐化しやすくアフィリエイト目的の長期流入と相性が悪い）
- 商品名（アーティスト名+作品名+形態）は必ず冒頭に置く
- 文字数は**32〜36字を目標、40字を上限**（SERP表示切れ防止が目的。SEO評価目的ではない）
- **候補を提示する前に、必ずPowerShellで`.Length`を実測する**（目算は誤りの元）
- ユーザーから「予約」「特典」等のワードも入れたいと指示があれば、上記5パターンのどれかに自然に組み込む（主軸キーワードとの併記でよい）

5案を字数付きで提示し、選定・修正を受けてから確定する。

## Step 4. 見出し構成（H2/H3）設計

- **タイトルの優先順位と見出し構成の優先順位を一致させる**（タイトルが購入導線優先型なら、購入導線に関する内容を冒頭寄りに配置する）
- H2見出しの長さは記事内で揃える（1つだけ突出して長くならないようにする）
- 収録内容（セットリスト等の長い一覧）は、特典差など決定要因になる情報より**後**に配置する
- **内部リンク導線**をまとめセクションに含める（同ジャンル記事がまだ無くても、将来の相互リンク・カテゴリページ導線として設計だけしておく）
- FAQは3〜4問、まとめ直前に配置

**リンク離脱対策（多重導線）**：以下の段階でリンクに触れる機会を作る（各段階は必要に応じて省略可）。

1. リード文直後の冒頭クイック情報ボックス（発売日・価格・予約リンク）
2. 比較結論部
3. 特典差など個別セクション
4. 購入導線の詳細H2（全リンクを集約）
5. まとめ（省略可）

**各タッチポイントは複数ショップを選べる形にする**（1タッチポイント1ショップに固定しない）。ただし**リンク先が実際にどのSKU（単体仕様かセット商品か）を指しているか確認し、ラベルと一致させる**。単体仕様の直リンクが無い場合は「セット商品ページです」等、正確な注記を添える。

構造化アウトライン・メタディスクリプション案（PowerShellで字数実測）・スラッグ案・設計意図メモの4点セットを提示し、確認を取る。

## Step 5. 本文執筆

### 5-1. 見出しレベル・段落ルール

`rewrite_common_rules.md`の禁止ワード・段落ルール（1段落1テーマ等）に加え、以下を適用する。

- **本システムはサイト広告ショートコード（`[nopc][title]`・`[nopc][mokujimae]`・`[nopc][originalsc]`）を使用しない**
- H3以降は`<!-- wp:heading {"level":N} -->`と明示する
- `<ul style=...>`ではなく`<div>`で箇条書きを書く

### 5-2. 文体・トーン

「ですます」一辺倒で語尾が単調にならないよう、語尾（〜です/ます、〜でしょう、〜てみてください、〜といいですよ等）と言い回し（同じ動詞の言い換え等）にバリエーションを持たせる。事実関係・数値・リンク構造は変更しない。

### 5-3. 購入導線セクションの判断材料

「どこで予約・購入する？」等の集約セクションには、販売先ごとの実際の差（価格・ポイント還元・実勢価格・SNS上の傾向等）を短く添える。差が資料に無い販売先は無理に差別化しない。

SNS上の個人投稿（購入報告等）を根拠に使う場合：
- 本文では**匿名化した傾向情報**としてのみ言及する（例：「SNS上では〇〇での予約報告が多く見られます（公式集計ではありません）」）
- 個別のハンドルネーム・投稿の直接引用/リンクは行わない

### 5-4. 見どころ・特典説明のカード化

基本情報・特典内容等、3項目以上の情報は表またはカード形式（ラベル+値のdiv）で見せる。プレーンな段落を連ねない。

**デザインはイチから設計しない**：ピル型リンクボタン・スマホ対応比較表・情報カード・判断材料カード等は`rules/system_shira_release_article.md`4-5章に完成形のHTML/CSSテンプレートがある。そこから書き始め、色・文言だけ差し替える。

### 5-5. 比較表・重複注記の作法

- 比較表は**差分のある項目のみ**を行にする。仕様間で値が同じ項目（共通特典等）は表に含めず、下に注記1行でまとめる
- 同じ注記・SKU説明を複数箇所に置く場合は、**最初から2〜3パターンに言い換えて書く**（コピペで同一文を複製しない）

## Step 6. アフィリエイトリンク生成

`blogs/shira_note/tools/generate_af_link.py`を使う。

```
python tools/generate_af_link.py rakuten   "{商品ページURL}" "{リンクテキスト}"
python tools/generate_af_link.py sevennet  "{商品ページURL}" "{リンクテキスト}"
python tools/generate_af_link.py amazon    "{amzn.to短縮URL}" "{リンクテキスト}"
```

| ASP | 自動変換 | 備考 |
|---|---|---|
| 楽天ブックス | ○ | 商品ページのプレーンURLを渡すだけでよい |
| セブンネット | ○ | 同上 |
| Amazon | × | amzn.to短縮URLはユーザーから受け取る（Amazonアソシエイト管理画面で個別発行が必要）。rel属性の付与のみ自動化 |
| タワーレコード・公式サイト | 対象外 | 通常のリンク（アフィリエイトなし）として扱う。`rel="noopener"`のみ付与 |

**注意**
- **`target="_blank"`は手動付与しない**（WordPress側で外部リンクに自動付与される前提。TV番組タイムテーブル記事の旧仕様とは異なるので混同しない）
- 1記事内で同じ商品を複数箇所でリンクする場合も、`href`/`rel`等の構造は毎回完全に同一のものを使い回す。変えてよいのはリンクテキストのみ
- 装飾（ボタン風の見た目）は白背景+色付き枠線+矢印アイコンの「ピル型」を基本形とする。プレーンな下線テキストのままにしない
- **本コマンドのアフィリエイトID（楽天もしも・セブンネットVC・Amazon）はShiraNote専用**。他ブログ・他アカウントでは流用不可（そのアカウント自身のASP登録から着手する）

## Step 7. 構造化データ生成（JSON-LD）

`<!-- wp:shortcode --><!-- MANUAL_JSONLD -->[jsonld]`形式（`<script>`直書きはWP 7.0以降のCustom HTMLブロック仕様変更で保存時に消えるため使用不可。functions.php側の`[jsonld]`ショートコードが実際の`<script type="application/ld+json">`へ変換する）、`@graph`で以下を統合する。

1. `BlogPosting`（必須）：headline/description/keywords/日付/image/author/publisher/articleSection/about（`Thing`型）/hasPart
2. `Product`：`brand`（`MusicGroup`または`Person`）、`offers`は`AggregateOffer`（`lowPrice`/`highPrice`/`priceCurrency`:"JPY"/`availability`：発売日が未来なら`PreOrder`、発売済みなら`InStock`）
3. `FAQPage`：本文FAQと一字一句一致
4. `BreadcrumbList`：カテゴリURL未確定なら「ホーム→記事→本記事」の3階層

publisher/author/inLanguage等の固定データは`/shira-keyword-article`と共通（`rules/system_shira_keyword_article.md`参照）。

## Step 8. 検品

`python tools/qa_draft.py draft_release_{アーティストslug}_{作品slug}.txt` を実行し、確認を挟まず自動でERROR/WARNを修正する。

- ERROR 0件・新規WARN 0件になった時点でユーザーに完了報告
- **qa_draft.pyは句点（。）の抜け等、文レベルの細部を検知しない。機械チェック通過後、最終稿を人の目で通し読みする**

保存先：`drafts/draft_release_{アーティストslug}_{作品slug}.txt`
