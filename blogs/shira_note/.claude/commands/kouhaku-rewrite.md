# 紅白歌合戦 タイムテーブル記事リライト

NHK紅白歌合戦（毎年12月31日・年1回）の記事を、その時点の最新情報にリライトし、`drafts/draft_kouhaku.txt` に上書き保存する。記事URLは `https://shira-treat.com/nhk-kouhaku-timetable/` で固定（毎年上書き）。放送までに情報が出るたびに、何度でもリライトする。最初に `rewrite_common_rules.md`（禁止ワード・段落・ブロック構造・JSON-LD）を読む。

## 土台

- `draft_kouhaku.txt` は **第77回の段階①**（司会・テーマ・放送日時だけ発表済み。出場者・曲順は未発表）の完成形（2026-10-09 オーナー決定）。**これを土台に書き換える。**
- `template_kouhaku_base_stage1.txt`：完成直後の保存。失敗したときの戻し先。
- `template_kouhaku_76th_full.txt`：第76回の完成形。出場者カード・タイムテーブルの部品の原本。
- この2つは書き換えない。

## 進め方

1. **資料が無い回は先に `kouhaku-research.md`**（承認済みの `tools/output/kouhaku_material.md` ができるまで書き換えない）。資料が渡された回は飛ばす。
2. **段階を決める**（下の表。迷ったら1行で確認）。段階は戻さない。
3. **読む**：全文は読まない。draftの後半約800行（`kouhaku-past` の折りたたみ内）は第76回の記録で、通常は読む必要がない。下の一覧のGrep目印で行を出し、必要な所だけ部分Readする。
4. **書き換える**：Write（全体上書き）はしない。複数箇所は、置換前の文字列が1回だけか確認してから書くスクリプト（`tools/draft_patch.py` 等）で。部品は `str.replace` か足し算で組む（**`%` 書式は使わない**。CSSの `%` とぶつかる失敗が2026-10-08・10-09に2回出た）。JSON-LDは `json.loads` で読み、必要な項目だけ書き換えて `json.dumps(ensure_ascii=False, indent=2)` で戻す（手書きしない）。
5. **検品**：`python tools/qa_draft.py draft_kouhaku.txt`（引数はファイル名だけ）。**ERROR 0件・新規WARN 0件**。次を機械で見る：ブロックの開閉・JSON-LDとメタ・FAQの一致（カード形式対応）・HTMLタグの開始と終了の数（2026-10-09追加。紅白は不一致をERRORにする）。
6. **目で確認**：前の段階の言葉の残り（Grep `未発表|まだ発表されていません|10月9日時点`。出場者が出たのに「未発表」が残るのが最も起きやすい）／入れた名前・曲が見えるか。出場者が出た段階では `python tools/check_names.py draft_kouhaku.txt --names-file tools/output/kouhaku_names.txt --aside "出場者＆歌唱曲一覧"`（名前を1行1名で書いたファイル。一覧とJSON-LDの漏れを検出）。
7. **報告**：段階・変えた箇所・検品結果・「この回の独自要素」を1行（10-4）。コミットはオーナーの指示があったときだけ。

**消してよいかを聞く**：「枠だけ消して」と「中身ごと消して」は別。指示のない削除はしない。迷ったら先に聞く（2026-10-09：開閉ボックスの中身を消して手戻り）。見た目（冒頭カード・FAQ・折りたたみ・概要の箱）は整えた形のまま。直すときは確認する。

## 部品

### 7. 出場者カード（`<div class="bd">` の中）

```html
<!-- 普通：名前の後ろは (初) か出場回数 （7） -->
<div class="row"><div class="name">{名前} (初)</div><div class="song">「{曲名}」</div></div>

<!-- メドレー -->
<div class="row">
  <div class="name">{名前}（{回数}）</div>
  <div class="song">
    {メドレー名}<br>
    「{曲1}」<br>「{曲2}」
  </div>
</div>

<!-- 特別企画 -->
<div class="row"><div class="name">{名前}</div><div class="song"><span class="label">内容</span> 「{曲名}」</div></div>

<!-- スペシャルステージ（出演者が多い企画） -->
<div class="row special-stage-block">
  <div class="name">『{企画名}』</div>
  <div class="song"><span class="label">内容</span>
    <span class="special-stage-list">
      <span class="special-stage-line">『{曲名}』 {出演者}</span>
    </span>
  </div>
</div>
```

曲名の改行は `」<br>「` と**直接書く**（`<script>` は入れない。WordPressで消える）。司会カード `kouhaku-card host` は名前を `<div class="name">` で並べる（入っている）。欠席・変更は備考の一行：`<span style="color:#9ca3af;font-size:10.5px;">※…</span>`。

### 8. ③のタイムテーブル

1. 型は `template_kouhaku_76th_full.txt` の前半・後半（Grep `aria-label="紅白歌合戦 タイムテーブル（前半）"`／`（後半）`）。1行は次の形。特別企画は `kb-special-banner`（緑の帯）をその出演位置に挟む。時間帯は `<h3 class="kb-time">19:20～</h3>`。
```html
<li class="kb-item kb-red-group">   <!-- 白組は kb-white-group -->
  <span class="kb-num">{番号}</span>
  <div style="min-width:0;">
    <div class="kb-artist">{名前}</div>
    <div class="kb-song">♪ {曲名}</div>
  </div>
</li>
```
2. カードの `aria-label` は `紅白歌合戦 タイムテーブル {時刻}（{n}）`（第76回のものは「第76回タイムテーブル」と名前が違い、重ならない）。
3. **`kb-*` のCSSは、いま第76回の折りたたみの中に1か所だけある。** 第77回のタイムテーブルを作るときは、そのCSSを第77回のブロックの先頭へ**移し**、折りたたみ側からは消す（二重にしない）。
4. 広告 `[nopc][originalsc][/nopc]` を前半と後半の間に1か所足す（今は1か所→2か所）。同じ広告コードを連続させない。
5. 公式の曲順だけを載せる（予想は載せない）。

### 15. JSON-LD

## 守ること（紅白の決まり）

- 使わない：`<script>`／AFFINGERの専用枠（`wp-block-st-blocks-st-slidebox`・`wp-block-st-blocks-memo`。オーナーが外した。出場者一覧は常に開いた形）。
- ショートコード `[nopc][title]`・`[nopc][mokujimae]`・`[nopc][originalsc]` は、それぞれ単独のパラグラフブロック。
- 文体は `rewrite_common_rules.md` 1章・16章（「彩る」「次の項目で」を使わない）。事実は公式（NHK公式・X公式）で確認できたものだけ。内定報道は確定情報として書かない。
