## タイトル・メタ定型

```
Venue101 {特別編成名} タイムテーブル {M月D日}の出演者・順番をリアルタイム更新
```
通常回は「{特別編成名} 」を省く。「Venue101 」の直後に「タイムテーブル」（特別編成がある回は「Venue101 EXTRA タイムテーブル」）。テーマ名・誇張語・具体数値は入れない（共通ルール3章）。

```
メタディスクリプション（XXX字）：
{M月D日}放送のVenue101 {特別編成名}、今日の出演者と歌唱曲、出演順をまとめています。曲順は事前に発表されないため、放送に合わせて更新します。
```
歌唱曲が未発表の回は「今日の出演者と出演順をまとめています。」へ。**メタに「出演順」または「順番」を必ず含める**。

## セクション別の番組固有ルール（エンジン手順番号に対応）

- **手順3 aside**：BROADCAST（放送日時・NHK総合・特別編成名）／STATUS／LINEUP（`/`区切り）／TIMETABLE／💡コメント（見どころ要約1文）／最終更新日／「最新情報を確認する」リンク（`#st-toc-h-1`）。ラベルは STATUS・LINEUP・TIMETABLE の3本固定
- **手順4 最新タイムテーブル**：曲順が事前に出ないので時間帯カードは作らない。通知カード1枚のみ。放送が始まって判明した順に、時間帯カードへ書き換える
- **手順5 出演者一覧**：`ARTIST LINEUP (YYYY.MM.DD)` の日付も更新。歌唱曲が発表済みなら各カードに曲名を入れ、未発表なら「歌唱曲は現時点で未発表。」で統一（日付を創作しない）。**次回（次週）枠**を末尾に置ける（出演者が出ている回のみ）
- **手順6 出演時間の目安**：3枠（序盤・中盤・終盤）。文は「直近N回の放送では〜」の形で、**必ず現draftの「実際の出演順」パネルと過去一覧の実績を確認してから書き直す**（共通ルール10-3。一般論で書かない）。数値（「3〜5分後」「23:20〜23:27頃」等）は実績が変わったら更新する。実績が1〜2回分しかない間は断定調を避け「前回は〜でした」に留める
- **手順6の後ろの段落**：「出演者の発表順と実際の登場順が一致するか」を実績から一文で述べる（直近3回とも不一致だった＝2026-09-25時点）。一致する回が出たら文言を見直す
- **手順8 実際の出演順**：アーカイブパネル。資料②（Grok）で更新。フッターは「ESTIMATED FROM SNS REALTIME TREND」と、パネル直下の「出演順と時間帯は、Xの実況投稿から推定した内容です。」を維持
- **手順9 見逃し配信**：NHK ONEの固定文言（番組基本情報の欄参照）。放送日や出演者を入れない（固定）
- **手順10 過去一覧**：エンジンのローテーション（追加＝退避データをH3フルカードで先頭／維持＝2回前／移動＝3回前を`<details>`へ／削除＝`<details>`内の最古）。`<details>`内は直近3回分まで保持。**休止週は回数に数えない**。根拠注記（フッター）は「※Xのリアルタイム投稿を参考にした推定タイムラインです。」で統一し、順番が不確かな箇所は「推定を含みます」と追記する
- **手順11 FAQ（5問。Q3・Q5のみ固定型）**：
  - **Q1＝「今日の…タイムテーブルは事前に発表されますか？」**（放送枠「HH:MM〜HH:MM」を回答に入れる。出演者の全列挙はしない）
  - **Q2＝「次回（WEEK2など）はいつ？」**。次回情報が無い回は「Venue101の次回放送はいつですか？」に差し替える（記事に無ければ「放送日は決まり次第この記事で更新します」）
  - **Q3＝見逃し配信（固定）**：「あります。Venue101は同時配信に加え、放送終了後から1週間の見逃し配信が、NHKの公式配信サービス「NHK ONE」で行われます。この記事でも出演順・タイムテーブルを更新しています。」
  - **Q4＝前回の出演順**（直前回データ。推定である旨と「実際の出演順」欄への誘導）
  - **Q5＝放送時間**（放送日・時間のみ更新）
- **手順12 まとめ**：3段落（放送日・時間／出演者と企画／更新の予告）。出演者名は列挙してよいが、asideと出演者一覧とあわせて**3箇所まで**（共通ルール11-1）
- **手順13 ナビ**：固定だが、**新番組が増えたらリンクを追加**（共通ルール8章の表が正。Venue101自身へのリンクは入れない）
