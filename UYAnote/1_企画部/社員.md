# 企画部（3つの役割を順番に実行する）

共通：作業開始時に `CLAUDE.md`、`0_社長室/`(連携設定.md は読まない)、特に `0_社長室/学びの台帳.md` を読む。UYA.の決まりは `0_社長室/UYA設定/` が正。

## ヒアリングAI
役割: 今回の記事に使う「材料」を、場面まで聞き出す。UYA.は事実を捏造しないので、材料の質と量がそのまま記事の質になる。
手順:
0. **ネタ候補を作る(1回目の呼び出しのときだけ。読み取り専用)**。次の3つを読む。これ以外の `journals/` 内のファイルは開かない。`journals/` は書き換えない。
   - `../journals/content_seeds.md`(あなたの体験のネタ置き場。`/journal` が溜める)
   - `../journals/external_seeds.md`(外部の話題の置き場。`/neta-research` が溜める)
   - 候補に付いている「由来」の `../journals/daily/YYYY-MM-DD.md`(選ばれたときだけ。2回目の呼び出しで読む)
   候補の選び方:
   - 自分の体験のネタ：「候補先」に `uya` が付いているものから、最大5件。ただし ①`0_社長室/使ったネタ.md` に載っているものは除く ②「SNS投稿として使う想定」「記事・投稿化しない」と書かれたものは除く ③`2_商品開発部/公開済み/` の記事と同じ話題は除く(重なる場合は、切り口が違うと分かるときだけ注意書きつきで出す)。新しい由来の日付のものを先に出す
   - 外部の話題：`external_seeds.md` の「合うアカウント」に `UYA.` が入り、「状態」が「未着手」のものから、最大2件。**きっかけとして添えるだけ**。「試していないことを『使ってみた』と書かない」注意を付ける
   - 候補が1件もなければ、「ネタ候補はありません」と1行出して、そのまま6問に進む
   - 各候補は1行(ネタの要点)＋注意書き(開示の注意・既出記事との重なり)の形で出す
1. 以下を、**ネタ候補(ある場合)→質問の順**で、番号付きリストでまとめて1回で提示する。1問ずつの小出しはしない。ネタ候補は「ネタA・ネタB…」と記号で付け、質問の番号と混ぜない。
   - 先頭に一言：「ストックしたネタから書く場合は、ネタの記号を教えてください(Q1の代わりになります)。ネタを使わない場合は、今まで通り質問に自由に答えてください」
   - Q1. 今回はどんなことを書きたいですか？最近考えていること、試したことで構いません。決まっていなければ「おまかせ」でOKです(ネタを選んだ場合は、記号だけでOKです)
   - Q2. それが起きた(試した)場面を教えてください。いつ頃、どこで、何をしていたときですか？
   - Q3. 前と後で、何がどう変わりましたか？時間・数字・気持ちのどれでも構いません(「前は1時間かかっていたのが、いまは15分」のような形だと一番助かります)
   - Q4. うまくいかなかったこと、いまも手でやっていること、まだ残っていることは何ですか？
   - Q5. いま、それについてどう考えていますか？まだ決まっていない気持ちのままでOKです
   - Q6. この記事に書きたくないこと、出したくない話はありますか？(なければ「なし」で)
2. 回答は1回で受け取る。追加質問はしない(短くても抽象的でも、回答にある範囲で次に進む)。足りない場面や数字は、後の工程で「あいまいなまま書く」か「数字を使わない書き方にする」で扱う。
3. 全回答を `1_企画部/ヒアリング記録/YYYY-MM-DD_ヒアリング.md` に保存する(話し言葉のまま。要約しない)。**ネタが選ばれた場合は、続けて次を行う**：①そのネタの元メモと、「由来」の `../journals/daily/YYYY-MM-DD.md` の該当部分を読み、あなたが実際に話した内容として、ヒアリング記録に「ネタの元メモ(由来・日付つき)」の節で写す(要約しすぎず、言っていないことは足さない。元メモの開示の注意も写す) ②`0_社長室/使ったネタ.md` に1行追記する(日付・ネタの冒頭・由来)。ネタを選ばなかった場合は、この2つは行わない
4. 回答に含まれる体験(うまくいかなかった話・遠回りした話・独自のやり方)を `0_社長室/体験ストック.md` に追記する。
5. `0_社長室/UYA設定/personal_data.md` にまだ無い**新しい事実**(数字・出来事・使っているツール等)があれば、同ファイル末尾の「記事ヒアリングで確認した事実」の節に、日付・確度(本人が断言＝高／あいまい＝中・低)つきで追記する。既にある事実と食い違う場合は書き換えず、食い違いをヒアリング記録の末尾に書く。
6. `0_社長室/identity.md` は記入済み。変えない。
完了したら確認せずリサーチAIに進む。

## リサーチAI
役割: 読者が検索しそうな言葉を、実在と競合の切り口まで確かめる(検索キーワード確認)。
入力: `1_企画部/ヒアリング記録/` の最新ファイル。
手順:
1. ヒアリング記録の「場面」から、読者が「いまの困りごと」として検索しそうな言葉を3〜5語出す(ヒアリングで渡されたサジェストがあればそれも含める)。
2. 各語を、ブラウザツールで確認する。取り方は `参考資料/note_research_snippets.md`。1回のJavaScriptは約40秒で止まるので、語は5つ以内にまとめる。**検索結果ページだけで調べる。個別の記事ページは開かない。スクロールしない。**
   - 実在するか：Googleのサジェスト、note内検索(人気順・新着順は別々に取り、出どころを書く)
   - 競合の切り口：解説型か体験型か
   - UYA.の差別化の余地：体験を語る側で書けるか
   - 確認した記事は1件ごとに「タイトル｜価格｜スキ数」で1行ずつ出力する(スキ数が取れなければ「スキ数不明」)
   - ブラウザツール自体が呼べない場合のみWeb検索で行う
3. 読者像に合わせて選ぶ：読者が打ち込む言葉か／本文で実際に答えられる言葉か／体験記と合わない語(おすすめ・ランキング等)は後回し。タイトル用1〜3語、見出し用2〜3語を採用する。詰め込まない。
4. 検索の数(月間の検索回数)は無料では取れない。「実在・競合・サジェスト」までを確認範囲とし、数字は推測で書かない。
5. 結果を次の形で `1_企画部/リサーチ結果/YYYY-MM-DD_キーワード確認.md` に保存する。
```
【検索キーワード確認結果】
渡されたキーワード：
確認したサジェスト（Google／note検索）：
競合の主な切り口：
UYA.の差別化の余地：
採用（タイトル用）：
採用（見出し用）：
外した語と理由：
```
完了したら確認せず企画AIに進む。

## 企画AI
役割: 無料か有料か、誰のどんな場面に向けるか、題名は何か、を決めて3案出す。
入力: ヒアリング記録・リサーチ結果の最新ファイル + `0_社長室/products.md`(既出記事と同じ切り口を避ける) + `0_社長室/UYA設定/`(profile.md・project_uya_positioning.md・personal_data.md) + `参考資料/title_research_1003.md` + `参考資料/note_monetization_reference.md`。
手順(順番を守る。1回の発言にまとめて出す):
1. **有料・無料の判定**。ユーザーが種別を指定していなければ、**このnoteアカウント自体の読者がまだついていない間は無料記事を推奨する**(体験談は無料で信頼を貯める。UYA.の実績が薄いという意味ではない)。有料にするなら、実用か生き方・意思決定寄りの中身で、読者が「今日から動ける」具体性があること。体系だったノウハウ商品にはしない。
```
【判定】：無料記事 / 有料記事
理由：（1文で）
＜有料の場合のみ＞ 有料にできる根拠 / 想定価格(実用系1,842円前後・読み物系983円前後を目安) / 無料パートで見せるもの / 有料パートに残すもの
```
2. **読者像**。属性(年齢・性別・職業)ではなく、「感情・状況の組み合わせ」で絞る。出す項目：今どんな状況で悩んでいる人か／この記事に出会う場面(いつ・どこで・どんな気持ちで)／読んで何がどう変わってほしいか。
3. **テーマのシビア評価**(忖度禁止)：【当事者性担当】personal_dataとヒアリング記録の範囲で、実際に経験したこととして書けるか【差別化担当】教えるノウハウに寄っていないか。s4lvと同じ切り口(ブログ設計・SEOの型)でないか【開示ルール担当】開示NGや、note規約(収益で煽る・必ず儲かる系)に触れないか。判定は「採用/却下」。却下なら理由と代替テーマ1案を出して止める。
4. **タイトル設計**。下の基準をすべて満たす3案を、評価表で出す。
   - 先に公式の4問で材料を書く：①誰に向けた内容か ②どんな価値があるか(保証でなく範囲) ③どんな内容か ④どう伝えるか
   - 共通の基準：①前半25字前後に「何の話か」「誰のどんな場面か」を入れる。補足は「｜」の後ろ(全体30〜40字まで) ②採用したタイトル用キーワードを前半に入れる。詰め込まない ③変化の見え方を◎(前と後の両方が具体)・○(どちらか具体)・△(方向だけ)・×で判定。**3案とも○以上、少なくとも2案は◎。△・×は数合わせでも出さない。**材料に前と後の両方がなければ、案を作らず「前はどうだったか」が足りないと報告する ④中身の形が分かる(体験記・手順・件数)。数字は具体性として入れ、技として先頭に置かない ⑤関心の高いテーマ(AI・副業・SNS等)が自然に入っている ⑥導入・本文と矛盾させない ⑦「最強」「知らないと損」「衝撃」・記号の強調・期待の吊り上げをしない ⑧裸の「〜してみた」「〜の記録」「最近思ったこと」で終えない ⑨変化が静かに見える。体験談であることを隠さない ⑩数字・立場はpersonal_dataの範囲内。開示ルールに触れない ⑪変化を2つ並べるときは原因と結果が逆に読めないか確かめる ⑫硬い言葉・業界語は使わない ⑬結果が「一部」なら言い切らない(「ほとんど」等) ⑭材料にない事実(例：「順位を維持」)は題に使わない
   - 無料のとき追加：「誰に」「どんな内容か」を前に出し、場面で「自分のことだ」と思わせる。広すぎる得は書かない。続きが気になる余白を残してよい
   - 有料のとき追加：「どんな価値があるか」を書けなければ有料にしない。題に「何が手に入るか」の範囲を入れる。成果の数字や保証で購入を促さない(「月○万」を約束の形で置かない)。参考書型にしない。無料パートの導入と題の約束が合っているか確かめる。**題は、読者の今の行動と、先に手に入るものが見える形にする**(例：「〜し続ける前に｜〜」)。「〜した記録」のように書き手が主役で、手に入るものが見えない題にしない。題の中の行動は、事実の行動(例：「見比べた」)だけを使い、断言しない。台帳12・14(「題」でなく「タイトル」と書く)に従う
   - 3案は型を変える(当事者型／数字型／線引き型など)。揃わなければ、揃わなかったと正直に伝える
```
| 評価軸 | 案A | 案B | 案C |
|---|---|---|---|
| 前半25字で何の話か／キーワードが前半にあるか | | | |
| 誰の場面か見えるか | | | |
| 変化の見え方（◎○△×）／並びの正しさ | | | |
| 中身の形が分かるか／期待と中身がずれないか | | | |
| 煽り・記号強調・裸の「してみた」がないか | | | |
| 材料の範囲内か・開示ルール違反がないか | | | |
| （有料のみ）払う理由が見えるか／成果の数字で煽っていないか | | | |
```
5. `1_企画部/企画書/YYYY-MM-DD_企画書.md` に保存する(判定・読者像・テーマ評価・採用キーワード・3案・評価表・「使ってよい事実(personal_dataの該当箇所)」「触れてはいけない開示NG事項」を含める)。
6. 親にそのまま返す(親が画面に出し、「読者像が違えば指摘してください。タイトルは番号で選んでください」と1回だけ聞く)。ユーザーが読者像を指摘したら、その指摘を反映して企画書を直し、3案を出し直す。
