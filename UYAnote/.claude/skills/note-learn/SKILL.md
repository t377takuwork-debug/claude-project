# note-learn（オーナーの直しを読み取って、次の記事に効かせる）

オーナーは、記事ごとに「チャットで気になる点を伝える」「noteの画面で自分で直す」を何度か繰り返して完成させる。完成した記事が、その時点の最新の意図。この手順で、直しを毎回かならず拾い、次の記事の最初の稿に効かせる。
チャットで伝えられた直しは、`CLAUDE.md` の「学びの台帳の運用」どおり、その場で台帳に書く(この手順の対象外)。この手順は、**noteの画面での直し**を拾う。

## A. 「下書きを修正した／直したので確認して」(公開前。何度でも)
親が直接行う(販売AIは使わない。トークンの節約)。
1. 内蔵ブラウザで `0_社長室/products.md` の編集URLを開く(開いたままならそのまま)。保存されていない直しがありそうなら、先に「下書き保存」を押してもらう。`.claude/hooks/note_read.js` の中身を、JS実行ツールにそのまま渡す。戻り値のJSON(`title`・`counts`・`md`)を取得する
2. `md` を、作業用フォルダ(scratchpad)の `note_now.md` に、UTF-8で保存する。**先頭に「公開メモ」の段落**(1行目が「#」で始まるタグ[と有料は価格]、2行目が「↑公開前に、この段落ごと消す」)があれば、取り除いてから保存する(完成稿には入れない。`3_広報部/社員.md` の手順0)。公開後(B)の読み取りで、まだ残っていたら、オーナーに「公開メモが残っています」と1行知らせる
3. `python .claude/hooks/note_diff.py 2_商品開発部/原稿/YYYY-MM-DD_原稿_完成.md <note_now.md>` で、直した箇所と修正率を出す。引用・太字・見出し・カードの数も比べて、画面の表示が崩れていないかを見る
4. 完成稿を更新する**前に**、いまの完成稿を `2_商品開発部/原稿/履歴/YYYY-MM-DD_完成_vN.md` に退避する(Nは連番。**v1がAIが書いた最初の版**)
5. 完成稿と `_原稿.md` を、先頭の管理情報を残したまま、`note_now.md` の本文に置き換える。`[カード:記事ID]` は、`products.md` の公開済みURLの1行(https://note.com/…/n/記事ID)に戻す
6. オーナーに、直した箇所の一覧を短く報告する。**オーナーが直した行は戻さない**。直した理由が文面から分からないものだけ、1つ聞く
7. 台帳に反映する：語り口の特徴は台帳7に追記または置き換え、新しい決まりは項目を足す(古いものと矛盾したら置き換え)。同じ傾向が3回目なら、`examples_essay.md` に移して台帳から消す。誤字・脱字は一覧で報告し、直してよいか聞く(オーナーが「誤字は直してよい」と言った後は、直して報告)
8. `qa_article.py` を完成稿に実行し、ERROR件数だけを1行で報告する

## B. 「公開しました」(公開後)
1. `products.md` に公開日と、オーナーが送ったURLを書く(URLを聞き返さない)
2. 編集URLを開いて Aの1〜3を行い、公開版の本文を読み取る。完成稿との差があれば、Aの4〜7を行う
3. `2_商品開発部/公開済み/` に、読み取った本文で記事を作る(先頭の管理情報に「公開日」を足す。完成稿のコピーではなく、公開版から作る)
4. `0_社長室/修正の記録.md` に1行足す：履歴の `v1` と公開版を `note_diff.py` で比べた、段落数・直した段落・修正率
5. ハッシュタグが公開ページに出ているか確認し、足りなければ報告する(公開画面での手入力)
6. 「登録しました。Xなら『Xの投稿を作って』、スレッズなら『スレッズの投稿を作って』と送ってください」と1行出して止まる

## C. 台帳の整理(月1回、または台帳が12項目を超えたとき)
重複・矛盾を置き換える。3回出たものは `examples_essay.md` へ。台帳は短く保つ(全AIが毎回読むため)。

## 限界
- 読み取りはnoteの編集画面の見た目(DOM)から行う。画面の作りが変わったら `note_read.js` を直す
- 修正率は「段落単位」の目安。語尾だけの直しも1段落として数える
