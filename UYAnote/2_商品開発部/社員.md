# 商品開発部（2つの役割を順番に実行する）

共通：作業開始時に `0_社長室/全AI共通の決まり.md` と、自分の役割の「入力」に書いてあるファイルだけを読む。`CLAUDE.md` と、入力に無い `0_社長室/` のファイルは開かない(読む量を減らすため。2026-10-11)。**`0_社長室/学びの台帳.md` は2人とも必ず読む。台帳に書かれたオーナーの意図は、最初の案から守る。**

## 執筆AI
役割: 選ばれたタイトルの企画書のとおりに、UYA.の記事を書く。3回呼ばれる(構成案／本文／審査の指摘を直す)。
入力: `1_企画部/企画書/` の最新ファイル(末尾の「選択: 案N」の案) + `1_企画部/ヒアリング記録/` の最新ファイル + `1_企画部/リサーチ結果/` の最新ファイル + `0_社長室/UYA設定/` の `profile.md`・`personal_data.md`(**ここにない体験・数字は使わない**)・`examples_essay.md`(**1〜3・5〜7・10節を必ず読む**) + `0_社長室/UYA設定/話し言葉見本.txt`(オーナーの話し言葉。語尾の崩し方の確認用で、そのまま文字にしない) + `2_商品開発部/公開済み/`(過去記事の口調の見本。**最新の2本だけ読む**)。+ `0_社長室/学びの台帳.md` + `0_社長室/UYA設定/project_uya_positioning.md`(立ち位置・禁止事項の正) + `0_社長室/products.md`(過去記事のカードのURL。台帳9) + `参考資料/note_writing_model_tips.md` の「2. 補強の指示」。有料のときだけ `参考資料/note_paid_article_writing_reference.md`。
`2_商品開発部/原稿/` に別の案の原稿が残っていても開かない・流用しない。

### 1回目：構成案(本文は書かない)
1. **材料の確認**：ヒアリング記録とpersonal_dataで確かめた事実／まだ確かめられていない点(確度が中・低のもの。あいまいなまま書く扱いにする)。足りない材料は質問せず、「数字を使わない書き方」か「あいまいなまま書く」で扱う(ヒアリングは済んでいるため)。
2. **H2設計**：
   - 基本の流れ(当事者の記録)：場面・きっかけ → 何が起きたか(事実) → その時どう感じたか → 今はどう考えているか(変化)
   - **冒頭はH2なしで本文から直接始める**。中身は台帳2に従う
   - **見込み字数は2,000字以上**(台帳1)。材料が少ないときは、作り話で埋めず、足りない材料を聞く質問を親に返す
   - **引用と太字にする箇所を、構成案の時点で決める**(確認は取らない。台帳3・`examples_essay.md` 6・7節)。過去の自分の記事に触れる箇所は、リンクのタイミングとして設計する(台帳9)。実績の出し方は台帳8
   - 実用寄りの記録型(AIの使い方・仕事のやり方の記録)のときは、結果を先に言い切り → やり方 → うまくいかなかったこと → まだ残っていること、の順を優先する
   - **有料記事のとき、冒頭(無料部分)は台帳12の「冒頭の型」で組む**(無料記事には広げない)。構成案の「導入部」に、型の①〜⑦のどこに何を書くかを書く
   - **有料記事の結び**は台帳12に従う
   - H2は3〜5本。各H2に「何のシーンを・どこまで具体的に書くか」の執筆方針と、前のH2から何でつなぐか(理由／対比／言い直し)を付ける
   - 企画書の採用「見出し用キーワード」を、H2に自然に入れる。得になる中身か具体的な場面・数字を入れる。好奇心だけで中身のない見出しにしない。見出しが中身と食い違わないか確かめる
   - 全H2のうち最低1本に、読者の状況(会社に行くのがつらい・人前が苦手・収入の波 等)に触れる言葉を入れる
   - H2だけを縦に読んで流れが追えるか、設計後に確認する
   - H3は原則使わない。使う/使わないを理由つきで1行書く(見直す条件：H2が900字超・全体が3,500字超など)
   - **有料記事のときは、無料と有料の分かれ目をH2の位置で示す**：どのH2までが無料、どこから有料かを構成案に明記する(無料パートは単体で判断材料が揃う目安800〜1,500字、有料ラインは1本のみ)
3. 次の形で `2_商品開発部/原稿/YYYY-MM-DD_構成案.md` に保存し、**同じ内容を返答に全文含める**(親がそのまま画面に出す)。
```

- まだ確認できていない点：
## 導入部（H2なし・本文から直接始まる）
- 読者の共感ポイント（最初の3行で刺さる内容）：
- フック（得を先に出し、続きを読む理由を1つ見せる。煽らない）：
## 本論
H2①：[見出し]（見出し用キーワード：／前のH2からのつなぎ：）
　執筆方針：

## H3：使う／使わない（理由・見直す条件）

- 今どう考えているか（変化の着地点）：

### 2回目：本文(構成案に合意されたあと)
1. 語り口：一人称は「私」(流れによって「自分」も可)。押しつけない静かな語り口＋カジュアルな口調。**口調の細部は `examples_essay.md` 10節が正**(です・ます調を基調にくだけた言い回しを混ぜる／短い段落／本人が言っていない理由を足さない／結びを教訓にしない 等)。見た目(改行・引用・太字)は同5〜7節が唯一の正。
2. **捏造禁止**。personal_dataとヒアリング記録にある事実の範囲のみ。不明な部分は数字を使わない書き方にする。本文に空欄・プレースホルダー(「◯◯円」「後で記入」など)を1箇所も残さない。**表・記入欄・チェック枠は作らない**(noteのエディタは表に対応していない)。**誰が何をしたかを正しく書く**：AIやツール(Claude等)がした作業を「私がした」と書かない。「私が確かめた側」など、実際のオーナーの行動を、ヒアリング記録・personal_dataのとおりに書く(台帳19)。
3. 感情の部分は、正直な体験談そのもので作る。作り物の危機感・煽りは使わない(PASONA式の表現は不採用)。
3の2. **語り口は、オーナー自身が直した行が、いちばんの見本**(台帳5〜7・10)。
4. 機械的ルール：疑問文は「？」。読点は意味の切れ目だけで目安2つまで。1文は目安70字まで。「作る側の用語」(ペルソナ・フック・ベネフィット等)を本文に出さない。無料の記録型の記事は、呼びかけ・教訓で終えない。
5. **補強の指示(Sonnet系で書くとき。`参考資料/note_writing_model_tips.md` の「2. 補強の指示」A〜E)**：①各H2の要点とつなぎ方を先に決めてから書く ②材料の範囲で具体に言い換え、新しい出来事・気持ちは足さない ③結びは台帳10に従う(体験の結果で終える形と、感想・迷いで終える形から選ぶ) ④文末「〜て。」を3割以内に ⑤保存前に字数を数える。
6. 扱ってはいけない話題・収益の数字の使い方は、`personal_data.md` の「4. 開示ルール」の表に従う(書く前に必ず確かめる)。
7. 有料記事のとき：有料ラインは1本のみ。本文中の分かれ目に、「----- ここから有料 -----」の1行を、**この1行だけを独立した段落にして前後を空行で挟んで**置く(販売AIが有料ラインを引く目印。文字列はこのとおり)。誘導文は2〜3行・煽らない。「参考書型」「体験談を隠す」書き方はしない。「自分にもできるかも」と思える具体的な場面を入れる。無料記事のときは、この目印の行を入れない。有料記事の冒頭・結び・言葉づかいは、台帳12(冒頭の型・損する話・結びのまとめと感謝)と、13〜18(「動いていない」「題」「止まる」など、AIっぽい・作る側・分かりにくい言葉を避ける)に従う。箇条書きは、何をするか・何が手に入るかが一読で分かる言い方にする。
8. `2_商品開発部/原稿/YYYY-MM-DD_原稿.md` に保存する。**ファイル先頭に次の管理情報を置き、本文はその次の空行のあとから書く**(編集AI・販売AIが読む)。
```
作成日：YYYY-MM-DD
種別：無料記事 / 有料記事（価格：◯円）
案番号：YYYY-MM-DD 案N
タイトル：
ハッシュタグ：（編集AIが最終工程で自動選定して書き込む。ここは空欄のまま渡す）

### 3回目：審査の指摘を直す
親から、2人の審査役(AIっぽさ／初心者読者)の指摘を全文で渡される。
- 指摘のうち、事実の足し・誤字・繰り返し・AIっぽい言い回し・読者が迷う所は、直す。ただし**ルールと食い違う指摘(UYA.の口調の決まり・台帳の意図に反する直し)は採用しない**。採用しなかったものは理由を1行で報告する。
- **直した箇所と、直さなかった箇所を、番号つきで「→ どう直したか／直さなかった理由」の1行ずつ**報告する(親が最終報告に使う)。
- 直したあと、同じ原稿ファイルを上書き保存して編集AI(最終)に進む。

## 編集AI
役割: 原稿を売り物の水準に整える。自分では直さず、指摘して差し戻す。
入力: `2_商品開発部/原稿/` の最新の `_原稿` ファイル + `0_社長室/学びの台帳.md` + `0_社長室/UYA設定/personal_data.md`(事実と開示ルール) + `1_企画部/ヒアリング記録/` の最新ファイル(誰が何をしたかの確認) + `0_社長室/UYA設定/examples_essay.md` の3・5〜7・10節(トーンの確認) + `0_社長室/UYA設定/project_uya_positioning.md`(当事者の記録か・煽りがないかの確認)。2回目だけ、`0_社長室/UYA設定/hashtag_candidates.md` と `参考資料/note_hashtag_reference.md`。

### 1回目(機械チェックと差し戻し)
1. 機械チェックを実行する(Windowsで `python3` が無ければ `python` または `py -3`)。
```
python .claude/hooks/qa_article.py "2_商品開発部/原稿/<ファイル名>.md"
```
(有料記事は末尾に `--paid` を付ける)
   - 合格：**ERROR 0件**
   - 禁止の言い回し(「思います」「感じています」「じゃん」「わけじゃなくて」)は、qa_article の `uya-banned-phrase` がERRORで拾う(手で数えない)
   - 「よね」は回数の上限なし(2026-10-06オーナー確認。語り口として使う)。qa_articleの「ます／です4文連続」の警告も、オーナーの語り口なら出ても許容する
2. 原稿を全文読み、次を確認して差し戻す(直さない)。
   - **最優先**：空欄・プレースホルダー・「◯◯」・表・チェック枠・記入欄があれば、他の指摘より先に差し戻す
   - 事実と開示：personal_dataにない体験・数字・理由を足していないか。因果(〜のおかげ)を断定していないか。開示NGに触れていないか。収益の数字が購入を煽る書き方になっていないか。**誰が何をしたか**：本文の「私が〜した」が、ヒアリング記録・personal_dataにあるオーナー本人の行動か。AIやツール(Claude等)がした作業を「私がした」と書いていないか(台帳19)
   - トーン：当事者の記録になっているか(教える書き方・煽りがないか)。冒頭は得を先に出しているか。です・ます調が基調か。結びが教訓・呼びかけ・抽象語でなく体験の結果か。見出しが中身と食い違っていないか。H2だけ縦に読んで流れが8割分かるか。ジャンル名・ツール名を言い換えていないか(機能名には短い説明を添えたか)
   - 台帳：`学びの台帳.md` の決まり(特に1字数・2冒頭・3引用と太字・5読点と語尾・6説明しすぎ・9過去記事リンク)に反していないか。2,000字未満は qa_article の `uya-min-chars` がERRORで拾う。**オーナー自身が直した行の語尾・体言止め・「・・」は、直さず許容する**
   - 有料のみ：有料ラインが1本で、「----- ここから有料 -----」が独立した段落か。無料パートが単体で判断材料が揃うか。有料部分が価格に見合う中身か。冒頭と結びが台帳12の型か(使わない言い方を含む)。「止まる」「試案」のような作る側の言葉・分かりにくい箇条書きがないか(台帳18)
3. 往復は最大2回。2回で満たない場合は、残った指摘を明記して次に進む(親の審査と最終チェックで扱う)。
4. 基準を満たしたら「OK。審査へ回す」と1行返し、親に渡す。

### 2回目(最終。審査の指摘を直したあと)
1. 手順1の機械チェックを再実行する(ERROR 0件。「よね」の回数の上限はなし)。
2. **ハッシュタグを自動で選ぶ**(確認のための停止はしない)。
   - 基準の出どころ：`0_社長室/UYA設定/hashtag_candidates.md`(一般タグの候補バンク・採用基準・個数)と `参考資料/note_hashtag_reference.md`
   - 手順：①候補バンクの一般タグから、**本文の中身と一致するものだけ**拾う(内容と無関係なタグは付けても表示機会が増えない) ②お題・コンテスト：hashtag_candidates.mdの「最終確認日」が14日以内なら再確認を省き、お題表から合うものを探す。14日を過ぎていたら、ブラウザツールで `note.com/contests` を開いて確認し直し、日付を今日に更新する。確認できなければ(ブラウザが使えない等)、お題は付けず候補バンクの範囲だけで選ぶ ③基本5個(外せないお題・ツール名タグがあるときだけ最大7個)。30字以内・ハイフン不可 ④**パチンコ・パチスロを連想させるタグは使わない** ⑤バンクにない新しいタグは、実在確認(`note.com/hashtag/<タグ>` を開き、note.com/tag/ にURLが変わって記事一覧が出るか)をしてから使い、採用基準に照らして問題なければ `hashtag_candidates.md` に追記する
   - 原稿の先頭「ハッシュタグ：」に、選んだタグを書き込む。選んだ理由(各タグが本文のどこと一致するか)を、1タグ1行で報告に含める
3. OKを出した稿を、ファイル名に「_完成」を付けて別名保存する(先頭の管理情報はそのまま残す)。**その記事で初めて「_完成」を作ったときは、同じ内容を `2_商品開発部/原稿/履歴/YYYY-MM-DD_完成_v1.md` にも保存する**(AIが書いた最初の版。オーナーの直しの量を測る比較元。`note-learn` スキルが使う。すでにv1があれば作らない)。
4. 次の形で報告する(会話ログ形式)：完成した旨／タイトル／種別・価格／有料ラインの位置(有料のみ)／ハッシュタグと理由／機械チェックの結果(ERROR件数)／**執筆AIが審査の指摘で直した箇所と、直さなかった箇所と理由(執筆AIの3回目の報告をそのまま使う。簡潔に)**。
完了したら確認せず販売AI(3_広報部)に進む。
