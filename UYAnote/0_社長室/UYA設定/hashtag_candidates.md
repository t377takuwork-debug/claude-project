# UYA. ハッシュタグ候補バンク

2026-09-28、オーナーが持ち寄った案から実在確認をして確定した「一般タグ」の一覧。`/uya-article`は記事のハッシュタグを選ぶとき、まずこのファイルを読み、記事の内容と一致するものを選ぶ（ここに載っていないタグを新しく思いつく場合は`参考資料/note_hashtag_reference.md`§3の手順で実在確認してから使う）。

**お題・コンテスト（#自己紹介 等）はここには含めない**。内容依存・入れ替わりがあるため`note.com/contests`を確認する運用のまま（`参考資料/note_hashtag_reference.md`§4、`.claude/commands/uya-article.md`の該当手順）。**ただしチェック頻度は下げる**（下記「お題・コンテストの確認頻度」参照）。

**お題の選択UIは1記事1つまでだが、他のお題タグも手入力すれば併用できる**（2026-09-29実機確認。詳細は`note_hashtag_reference.md`§4）。お題候補が複数あっても、基本的にはすべて手入力で併用してよい（合計10個の上限だけ気にすればよい）。

## お題・コンテストの確認頻度（2026-09-28確定）

**最終確認日：2026-09-28**

- 記事を作るたびに、まずこの日付を見る。**前回確認から14日以内なら`note.com/contests`のライブチェックを飛ばし**、下の「お題」表の記録から記事の内容と合うものを探す
- 14日を過ぎていたら`note.com/contests`を確認し直し、この日付を今日の日付に更新する（コンテストは1〜2ヶ月周期だが、複数が期限をずらして同時進行しているため、新しいものは2週間程度のペースで入れ替わる想定）
- 有料記事など特に力を入れる記事のときは、14日以内でも念のため確認してよい（必須ではない）

## 新しい候補タグを見つけたときの採用基準（2026-09-28確定）

一般タグ・お題を問わず、バンクにない新しいタグを候補にするときは、まず実在確認（`note_hashtag_reference.md`§3）をした上で、次の基準に照らす。

| 基準 | 扱い |
|---|---|
| 体系立てた稼ぎ方・ノウハウ訴求のタグ（例：ノウハウ・セールス・マネタイズ・売れる仕組み系） | **除外**。s4lvとの差別化（当事者記録・教えない）と矛盾するため |
| `personal_data.md`の事実と違う属性のタグ（例：子育て・既婚 等） | **除外**。捏造禁止ルールに反するため |
| 具体的な広告・ASPサービス名（例：Amazonアソシエイト・アドセンス） | **バンクに入れず個別記事ごとに判断**（開示ルール「具体的な仕組み名は記事ごとに判断」に従う） |
| 曖昧すぎる語・実態が確認できない語（例：安心・毎日投稿） | **除外** |
| 上記に当てはまらず、記事の中身と一致する | **採用候補にしてよい**。オーナー確認の上、この表に追記する |

## 個数の基準（2026-09-28確定）

- **基本5個**。note公式の目安（3〜5個程度、5つぐらいが効果的）に合わせる
- お題タグやツール名タグが内容的に外せない時だけ**最大7個**まで
- **プラットフォーム上限の10個は使わない**方針（タグを増やすこと自体は効果を保証しないため）
