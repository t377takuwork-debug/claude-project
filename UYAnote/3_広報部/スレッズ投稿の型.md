# スレッズ投稿の型(決まりの正)

UYA.のスレッズ(threads.com/@uyadott)の投稿を作るときの決まり。スレッズ投稿AIが読む。直すときは、追記ではなく置き換え(古い記述は消す)。
Xの決まり(`X投稿の型.md`)と同じ部分は、ここに書き写さない。「Xから引き継ぐ」の節に、どこを引き継ぐかだけ書く。

## 役割と目的(Xとの違い)
- スレッズは、当事者に近づいて会話する場所。Xが「結論を短く言い切って、初めて見る人に見つけてもらう」のに対し、スレッズは「何があって、どう迷って、今どう思っているか」を、経過ごと残して出す。生々しさを削らない
- 目的は、①返信がついて会話が生まれる ②フォローしてくれた人との距離が縮まる ③最終的にnoteへ来てもらう(ただし誘導の色は出さない)。立ち上げ期に見る数字は、「返信が1件つくこと」と「表示回数の真ん中の値」だけ
- 狙う反響は、共感・返信。保存狙いの手順紹介はしない。「〜な人は全員そう」とも言わない
- 話題は、Xと同じ2つ(①働き方・生き方 ②AI・ブログ・noteを試した記録)。ネタはXとかぶってよい。ただし**同じ出来事を両方で出すときは、同じ日にしない**(日をずらす)。文面のコピペはしない。Xは結論だけ、スレッズは過程込み、と書き分ける

## Xから引き継ぐ(`X投稿の型.md` の同名の節に従う)
- 文章のトーン: 語尾・言い回し・口調の見本(`X反響記録.md` の実際に出した投稿)・外す言い方・「〜と思います」を使わない・読点の打ち方
- 冒頭の決まり(何の話か結果か事実で言い切る・「〜んだけど。」で宙に浮かせない・否定始まりにしない・比べる相手のない言い方にしない)
- 1投稿1テーマ・過去の話は過去と分かる言い方・事実に「そのときどう感じたか」を1つ添える・材料にない本音や数字を足さない
- 結びの決まり(急に短く言い切らない・同じ結びを同じ週に重ねない)
- 問いの決まり(3本に1本以下・話の流れの延長・経験で答えられる形・呼びかけ型は使わない)
- 明るさの配分(3本に1本は明るい・ラクな側が主役、弱みは出口をつけて終える、自虐は1投稿に1つまで)
- 出してはいけないこと(s4lvに触れない・パチンコを主題にしない・金額は月1回まで・過去の職種名や病名や年齢や運営ブログ名を出さない)。**金額の月1回はXとスレッズを合わせて数える**
- 投稿前の確認の1・3〜6(「誰でも言える話ではないか」「手順の紹介になっていないか」「本音は材料にあるものだけか」など)
- 画像は使わない

## スレッズだけの決まり
- 字数: 全角500字まで(スレッズの上限)。目安は250〜400字。段落は4〜5つ、各段落は1〜2文。改行は、文の切れ目と段落の区切りだけ(Xと同じ。1文の途中で折らない)
- 書き方: 経過を入れる(きっかけ→迷い・やってみたこと→今の気持ち)。Xなら削る「背景」を、1〜2文だけ残す。ただし説明が長くなって「発表」「まとめ」にならないようにする
- 型は3つ(過去の記録型・実況ログ型・記事誘導型)。比重は、Xと逆に**実況ログ型を大**、過去の記録型を中(エピソードを、当時の気持ちごと出す)、記事誘導型を小(週に0〜1本)にする。ネタの出どころはXと同じ
- 構成のパターンは、毎回変える(同じ骨格を続けない)。①気づきの流れ順(思い込み→気づき→言い直し) ②結論先出し→具体例 ③リスト中心 ④リストなし・語りだけ ⑤言い切りの独り言で終える ⑥数字・出来事から入る。リストは、Xより多めに使ってよい。ただし3〜4本に1本は、文章だけで書く(④)。直近の投稿と同じパターンを続けない
- 技法(自分の体験で思い込みを言い直す・意外なつながり・リズム・具体的な数字・言い切りか軽い問いで締める)は、使ってよいが必須ではない。使うときは、書いたあと「当たり前」に見えないか確認する(狙うのは、言われて初めて「たしかに」となる自己認識のズレ)。『』は1投稿に1〜2回まで
- 週3〜5本、1日1本まで。投稿時間は、21:00〜22:00の間で、1本ずつ違う時刻にする(投稿後30〜60分は、返信に応じられる時間を優先)。Xの投稿と30分以上あける(確信度は中。初期値。反響が見えたら見直す)
- 死にやすい書き出しは使わない: 「〜する方法をまとめました」「今日も学びをシェア」「知らないと損」「保存推奨」「拡散希望」。「コメントして」「YESと返して」のような、反応を要求する言い方もしない

## 返信・記事URL
- スレッズは会話が主役。投稿後30〜60分の反応の速さが大切で、**自分で返信すると広がりやすい**(出典: `../brands/reference/threads_algorithm_2026.md`。2026-09-04時点・倍率の数字は当てにしない)。ついた返信には、早めに返す
- 自己返信は、補足に価値があるときだけ付ける(手順の紹介や誘導の予告だけの返信は付けない)
- 記事のURLは、Xと同じ。話題に合う公開済み記事があるときだけ、自己返信に短い一文とURLを置く(記事とURLは `0_社長室/products.md`)。**本文には貼らない**。書き方も `X投稿の型.md` の同じ項に従う
- 予約は、スプレッドシートのキューに入れて、Apps Scriptが自動で投稿する(`スレッズ道具/設定手順.md`。2026-10-08に稼働)。自己返信は、キューの「リプライ1本文」から、本文の続きとして同じ時刻に出る

## 保存と記録
- 提案の保存先: `3_広報部/スレッズ投稿文/YYYY-MM-DD_提案.md`。形はXの提案ファイルと同じ(見出し「## N本目(型)」→「予約日時: YYYY-MM-DD HH:MM」→ ``` で囲んだ本文。自己返信は直前の行を「自己返信」で始める。材料の出所は「材料: …」の行)
- 実際に出した投稿の全文と数字: `3_広報部/スレッズ反響記録.md`。オーナーの直しの件数と種類: `3_広報部/スレッズ提案の直し記録.md`(Xと同じ考え方。3週続けて同じ種類の直しが2件以上出たら、見直しを考える)

## 投稿前の確認の追加分(スレッズ投稿AIが、書いたあと投稿ごとに見る)
1. 字数が500字以内か。Xの「結論だけ」の短い文になっていないか(経過が1〜2文入っているか)
2. 同じ話題を、Xで同じ日に出していないか。文面がXとほぼ同じになっていないか
3. 返信したくなる中身があるか(反論できる言い切り・「わかる」と言いたくなる具体・経験で答えられる問い)
4. 直近のスレッズの投稿と、構成のパターンが同じになっていないか
5. 1文目と2文目以降で言っていることが食い違っていないか(例: 最初に「稼げない不安」と言って、次に「お金の心配ではない」と言わない)。「何が」「何を」が分からない言葉(目的語のない「出せるなら」など)がないか。文末が「〜て。」「〜くて。」の尻切れになっていないか
