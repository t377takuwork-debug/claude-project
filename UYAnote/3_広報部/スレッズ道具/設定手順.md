# スレッズ自動投稿の設定手順(あなたの作業と、私の作業)

UYA.のスレッズ投稿を、スプレッドシートに入れておくと自動で出る仕組みの、最初の設定。
仕組みの説明は、この下の「仕組み」を見てください。Metaの画面の言葉は、時期によって変わることがあります。近い名前の項目を探してください。

## 先に決めたこと
- シート: `sheets_config.json` に入っているシート。書き込みの鍵(サービスアカウント)は、MBTICODE・vivant・s4lvと同じものを使い回す
- トークン(Threadsの合言葉)は、チャットに貼らない。`threads_auth.local.json`(gitに入れない)と、シートの「設定」タブにだけ入れる

## あなたの作業

### A. シートの共有(まず、これだけ)
1. スプレッドシートの右上「共有」を押す
2. 次のメールアドレスを追加し、権限を「編集者」にする(通知は送らなくてよい)
   `mbticode-sheets-writer@avian-computer-503518-f6.iam.gserviceaccount.com`
3. 「共有しました」と私に伝える → 私が4つのタブ(Threads投稿キュー・設定・インサイト・日次観測ログ)を自動で作る

### B. Meta側(@uyadott をスレッズAPIにつなぐ)
1. developers.facebook.com にログインし、「マイアプリ」を開く。s4lvは既存のVIVANTアプリに @cfrms4lv をテスターとして足している。UYA.も、同じアプリに足すか、別のアプリを作るかを選ぶ(足せるなら足す方が楽。上限などは画面を見て判断)
2. アプリの「Threads API の設定」の「テスター管理」で、@uyadott を追加する
3. スマホのスレッズで @uyadott にログインし、届いた招待を承認する(これを飛ばすと操作できない)
4. 「アクセストークンを生成」で、短期トークンを発行する。同じ画面付近で、アプリのApp Secretを控える
5. 短期トークンを長期トークン(約60日)に交換する。ブラウザのアドレスバーに次を貼って開く(`APP_SECRET`と`SHORT_LIVED_TOKEN`を置き換える)
   `https://graph.threads.net/access_token?grant_type=th_exchange_token&client_secret=APP_SECRET&access_token=SHORT_LIVED_TOKEN`
6. 返ってきた `access_token` が長期トークン。次のアドレスを開いて、`id`(threads_user_id)を確かめる
   `https://graph.threads.net/v1.0/me?fields=id,username&access_token=長期トークン`
7. このフォルダに `threads_auth.local.json` を作り、次の形で保存する(**中身をチャットに貼らない**)
   `{"access_token": "長期トークン", "threads_user_id": "id", "app_secret": "APP_SECRET"}`
8. つながるかの確認(読み取りだけ)。ターミナルで次を実行し、`[OK] authenticated as: ...` と出ればよい
   `powershell -ExecutionPolicy Bypass -File "3_広報部\スレッズ道具\threads_connect_test.ps1"`

### C. Apps Script(自動で投稿する部分)
1. スプレッドシートの「拡張機能」→「Apps Script」を開く
2. このフォルダの `threads_scheduler.gs` の中身を全部コピーして、エディタに貼って保存する
3. シートの「設定」タブの B1 に access_token、B2 に threads_user_id を貼る
4. 実行する関数を `setup` にして実行する(初回は権限の確認が出るので許可)。実行後、B1・B2 の中身は自動で消える
5. 実行する関数を `installTriggers` にして実行する(15分おきの投稿、毎晩の数字の回収、異常があるときのメール、毎週月曜のトークン更新が設定される)

## 私の作業(あなたが上のA・Bを終えたあと)
- `setup_sheets.py` で、タブと見出しを作る
- 提案を入れる: `python 3_広報部/スレッズ道具/queue_from_proposal.py 3_広報部/スレッズ投稿文/YYYY-MM-DD_提案.md [番号]`(機械チェック → シートへ追加 → 読み戻して照合までを一度に行う。`--dry-run` で、シートに書かず確かめられる)
- 数字を読む: `python 3_広報部/スレッズ道具/fetch_insights.py`

## 仕組み
- シートの「Threads投稿キュー」に入れた行を、Apps Scriptが15分おきに見て、予定の時刻を過ぎた行をスレッズ公式APIで投稿する。パソコンを閉じていても動く
- 自己返信は、キューの「リプライ1本文」から入れる。本文の続きとしてつながる(最大4本)
- 数字(表示回数・いいね・返信・リポスト・引用)は、毎晩23:30にインサイトのタブへ回収される
- 時刻はキューの「投稿日時」で決まる。型の決まり(21:00〜22:00の間でばらす)は、提案ファイルの「予約日時」に書く
- **当日の枠に入れるときは、本文を確定させてから入れる**。時刻を過ぎた行はすぐ投稿される(s4lvで、確定前の本文が先に出た事故がある)
- **シートに手で貼り付けない**。セルの中の改行で行が割れる。必ず `queue_from_proposal.py` で入れる
- **ステータスの列を手で書き換えない**。もう一度投稿される事故になる。手で消した投稿の後始末は `withdraw_posted_row.py "YYYY-MM-DD HH:MM"`
- トークンの更新は、Apps Script側の月曜07:00だけ。ローカルでは更新しない(2系統がずれて失敗する)
- Windowsでは、pythonが見つからないときは `py -3` を使う
- Threadsの画面は、ブラウザの自動操作で動かさない(公式APIだけを使う)
