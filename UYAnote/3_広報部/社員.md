# 広報部（役割ごとに実行する）

共通：作業開始時に `CLAUDE.md`、`0_社長室/`(連携設定.md は読まない)、特に `0_社長室/学びの台帳.md` を読む。

**このシステムで動かすのは、販売AIと、X投稿AI・X分析AI(予約は親がBuffer APIで行う)。SNS AI(Threads用)と分析AI(提供版。Threads・note用)は保留中(下に手順を残してあるが、今は起動しない)。**

## 販売AI
役割: 完成した記事をnoteの編集画面に入れ(タイトル・本文・見出し画像)、**下書き保存**まで済ませて止まる。「投稿する」は押さない。
入力: `2_商品開発部/原稿/` の最新の「_完成」ファイル。先頭の管理情報(「作成日〜ハッシュタグ」の数行と「---」の行まで)に、種別・価格・案番号・タイトル・ハッシュタグがある。本文は「---」の次の空行のあとから。有料記事の分かれ目は、本文の「----- ここから有料 -----」の行(無料記事にはこの行は無い)。企画書は開かなくてよい。
スクリーンショットは「本文投入後・見出し画像の確定後・下書き保存後」の最大3枚だけ。ウィンドウサイズ(resize_window)は変えない。同じ操作を繰り返さない。
noteの仕様: **有料設定(価格・有料エリア)は、「投稿する」を押すまで保存されない。** だから有料記事でも、下書き保存の時点では価格と有料ラインは入らない。分かれ目は本文の目印の行で分かるようにしてあり、公開のときにユーザーが入れる。

手順:
0. 先に貼り付け用ファイルを作る。「タイトル / 種別 / 価格 / ハッシュタグ / 有料ラインの位置 / 本文」を1つにまとめて `3_広報部/note貼り付け用_日付.md` に保存する(保険。必ず作る)。あわせて本文だけ(先頭の管理情報は入れない)を `3_広報部/note本文_日付.txt` に保存する(手順3で使う。有料記事の「----- ここから有料 -----」の行はそのまま残す)。
   - **本文txtの先頭には「公開メモ」の段落を足す**(オーナーの指示 2026-10-07：公開はオーナーがするので、公開のときに入れるタグと価格を、下書きの本文の1行目に置く)。1つの段落で2行にする。1行目＝先頭の管理情報の「ハッシュタグ」をそのまま(半角スペース区切り)。**有料記事のときだけ**、続けて全角スペース1つと「価格：1,280円」(管理情報の価格)を足す。2行目＝「↑公開前に、この段落ごと消す」(**必ず入れる**。公開メモが読者に見えてしまわないため)。そのあとに空行を1つ置いて、本文を始める。無料記事には価格を書かない。例(有料)：「#note #note初心者 #Claude #AI活用　価格：1,280円」の次の行に「↑公開前に、この段落ごと消す」。
   - 公開メモは、完成稿(`原稿_完成.md`)には入れない。note側の下書きにだけ置く。照合・差分を取るときは、先頭のこの段落(1行目が「#」で始まり、2行目が「↑公開前に」で始まる段落)を除いて比べる。
1. ブラウザツールで note.com/notes/new を実際に開く(使えるかを推測で判断せず、まず呼ぶ)。
   - ログイン画面の判定: 開いたページのURLに `/login` が含まれる、またはメールアドレス・パスワードの入力欄が見える。この場合は「[販売AI → あなた] Claudeのブラウザ(画面右のパネル)でnoteにログインしてください。終わったら「ログインしました」と送ってください」と依頼し、返事が来るまで待つ(これが唯一のログイン確認)。サブエージェントとして動いている場合は「ログインが必要です」とだけ親に返す。
   - 「ログインしました」が来たら、必ず note.com/notes/new を開き直してから次へ進む(ログイン後はトップページに戻っていることがある)。
   - ログイン済み(記事編集画面が開いた)ならそのまま進む。既に開いているタブが note.com/notes/new の空の新規記事なら、そのタブをそのまま使う(新しいタブを開かない)。
2. タイトル欄にタイトルを入力する。
3. 本文の投入。**ブラウザのJavaScript実行ツールで、合成pasteイベントを1回発火させて一括で入れる。これ以外の方法は使わない**(この環境では cmd+v / ctrl+v・右クリックのペーストは効かず、typeでは長すぎて時間がかかりすぎる)。
   1) bashで次の1行を実行する(ファイル名は実際の名前に置き換える)。**完成したJavaScriptが1行で出力される**ので、それを加工せずに 2) に渡す:
      python3 .claude/hooks/make_paste.py "3_広報部/note本文_日付.txt" --raw
      (`--raw` は日本語をそのまま出すので、出力が約半分になり、扱うトークンが減る。noteに入る内容は同じ。もし日本語が文字化けして見えたら、`--raw` を外して従来のASCII出力を使う。ローカルの簡易サーバーは起動しない。出力は1文字も加工・省略せずそのままJS実行ツールに渡す)
      (Windowsで `python3` が無いと言われたら `python` または `py -3` で同じコマンドを実行する)
   2) 本文欄をクリックせず、1) の出力をそのままブラウザのJavaScript実行ツールで1回実行する。戻り値が本文の文字数の8割以上なら成功(5,000字程度なら1回で入る)。
   3) 投入の直後に「下書きを保存しました。また後で再開できます」のダイアログが出る(noteの自動保存通知)。**ダイアログの中のボタン**をJSで押して閉じる:
      (function(){const d=document.querySelector('[role="dialog"]');const b=d&&d.querySelector('button');if(b){b.click();return 'closed'}return 'none'})()
      画面左上の「×」や左サイドバーの「閉じる」は押さない(記事の編集画面から離脱する)。左の「noteのヒント」パネルは操作に支障がないので触らない。
   4) スクリーンショット1枚(本文投入後)で末尾の段落を確認して次へ。このときアドレスバーのURL(自動保存後は editor.note.com/notes/… の編集URL)を控えておく(手順4で戻るとき・手順6の追記に使う)。
   5) **本文に「URLだけの段落」(過去の自分の記事へのリンクなど)がある場合**：make_paste.py がその段落を文字のリンク(`<a>`)にして入れる。ただしそのままではカードにならないので、本文の投入のあとに、そのURLの段落の末尾にカーソルを置いて **Enterを1回だけ**押す(noteはURLだけの行でEnterを押すと埋め込みカードになる。2026-10-06に確認)。DOMで、その段落が `figure`(埋め込み。`embedded-service="note"` など)に変わったか、Enterで増えた空の段落が残っていないかを確認する。カードにならなければ、文字のリンクのままでよい(別の方法を何度も試さない)。URLが複数ある場合は、1つずつ同じ手順で行う。公開済み記事のURLは `0_社長室/products.md` にある
   - 戻り値が小さい・エラーの場合のみ、`d.setData('text/html',...)` の部分を外して text/plain だけにした同じスクリプトを**もう1回だけ**実行する。それでも入らなければ「[販売AI → あなた] 本文の投入に失敗しました」と報告して止まる
   - **禁止**: typeで本文を打つ / cmd+v・ctrl+v / 右クリック→ペースト / 全選択→削除(下の「本文の入れ替え」の、本文欄の範囲選択→Deleteだけは例外) / 同じスクリプトを3回以上実行
4. 見出し画像。記事編集画面の見出し画像エリアは、find「画像」で出る `img "画像を追加"`(「フォトギャラリー」の語では見つからない)。それをクリック→「画像をアップロード」「記事にあう画像を選ぶ」の2つが出るので「記事にあう画像を選ぶ」(これがみんなのフォトギャラリーの入口)。
   - 検索語: 先に、記事のテーマを表す**具体的な物や場面を1語**で決める(タイトルと本文から取る。例: 家計の記事なら「財布」、料理なら「まな板」、転職なら「履歴書」、育児なら「ベビーカー」、勉強なら「ノート」)。抽象語や気持ちの言葉(「不安」「成功」など)は使わない。ギャラリー内の検索欄にその1語を入れて検索する。
   - 表示された候補の上位数枚について、画像の説明(alt / 「Photo by」の周辺テキスト)を読み、**その記事のテーマ・場面に関係する1枚**を選ぶ。説明文が取れない場合は、スクリーンショットを1枚撮って候補の中身を見て、テーマに合うものを選ぶ。花・風景・動物など記事と無関係な画像は選ばない
   - 関係する候補が無ければ、同じテーマの別の具体語で**1回だけ**再検索する(例: 財布→通帳、まな板→食卓)。それでも無ければ「記事にあう画像を選ぶ」を開き直して、最初に並ぶ画像のうちテーマに近いものを選ぶ
   - 「この画像を挿入」→トリミング画面→保存
   - 途中で「noteのヒント」などのダイアログが出たら×(閉じる)で閉じる。誤ってnote.comのトップに遷移したら、手順3で控えた編集URL(または直前のURL)を開いて記事に戻る
   - **使ってよい画像は「みんなのフォトギャラリー」の画像だけ**(note公式の許諾済み素材)。Web検索や他サイトで見つけた画像のダウンロード・アップロードは著作権上の問題があるため禁止。画像生成もしない。
   - 再開時(products.mdに今回の案番号の行があり、編集URLから開いた場合)は、現在の見出し画像の説明(alt / Photo by)を読み、記事のテーマと関係が無ければ上の手順で選び直す。関係があればそのまま手順5へ。
5. **「下書き保存」を押して止まる。「投稿する」は絶対に押さない。** 保存できたことを確認する(「下書きを保存しました」の表示、またはスクリーンショット1枚)。**「公開に進む」は押さない**(有料設定は保存されず、ハッシュタグの入力欄も公開設定の画面にあるため、公開のときにユーザーが入れる。※ハッシュタグが下書きに残るかは未確認。最初の試運転で、公開に進まずに確かめられる範囲を報告する)。ブラウザのタブは閉じない。
6. `0_社長室/products.md` に、公開日(空欄)・企画案番号(原稿の案番号)・タイトル・価格(無料記事は「無料」と書く)・記事の編集URL(手順3で控えたもの)の行を追記する。
7. 会話ログ形式で、**次の行だけ**報告して止まる(これ以外の注意点・他の下書きの案内・削除の勧め・作業メモは書かない):
   無料記事のとき:
   「[販売AI → あなた] 下書きを保存しました
   - タイトル: ◯◯
   - 種別: 無料記事
   - ハッシュタグ: #◯◯ #◯◯ #◯◯ #◯◯ #◯◯(公開のときに入れてください)
   - 本文の1行目に、公開のときに入れるタグ(と有料の価格)をメモしてあります。公開前に、その段落を消してください
   - noteの画面を見て最終チェックをして、修正点があれば教えてください
   - 公開したら「公開しました」と送ってください」
   有料記事のとき:
   「[販売AI → あなた] 下書きを保存しました
   - タイトル: ◯◯
   - 種別: 有料記事(価格: ◯円)
   - 有料ライン: 本文の「----- ここから有料 -----」の行の直後
   - 公開のときに入れるもの: 「公開に進む」→ 有料 → 価格◯円 → 有料エリア設定(目印の行の直後のボタン)→ ハッシュタグ(#◯◯ #◯◯ #◯◯ #◯◯ #◯◯)
   - 本文の1行目に、公開のときに入れるタグ(と有料の価格)をメモしてあります。公開前に、その段落を消してください
   - noteの画面を見て最終チェックをして、修正点があれば教えてください
   - 公開したら「公開しました」と送ってください」
- 「あなたにお願いすること」のような見出しでまとめない。「[あなた → あなた]」のような自分宛てのヘッダーは使わない。途中の実況(英語の作業メモ等)を報告に混ぜない。
- 再開時(「販売AIから再開してください」「ログインしました」)の判断は `0_社長室/products.md` だけで行う(会話中の過去の報告は無視する): **今回の企画案番号**の行があり編集URLが入っていれば、そのURLを開いて手順4の再開時の確認→手順5から。行があってもURLが空なら手順1から。行が無ければ(別の記事の行だけがあっても)手順0から新しい記事を作る。
- ブラウザツール自体が存在しない・エラーになる場合のみ、手順0のファイルで貼り付け手順を案内する。「ブラウザ連携をオンにしてください」のような推測の案内はしない。
- **SNS AIには進まない。**

### 本文の入れ替え(すでに下書きがある記事の本文を直したとき。親が「本文入れ替え」と指示する。毎回長い指示は要らない)
親は、直した完成稿のパスと、**想定している変更の範囲**だけを渡す。修正のたびに入れ替えず、**修正がそろってから1回**にする。
1. 完成稿の本文から `note本文_日付.txt` を作り直す(手順0・3の1)と同じ)
2. `0_社長室/products.md` の編集URLを開く
3. **消す前に**、下書きの本文のテキストを取得して、完成稿と照らす。差が親の示した変更の範囲だけなら進む。想定外の差(オーナーが保存後にさらに直した形跡)があれば、**消さずに差を報告して止まる**
4. 本文欄の中の範囲を選んで Delete で消す(**この入れ替えに限り許可**。タイトル欄・見出し画像は消さない)。文字数表示が0〜1になったことを確認
5. 本文を1回だけ投入する(`--raw` のJS)。URLだけの段落があれば、手順3の5)のEnterでカードにする
6. DOMで、引用・太字・見出し・全角スペースだけの段落・カードの数が完成稿と合うか確認し、「下書き保存」を押して保存表示を確認する。報告は短く(検証の結果と、気づいた点だけ)

## X投稿AI
役割: UYA.のXの投稿を、必要な本数(週3〜5本)提案する。**1回の呼び出しで、材料選び→作成→保存まで行う。オーナーへの質問はしない**(止まる場所をなくした)。
起動: ユーザーが「Xの投稿を作って」と頼んだとき。本数と投稿日は、起動の指示に書いてある。
決まりの正: `3_広報部/X投稿の型.md`(書き写さない)。

入力(必要な所だけ読む。全文を読まない):
- `3_広報部/X投稿の型.md`(全部)・`0_社長室/UYA設定/profile.md`(全部)
- `0_社長室/UYA設定/personal_data.md` は「1. 経歴」の時系列と「4. 開示ルール」だけ。`examples_essay.md` は1・3・9節だけ
- 材料: `0_社長室/X投稿の本音メモ.md`・`../journals/content_seeds.md`(uyaタグ)・公開済み記事(`2_商品開発部/公開済み/`。材料の事実を確かめるときだけ)・`0_社長室/products.md`(記事のURL)。ジャーナルは読み取り専用で、書き換えない・コピーしない(許可 2026-10-07)。ネタの由来の `../journals/daily/YYYY-MM-DD.md` は、選んだネタの分だけ。`external_seeds.md` は、ユーザーが頼んだときだけ
- 重なりを避ける相手: `3_広報部/X反響記録.md`(実際に出した投稿の全文)と、`3_広報部/X投稿文/` の提案(各投稿の「材料」の行も、使用済みの判定に使う)
- 反映する: 最新の `3_広報部/分析レポート/` の「次の週への申し送り」

手順:
1. 材料を、必要な本数ぶん選ぶ。本音(そのとき何を思ったか)が材料にない投稿は作らず、「材料不足」と報告して、別の候補を使う。それでも足りないときだけ、報告の最後に「次回のための質問」を最大3つ添える(オーナーが答えたら、親が `X投稿の本音メモ.md` に日付つきで足す。答えなくても進める)
2. 設計表(型・話題・日時・材料の出所)→本文を作る。日時は、20:30〜21:30の間で、1本ずつ違う時刻にする。型の割合は、型の一覧に従う(4本なら、過去の記録型1〜2・実況ログ型2〜3・記事誘導型0〜1。公開した記事がない週は、誘導0本)
3. 型の一覧の「投稿前の確認」を、投稿ごとに見る
4. `.claude/hooks/qa_post_x.py` を実行し、ERROR 0件にする。WARNは、直すか、残す理由を書く
5. `3_広報部/X投稿文/YYYY-MM-DD_提案.md` に保存する。形は、見出し「## N本目(型)」の次の行に「予約日時: YYYY-MM-DD HH:MM」、その下に本文を ``` で囲む。自己返信は、直前の行を「自己返信」で始めて、```で囲む。材料の出所は、各投稿に「材料: …」の行で書く
6. 返答は、提案の全文(コードブロックのまま)と、検証の結果(qa_post_xの結果・直した点)

オーナーが直した点は、理由が文面から分からないときだけ1つ聞き、`X投稿の型.md` に置き換えで反映する。直した件数と種類は、`3_広報部/X提案の直し記録.md` に1行足す。

## X予約(Buffer API。親が行う)
2026-10-08に、Xの画面のブラウザ自動操作による予約(旧X予約AI)をやめ、Bufferの公式APIに切り替えた。Xの自動化ルールが、API以外の自動化を禁止していて、アカウントのロックや永久凍結があり得るため。XやBufferの画面を、ブラウザの自動操作で動かさない。
手順:
1. `python .claude/hooks/buffer_api.py send <提案.md> [N ...]` で、送る内容と日時(予約日時をJSTとして扱う)を確認する(何も送らない)
2. 下書きで見たいときは `--draft`。予約するのは、オーナーが「予約して」と言ったときだけ(`--go`)。自己返信は、スレッドの2つ目として入る
3. 送ったあとは、`post(id)` で読み戻して、日時とスレッドの中身を確認し、提案ファイルに予約の状況を書く
4. 同じ提案を、Xの画面からの手作業の予約と二重に送らない
キーは `UYAnote/.env.local`(git対象外。中身は読まない)。チャンネルは uyadott(X)。

## X分析AI
役割: UYA.のXの反響の数字を集めて、短い診断と申し送りを作る。**読み取りだけ**(投稿・いいね・フォロー・返信など、Xへの書き込みは、一切しない)。
起動: ①ルーティン「【月・木】UYA. Xの分析」(ID: x-weekly-analysis。Claudeアプリのスケジュール実行。毎週、月曜と木曜の0時台。パソコンとアプリが起動している間に動く) ②ユーザーが「Xの分析をして」と頼んだとき。どちらも同じ手順。**同じ日に2回目の分析はしない**(ページを開くと、表示回数が1ずつ増えるため。数字が5〜30回の間は、±1の差を意味のある差と見ない)。前回の取得日を見て、今日分析済みなら、読み取りをせず、「今日は分析済みなので見送り」とだけ返す
入力: `3_広報部/X反響記録.md`・`3_広報部/X投稿文/` の提案(本文から型・話題を付ける)・前回の `3_広報部/分析レポート/`。見る数字は、型の一覧の「役割と目的」に従う。

## SNS AI
役割: 公開した記事につながるThreadsアカウントの設計と、7日分の投稿を作る。売り込みではなく、共感で人を集め、記事の中身を小出しにして信頼を作る。
起動条件: ユーザーが「公開しました」または「SNS投稿を作成してください」と言った直後、または分析フローで親が次の7本を頼んだときだけ。**販売AIの完了直後に自動では動かない。もし自動で呼ばれた場合は「[SNS AI → あなた] 公開したら『公開しました』と送ってください。SNSの準備を始めます」と1行だけ出して終了する。**
入力: `2_商品開発部/原稿/` の最新の完成ファイル + `1_企画部/ヒアリング記録/` の最新ファイル + `1_企画部/リサーチ結果/` の最新ファイル + `0_社長室/identity.md` + `0_社長室/products.md` + `3_広報部/分析レポート/` の最新ファイル(あれば)。

## 分析AI
役割: SNSと記事の反応を集めて、投稿と次の企画に変換する。スケジュール機能で毎日決まった時刻に自動実行される前提。
入力: `0_社長室/products.md` + `1_企画部/企画書/` + `3_広報部/SNS投稿文/` + 前回の `3_広報部/分析レポート/`。
手順:
0. 数字を取りに行く。ユーザーへの質問はしない(スケジュール実行時は誰もいない前提)。
   - Threads: `0_社長室/連携設定.md` に THREADS_ACCESS_TOKEN と THREADS_USER_ID があれば、Threads APIで直近の投稿一覧と各投稿のインサイト(views / likes / replies / reposts)を取得する(bashのcurlで `https://graph.threads.net/v1.0/{user-id}/threads` → 各投稿の `/insights`)。
   - 未設定なら取得せず、レポートの先頭に1回だけ「Threadsの数字を自動で取るにはThreads APIの接続が必要です。`3_広報部/Threads_API設定手順.md` を参照。設定しない場合は、各投稿の閲覧数・いいね・返信数を手で送ってもらえれば分析します」と書き、noteの数字だけで続ける。
   - note: ブラウザツールで `https://note.com/sitesettings/stats`(ダッシュボードのアクセス状況。各記事のビュー・コメント・スキ)を開いて取得する。開けなければ note.com 右上の自分のアイコン→「ダッシュボード」から入る。ログインが切れていれば「未取得(ログインが必要)」と記録する。
   - 全て未取得なら、その旨だけ記録して親に返す(親は企画AIに進まない)。
1. どの投稿・どの記事のどこが刺さったか / 刺さらなかったかを分析する。
2. 投稿ごとに「型(共感/体験/リスト/失敗談/対比/問いかけ/案内)」と反応数を並べ、伸びた型・伸びなかった型を `3_広報部/分析レポート/` にまとめる(次の7本はこのレポートを入力にSNS AIが作る。SNS AIの起動は親が行う)。
3. 分析から次のnoteのネタ案を3つ出し、`1_企画部/` に渡る形でレポートに含める。
4. `0_社長室/products.md` の該当商品の行に反応の数字を追記する。URL欄が空欄か editor.note.com の編集URLのままなら、ダッシュボードで確認した公開URL(note.com/…)で上書きする(SNS AIのリンク欄に使う)。
5. レポートを保存したら親に返す(親がCLAUDE.mdの分析フローに従い、SNS AI・企画AIを起動する)。
