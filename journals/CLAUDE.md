# journals プロジェクト

音声ジャーナル（思考ログの文字起こし）を、記録・構造化・分析まで一気通貫で資産化するパイプライン。
処理は `/journal` スキルが担う（定義: `.claude/commands/journal.md`）。

**注意**: ここはリポジトリ管理下のナレッジベース。Claude Codeの自動メモリ（`~/.claude/projects/.../memory/`）とは別物で、混同しない。メモリは「Claude Codeがユーザーとの協働について覚えておくこと」、journalsは「ユーザー自身の思考ログの資産化」。

---

## ディレクトリ構成

```
journals/
├── CLAUDE.md              ← 本ファイル
├── daily/
│   ├── YYYY-MM-DD.md      ← クレンジング済みジャーナル本文（1日1ファイル・同日複数回は時刻見出しで追記）＋抽出結果・分析セクション
│   └── raw/
│       └── YYYY-MM-DD.txt ← クレンジング前の生の文字起こし（検証用・同日複数回は時刻区切りで追記）
├── tasks.md                ← タスクの横断インデックス
├── ideas.md                 ← アイデアの横断インデックス
├── insights.md              ← 気付きの横断インデックス
├── content_seeds.md         ← ブログ/SNSネタの横断インデックス（候補先アカウントをタグ付け）
├── themes.md                ← 長期テーマ（テーマ単位で育てる。単純な追記ログではない）
└── collision_log.md         ← 既存方針とのバッティング検知ログ
```

## 使い方（最小手順）

1. 音声ジャーナルの文字起こしテキストをそのまま貼り付け、`/journal` を実行する
2. 日付を聞かれたら答える（省略時は当日扱い）
3. 出力される「保存先・抽出件数・方針バッティング検知・Next Action提案」を確認する

長い未整形テキストが指示なしで貼られた場合、`/journal`として処理してよいか一言確認してから進める（黙って推測しない）。

## 完了条件

- `daily/raw/YYYY-MM-DD.txt` と `daily/YYYY-MM-DD.md` が保存済み
- 該当する横断インデックス（tasks / ideas / insights / content_seeds / themes）に抽出結果が反映済み
- 方針バッティングを検知した場合は `collision_log.md` に記録し、ユーザーへ確認済み（未回答のまま放置しない）

## 関連ルール

- 捏造禁止の精神をそのまま適用する：クレンジングは「フィラー除去・誤字修正」に留め、発言していない主張や結論を足さない
- 既存の基盤ファイル（ルート`CLAUDE.md`・各`rules/`・`rewrite_common_rules.md`・`docs/systems/`等）は本パイプラインが勝手に書き換えない。矛盾を検知したら提案として確認するのみ
