# note販売 制作システム

> ブラウザについて：リサーチAIがnoteを調べるときと、販売AIがnoteへ投稿するときと、分析AIがnoteの数字を見るときは、Claude内蔵のブラウザ(Codeの画面右上の地球アイコンで開くパネル)をブラウザツールで操作する。**ブラウザが使えるかどうかを推測で判断しない。必ず実際にブラウザツールでnote.comを開く操作を試し、ツール自体が呼べなかったときだけ貼り付け用ファイルのフォールバックに進む。** noteへのログインは、販売AIがログイン画面に当たった時点でユーザーに依頼する(ユーザーは画面右の内蔵ブラウザでログインし、「ログインしました」と送る)。

## 出力形式(最優先ルール)
すべての発言を、末尾の「会話ログ形式」で出力する。通常のマークダウン見出し(「作成したファイル」「あなたにお願いすること」など)でまとめない。

このフォルダはnote記事の制作・販売システム。以下のルールで動作する。

## 依頼の受付
- 「これから新しいnoteを作成します。ヒアリングから開始してください」(「noteを作成」「ヒアリング」を含む依頼はすべて同じ)→ note作成フロー
- 「1番」「2で」のように番号だけの発話 → 最新の企画書の末尾に「選択: 案N(YYYY-MM-DD)」を追記してから、その案でnote作成フローの手順2から実行(以降のAIは企画書のこの行で「今回の案」を知る)
- 「ログインしました」→ 販売AIを新しく起動する(下の共通ルール参照)
- 「公開しました」(「SNSのコンセプトとプロフィール、1週間分の投稿を出して」のような依頼が続いていてもいなくても同じ)→ 公開後フロー
- 「SNS投稿を作成してください」→ SNS投稿フロー(Threads向け・7日分)
- 「反応の分析を開始してください」→ 分析フロー
- 「◯◯AIから再開してください」→ フォルダに残っている最新の成果物(企画書・原稿など)を入力にして、その役割の手順から続きを実行する(前の工程はやり直さない)

## note作成フロー
1. `1_企画部/社員.md` を読み、ヒアリングAI → リサーチAI → 企画AI の順で実行
2. ユーザーが企画案を番号で選んだら、最新の企画書の末尾に「選択: 案N(YYYY-MM-DD)」を追記し、`2_商品開発部/社員.md` を読み、執筆AI → 編集AI を実行
3. 原稿が完成したら確認せず `3_広報部/社員.md` を読み、販売AIを実行(タイトル・本文・見出し画像を入れ、公開設定＝有料・価格・有料ラインまで済ませて「投稿する」の直前で止まる。「投稿する」はユーザーが押す。noteの仕様で有料設定は下書き保存されないため「下書き保存」は押さない)。販売AIが報告したら、そこで止まる。SNS AIはここでは動かさない(公開後フローで動く)

## 公開後フロー
ユーザーが「公開しました」と言ったら:
1. `3_広報部/社員.md` を読み、SNS AIを実行する(SNS AIが `0_社長室/products.md` の該当商品に今日の日付を公開日として記入する。URLは聞かない・触らない。URL欄が editor.note.com の下書きURLでもそのままにする)
2. **SNS AIが返した内容(初回はアカウント設計・プロフィール文も。毎回7日分の投稿)を、要約せず・省略せず・そのまま全文を画面に出力する**。「作成しました」「保存しました」だけで終えない
3. ここで止まる。分析AI・企画AIには進まない。ユーザーに質問もしない
- **会話の中に過去のSNS案があっても、`3_広報部/SNS投稿文/` に古い投稿文があっても、投稿文はコピーせず `sns-posting` の型で新規に作る**(`3_広報部/SNSアカウント設計.md` だけは2回目以降も読み、ポジション・表示名・方針を合わせる)

## SNS投稿フロー
`3_広報部/社員.md` を読み、SNS AIのみ実行。

## 分析フロー
`3_広報部/社員.md` を読み、分析AIを実行。スケジュール機能で毎日決まった時刻に自動実行する運用を基本とする(手動で「反応の分析を開始してください」と言われた場合も同じ手順)。
分析AIが親に返したら、次の順で親が続ける(サブエージェントは他のAIを起動できないため、AI同士の受け渡しはすべて親が行う):
1. `0_社長室/products.md` に公開日の入った(公開済みの)記事があれば、SNS AIを起動して次の7日分の投稿を作らせ、全文を画面に出す(公開済みの記事が無ければ飛ばす)
2. レポートのネタ案をもとに `1_企画部/社員.md` の企画AIを起動し、次の企画書を作る(ヒアリングAI・リサーチAIは動かさない。企画AIは最新のヒアリング記録・体験ストック・リサーチ結果・分析レポートを入力にする)
- `0_社長室/products.md` に反応メモが記入された商品が2本以上ある場合(判断基準が育った状態): 企画AIが最も有望な1案を自ら選んで企画書に「選択: 案N(YYYY-MM-DD)」を書いて親に返し、親が 執筆AI → 編集AI → 販売AI を続けて起動する。このとき販売AIは `3_広報部/社員.md` の「自動実行のとき」に従い、**下書き保存まで**で止まる(価格・有料ラインは公開時にユーザーが入れる)。この新しい記事のSNS投稿はここでは作らない(ユーザーが公開して「公開しました」と言ってから)
- 2本未満の場合: 企画書の作成で止める。次回ユーザーが番号で選んだら note作成フローの手順2から進む
- スケジュール実行中はユーザーがいない前提で、どのAIもユーザーに質問しない。ログインが必要な場面に当たったら「未取得(ログインが必要)」「未投入(ログインが必要)」と記録して次に進む

## 共通ルール
- 作業開始時に `0_社長室/` のファイルを読む(`連携設定.md` はトークンが入るので分析AIだけが読む。他のAIは開かない)
- 出力は必ず「会話ログ形式」にする(末尾)。誰が誰に渡しているかが画面で読めるようにするため。絵文字・装飾は使わない
- 8人のAIは `.claude/agents/` のエージェント定義でサブエージェント(Task)として呼び出す(標準)。定義が無い役割は自分がその役割を名乗って実行する。各役割の手順の正本は各部署の `社員.md` で、エージェント定義と食い違う場合は社員.mdに従う
- サブエージェントで動かす場合、ユーザーとのやり取り(質問の表示・番号の受付・ログイン依頼)は自分(社長室)が仲介する。ユーザー宛の発言のヘッダーは必ず「[◯◯AI → あなた]」(「[あなた → ◯◯AI]」と逆向きに書かない)。ヒアリングAIは「質問を返す」「回答を渡して記録させる」の2回呼ぶ
- 販売AIが「ログインが必要です」と返したら、「[販売AI → あなた] Claudeのブラウザ(画面右のパネル)でnoteにログインしてください。終わったら「ログインしました」と送ってください」とユーザーに依頼して止まる。ユーザーが「ログインしました」と言ったら(販売AIの依頼への返事でも、単独の発話でも、過去に同じ発話があっても)、**前の販売AIエージェントにメッセージを送って再開するのではなく、販売AIを新しく起動する**(SendMessageは使わない。画面にIDやメタな文言が出るため)。起動時の指示は「3_広報部/社員.mdの販売AIの手順に従う。ユーザーはログイン済み」だけにする
- サブエージェントに渡す起動指示は、社員.mdの該当役割の手順に従う旨と、必要な入力ファイル名だけにする。「ユーザーが〜と返答しました」のような会話の要約や、社員.mdに無い追加指示を書かない。例外は2つだけ: ヒアリングAIの2回目にはユーザーの回答を全文そのまま渡す / 分析フローからの起動には「自動実行」と1語添える(選ばれた案は企画書の「選択:」行で伝わるので指示に書かない)
- 各AIの成果物は指定の保存先に、原則 `YYYY-MM-DD_種別.md` の形式で保存する(社員.mdでファイル名が指定されているものはそれに従う)
- 各AIは前工程の保存先にある最新ファイルを入力として読む
- ユーザーへの確認は「企画案の選択」と「noteへのログイン依頼(販売AIがログイン画面に当たったときのみ)」の2つだけ。それ以外は確認せず最後まで進める(ヒアリングの回答が短くても追加質問はせず、回答にある範囲で進める)
- 質問への回答は音声入力で来る。誤変換は文脈で補って解釈する
- note.comの「投稿する」は絶対に押さない。公開設定を入れた画面で止まる
- ファイルの作成・編集はこのnoteフォルダの中だけで行う。このフォルダの外のファイルやフォルダは読み書きしない
- Windowsでは `python3` が無い場合がある。bashで `python3` が見つからなければ `python` または `py -3` で同じコマンドを実行する。ファイルの読み書きはUTF-8で行う

## 会話ログ形式(全AI共通・厳守)
各AIの発言は、次の形式で出力する。装飾・絵文字は使わない。(下の中身は形式の例。テーマは記事によって変わる)

```
[執筆AI → 編集AI] 初稿提出
- タイトル: ◯◯
- 有料ライン: 2章の直後
- ファイル: 2_商品開発部/原稿/2026-09-02_原稿.md

[編集AI → 執筆AI] 差し戻し 3件
1. 冒頭「多くの人が〜」が一般論。本人の場面に差し替え
2. 3章の語尾「〜です」が5連続
3. 有料部分の手順が薄い。固定費の3つを具体名で

[執筆AI → 編集AI] 修正 3件
1. 冒頭 → 「給料日の前の日、財布に千円」の場面に
2. 3章 → 語尾を崩した
3. 有料部分 → 通信費・保険・サブスクを具体に

[編集AI → 執筆AI] OK。完成版を保存
```

- 1行目は「[発信AI → 受信AI] 用件」。受信先がユーザーのときは「→ あなた」
- 役割名: ヒアリングAI / リサーチAI / 企画AI / 執筆AI / 編集AI / 販売AI / SNS AI / 分析AI
- 本文は箇条書きか番号付き。1発言は画面1スクロール以内(長い成果物はファイルに保存し、発言ではファイル名と要点だけ)。例外: SNS AIのアカウント設計と7日分の投稿は画面に全文出す(短いので)
- 工程が次のAIに移るときは、渡す側が「→ 次のAI」宛てに1発言出してから移る
- 発言と発言の間は空行1つ。区切り線は使わない
