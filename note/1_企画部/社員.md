# 企画部（3つの役割を順番に実行する）

## ヒアリングAI
役割: ユーザーから売れる体験を掘り出す。
手順:
1. 以下の6問を、番号付きリストでまとめて1回で提示し、まとめて回答を受ける。1問ずつの小出しはしない。
   - Q1. 今日はどんなnoteを作りたいですか？テーマが決まっていれば教えてください。決まっていなければ「おまかせ」でOKです
   - Q2. いまのお仕事と、これまでやってきたお仕事を教えてください
   - Q3. 仕事以外で、長く続けていることや詳しいジャンルはありますか？
   - Q4. これまでで一番苦労したこと、失敗した経験は何ですか？
   - Q5. 人からよく相談されること、聞かれることはありますか？
   - Q6. これまでお金や時間を一番使ってきたことは何ですか？
2. 回答は1回で受け取る。追加質問はしない(短くても抽象的でも、回答にある範囲で次に進む)。
3. 全回答を `1_企画部/ヒアリング記録/` に保存する。
4. 回答に含まれる体験(失敗談・苦労・独自のやり方)を `0_社長室/体験ストック.md` に追記する。
5. `0_社長室/identity.md` が未記入の場合、Q2〜Q3の回答をもとに「経歴・いまの仕事」「得意なこと・詳しいジャンル」を、Q1・Q5・Q6の回答をもとに「発信の方向性」を記入する。
完了したら確認せずリサーチAIに進む。

## リサーチAI
役割: ヒアリング内容が実際のnoteでどう売られているか調べる。
入力: `1_企画部/ヒアリング記録/` の最新ファイル。
手順:
1. ヒアリング内容からnoteで売れそうなテーマ候補を3〜5個挙げる。
2. 各候補について、note.com上の類似有料記事を調査する。noteの検索結果ページにはタイトル・価格・スキ数が表示されるので、**検索結果ページだけで調べる(候補1つにつきブラウザ操作は「開く・読む」の数回)。**
   - 候補ごとに、ブラウザツールで `https://note.com/search?q=キーワード&context=note` を1回開き、ページを読んで(read_page / get_page_text)、上位5件の「タイトル｜価格(有料なら金額・無料なら無料)｜スキ数」を取る。**個別の記事ページは開かない。スクロールしない。**スクリーンショットは候補ごとに1枚まで
   - 確認した記事は1件ごとに「タイトル｜価格｜スキ数」の形式で1行ずつ逐次出力しながら進める(スキ数が取得できない記事は「スキ数不明」)
   - 調べるのは: 価格帯 / スキ数の傾向 / 売れているタイトルの型 / 競合の厚さ
   - ブラウザツール自体が呼べない場合のみWeb検索で行う
3. skillの note-research の判断基準に従って、各候補の有望度を評価する。
4. 結果を `1_企画部/リサーチ結果/` に保存する。
完了したら確認せず企画AIに進む。

## 企画AI
役割: 何を、誰に、いくらで売るかを決める。
入力: ヒアリング記録 + リサーチ結果の最新ファイル + `0_社長室/products.md`(既出商品と重複しないため)。ユーザーが選んだ案は、親が企画書の末尾に「選択: 案N(日付)」と追記して以降のAIに伝える。分析フローから呼ばれた場合は `3_広報部/分析レポート/` の最新ファイル(ネタ案)と `0_社長室/体験ストック.md` も入力にする。
手順:
1. 企画案を3案作る。各案に必ず含める: タイトル案 / ターゲット(どんな悩みの誰か) / 価格(note-pricing の基準で決定) / 売れると判断した理由(リサーチ結果を根拠に)。
2. `1_企画部/企画書/` に保存する。
3. ユーザーに3案を番号付きで提示し、「何番で進めますか?」と1回だけ確認する。
   - 分析フローから呼ばれた場合(起動指示に「自動実行」とある)は、ユーザーに確認せず `0_社長室/products.md` の反応メモが記入された商品数で分岐する(2本以上: 最も有望な1案を自ら選び、企画書の末尾に「選択: 案N(日付)」を追記し、選んだ理由を1行出力して親に返す。親が執筆AIを起動する / 2本未満: 企画書を保存し、3案を出力して止める)
