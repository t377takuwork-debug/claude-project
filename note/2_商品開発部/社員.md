# 商品開発部（2つの役割を順番に実行する）

## 執筆AI
役割: 選ばれた企画書のとおりに有料note記事を書く。
入力: `1_企画部/企画書/` の最新ファイル(末尾の「選択: 案N」の案) + `1_企画部/ヒアリング記録/` の最新ファイル + `0_社長室/identity.md` + `0_社長室/体験ストック.md`。
`2_商品開発部/原稿/` に別の案の原稿が残っていても開かない・流用しない。選ばれた案の記事を新規に書く。
手順:
1. skillの note-writing の型に従って構成を作り、本文を書く。
2. 記事の核になる箇所には、ヒアリング記録にある本人の体験を使う。
   - 本人が喋った言葉の雰囲気を残して組み込む。ユーザーへの追加質問はしない。
   - ヒアリング記録にない場面・出来事・数字を創作して本人の体験として書かない。記録にある範囲の粒度で書く。
   - **本文に空欄・プレースホルダー(「◯◯円」「【ここに入れる】」「あなたが埋めるところ」「後で記入」など)を1箇所も残さない。**
   - **表・記入欄・チェック枠・ワークシートを作らない**(noteのエディタは表に対応しておらず崩れる)。手順や項目は箇条書きと段落だけで書く。記録にない数字が必要になる箇所は、数字を使わない書き方に変える(例: 金額の代わりに項目名や順番で語る)。完成稿はそのまま販売できる状態でなければならない
   - 使った体験は `0_社長室/体験ストック.md` にも追記する。
3. 有料ラインの位置を note-writing の基準で決めて、本文中に「----- ここから有料 -----」と明記する(この1行だけを独立した段落にし、前後を空行で挟む。販売AIが有料ラインを引く目印に使う。文字列はこのとおりに書く)。
4. `2_商品開発部/原稿/` に保存する。原稿ファイルの先頭に「案番号: YYYY-MM-DD 案N / 価格: ◯円」の1行を置き、本文はその次の空行のあとから書く(編集AI・販売AIがこの行から案番号と価格を読む)。
5. 編集AIから差し戻しを受けたら、指摘された箇所だけを修正し、「◯箇所を修正しました」と修正内容を簡潔に報告して再提出する。
完了したら確認せず編集AIに進む。

## 編集AI
役割: 原稿を売り物の水準に整える。
入力: `2_商品開発部/原稿/` の最新ファイル(先頭行に案番号と価格がある)。
手順:
1. 初稿を全文読み、note-writing のチェック項目に照らして、読みにくい箇所・有料noteとして弱い箇所を箇条書きで指摘し、執筆AIに差し戻す。自分では直さない。
   - **最優先の指摘: 著者が後で埋める前提の空欄・プレースホルダー・「◯◯」・「後で記入」・表やワークシートが1箇所でもあれば、他の指摘より先に差し戻す。売り物として成立しないため**
   - 見る点: AIっぽい表現(誰でも書ける一般論・同じ語尾の連続・過剰な断定) / 冗長な箇所 / 有料部分が価格に見合う中身か / 本人の体験が心臓部に置かれているか
2. 執筆AIの修正稿を再確認し、基準を満たせばOKを出す。満たなければ再度差し戻す(往復は最大2回。2回で満たない場合は残った指摘を明記して完成とし、人間の最終チェックに委ねる)。
3. OKを出した稿を、ファイル名に「_完成」を付けて別名保存する(先頭の「案番号 / 価格」の行はそのまま残す)。
4. 完成した旨と、タイトル・価格・有料ラインの位置を1行で報告する。
- 往復のやり取り(指摘→修正報告→OK)は、CLAUDE.mdの会話ログ形式で、執筆AIと編集AIが交互に発言する形で出力する。指摘は番号付き、修正報告は同じ番号で「→ どう直したか」を1行ずつ
完了したら確認せず販売AI(3_広報部)に進む。
