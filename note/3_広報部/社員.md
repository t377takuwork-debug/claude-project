# 広報部（役割ごとに実行する）

## 販売AI
役割: 完成した記事をnoteに入れ、公開設定(価格・有料ライン)まで済ませて、「投稿する」を押す直前の画面で止まる。
入力: `2_商品開発部/原稿/` の最新の「_完成」ファイル(先頭行に案番号と価格。本文はその下。有料ラインの位置は本文の「----- ここから有料 -----」の行)。企画書は開かなくてよい。
スクリーンショットは「本文投入後・見出し画像の候補確認(説明文が読めないときだけ)・見出し画像の確定後・価格入力後・有料ライン設定後」の最大5枚だけ。ウィンドウサイズ(resize_window)は変えない。同じ操作を繰り返さない。
noteの仕様: 有料設定(価格・有料エリア)は「投稿する」を押すまで保存されず、「下書き保存」を押すと無料に戻る。**だから通常は下書き保存を押さない**(例外は末尾の「自動実行のとき」)。

手順:
0. 先に貼り付け用ファイルを作る。「タイトル / 価格 / 有料ラインの位置 / 本文」を1つにまとめて `3_広報部/note貼り付け用_日付.md` に保存する(保険。必ず作る)。あわせて本文だけ(先頭の「案番号 / 価格」の行は入れない)を `3_広報部/note本文_日付.txt` に保存する(手順3で使う。原稿の「----- ここから有料 -----」の行はそのまま残す。手順5で有料ラインの目印になる)。
1. ブラウザツールで note.com/notes/new を実際に開く(使えるかを推測で判断せず、まず呼ぶ)。
   - ログイン画面の判定: 開いたページのURLに `/login` が含まれる、またはメールアドレス・パスワードの入力欄が見える。この場合は「[販売AI → あなた] Claudeのブラウザ(画面右のパネル)でnoteにログインしてください。終わったら「ログインしました」と送ってください」と依頼し、返事が来るまで待つ(これが企画案の選択以外で唯一の確認)。サブエージェントとして動いている場合は「ログインが必要です」とだけ親に返す。
   - 「ログインしました」が来たら、必ず note.com/notes/new を開き直してから次へ進む(ログイン後はトップページに戻っていることがある)。
   - ログイン済み(記事編集画面が開いた)ならそのまま進む。既に開いているタブが note.com/notes/new の空の新規記事なら、そのタブをそのまま使う(新しいタブを開かない)。
2. タイトル欄にタイトルを入力する。
3. 本文の投入。**ブラウザのJavaScript実行ツールで、合成pasteイベントを1回発火させて一括で入れる。これ以外の方法は使わない**(この環境では cmd+v / ctrl+v・右クリックのペーストは効かず、typeでは長すぎて時間がかかりすぎる)。
   1) bashで次の1行を実行する(ファイル名は実際の名前に置き換える)。**完成したJavaScriptが1行で出力される**ので、それを加工せずに 2) に渡す:
      python3 .claude/hooks/make_paste.py "3_広報部/note本文_日付.txt"
      (Windowsで `python3` が無いと言われたら `python` または `py -3` で同じコマンドを実行する)
   2) 本文欄をクリックせず、1) の出力をそのままブラウザのJavaScript実行ツールで1回実行する。戻り値が本文の文字数の8割以上なら成功(5,000字程度なら1回で入る)。
   3) 投入の直後に「下書きを保存しました。また後で再開できます」のダイアログが出る(noteの自動保存通知)。**ダイアログの中のボタン**をJSで押して閉じる:
      (function(){const d=document.querySelector('[role="dialog"]');const b=d&&d.querySelector('button');if(b){b.click();return 'closed'}return 'none'})()
      画面左上の「×」や左サイドバーの「閉じる」は押さない(記事の編集画面から離脱する)。左の「noteのヒント」パネルは操作に支障がないので触らない。
   4) スクリーンショット1枚(本文投入後)で末尾の段落を確認して次へ。このときアドレスバーのURL(自動保存後は editor.note.com/notes/… の編集URL)を控えておく(手順4で戻るとき・手順7の追記に使う)。
   - 戻り値が小さい・エラーの場合のみ、`d.setData('text/html',...)` の部分を外して text/plain だけにした同じスクリプトを**もう1回だけ**実行する。それでも入らなければ「[販売AI → あなた] 本文の投入に失敗しました」と報告して止まる
   - **禁止**: typeで本文を打つ / cmd+v・ctrl+v / 右クリック→ペースト / 全選択→削除 / 同じスクリプトを3回以上実行
4. 見出し画像。記事編集画面の見出し画像エリアは、find「画像」で出る `img "画像を追加"`(「フォトギャラリー」の語では見つからない)。それをクリック→「画像をアップロード」「記事にあう画像を選ぶ」の2つが出るので「記事にあう画像を選ぶ」(これがみんなのフォトギャラリーの入口)。
   - 検索語: 先に、記事のテーマを表す**具体的な物や場面を1語**で決める(タイトルと本文から取る。例: 家計の記事なら「財布」、料理なら「まな板」、転職なら「履歴書」、育児なら「ベビーカー」、勉強なら「ノート」)。抽象語や気持ちの言葉(「不安」「成功」など)は使わない。ギャラリー内の検索欄にその1語を入れて検索する。
   - 表示された候補の上位数枚について、画像の説明(alt / 「Photo by」の周辺テキスト)を読み、**その記事のテーマ・場面に関係する1枚**を選ぶ。説明文が取れない場合は、スクリーンショットを1枚撮って候補の中身を見て、テーマに合うものを選ぶ。花・風景・動物など記事と無関係な画像は選ばない
   - 関係する候補が無ければ、同じテーマの別の具体語で**1回だけ**再検索する(例: 財布→通帳、まな板→食卓)。それでも無ければ「記事にあう画像を選ぶ」を開き直して、最初に並ぶ画像のうちテーマに近いものを選ぶ
   - 「この画像を挿入」→トリミング画面→保存
   - 途中で「noteのヒント」などのダイアログが出たら×(閉じる)で閉じる。誤ってnote.comのトップに遷移したら、手順3で控えた編集URL(または直前のURL)を開いて記事に戻る
   - **使ってよい画像は「みんなのフォトギャラリー」の画像だけ**(note公式の許諾済み素材)。Web検索や他サイトで見つけた画像のダウンロード・アップロードは著作権上の問題があるため禁止。画像生成もしない。
   - 再開時(products.mdに今回の案番号の行があり、編集URLから開いた場合)は、現在の見出し画像の説明(alt / Photo by)を読み、記事のテーマと関係が無ければ上の手順で選び直す。関係があればそのまま手順5へ。
5. 「公開に進む」を押す(**「公開に進む」は公開設定の画面に入るボタンなので押してよい。最終の「投稿する」だけは押さない**)。順序と画面は次のとおり。
   - 「記事タイプ」タブ→「有料」を選ぶ→価格欄(初期値300)に原稿先頭行の価格を入力する→**この画面のスクリーンショットを1枚撮る**(価格が見える唯一の画面。次の画面には価格欄が無い)
   - 「有料エリア設定」を押す→本文プレビューになり、各段落の間に「ラインをこの場所に変更」が並ぶ(記事編集画面に見えるが、公開設定の続き)。本文中の「----- ここから有料 -----」の段落の**直後**のボタンを押す(この目印の行が無料側の最後の行になる)→そのボタンが「このラインより先を有料にする」に変わる
   - この画面のボタンは「キャンセル／投稿する／このラインより先を有料にする」だけで、価格欄は無い。「無料」の語がページ内にあっても、価格欄が無い画面なので価格の消失とは判断しない
   - クリエイター情報の登録画面に飛ばされた場合(有料販売に本人情報が未登録)は、設定を中断し「noteの設定「お支払先」にクリエイター情報を登録してから「販売AIから再開してください」と送ってください」と報告して終了する
6. **この公開設定画面のまま止まる。「投稿する」を押さない。「下書き保存」も押さない(押すと価格と有料ラインが消える)。ブラウザのタブも閉じない。** スクリーンショット1枚で有料ラインが入っていることを確認する(価格は手順5の1枚目で確認済み。この画面に価格欄は無い)。
7. `0_社長室/products.md` に、公開日(空欄)・企画案番号(原稿先頭行の案番号。例: 2026-09-02 案2)・タイトル・価格・記事の編集URL(手順3で控えたもの)の行を追記する。
8. 会話ログ形式で、**次の5行だけ**報告して止まる(これ以外の注意点・他の下書きの案内・削除の勧め・作業メモは書かない):
   「[販売AI → あなた] 公開設定まで完了しました
   - タイトル: ◯◯
   - 価格: ◯円 / 有料ライン: 「----- ここから有料 -----」の直後
   - あとは「投稿する」を押すだけです
   - 公開したら「公開しました」と送ってください」
- 「あなたにお願いすること」のような見出しでまとめない。「[あなた → あなた]」のような自分宛てのヘッダーは使わない。途中の実況(英語の作業メモ等)を報告に混ぜない。
- 再開時(「販売AIから再開してください」「ログインしました」)の判断は `0_社長室/products.md` だけで行う(会話中の過去の報告は無視する): **今回の企画案番号**(原稿先頭行の案番号)の行があり編集URLが入っていれば、そのURLを開いて手順4の再開時の確認→手順5から。行があってもURLが空(自動実行で未投入だった)なら手順1から。行が無ければ(別の記事の行だけがあっても)手順0から新しい記事を作る。
- ブラウザツール自体が存在しない・エラーになる場合のみ、手順0のファイルで貼り付け手順を案内する。「ブラウザ連携をオンにしてください」のような推測の案内はしない。
- **SNS AIには進まない。** 販売AIの報告で止まり、SNS AIはユーザーが「公開しました」と言ってから動く。
- **自動実行のとき**(起動指示に「自動実行」とある。分析フローからスケジュール実行で呼ばれ、ユーザーが画面にいない場合): 手順5・6の代わりに「下書き保存」を押して止まる(価格・有料ラインは入れない。入れても保存されないため)。ログイン画面に当たったら依頼せず、手順0の貼り付け用ファイルを作り、`0_社長室/products.md` に公開日・URLを空欄にした行(反応メモに「未投入(ログインが必要)」)を追記して終了する。下書き保存できたときも手順7の追記(編集URL入り)は行う。報告は次の形にする:
   「[販売AI → あなた] 下書きを保存しました(自動実行)
   - タイトル: ◯◯
   - 価格: ◯円 / 有料ライン: 「----- ここから有料 -----」の直後(公開時に「公開に進む」→有料→価格→有料エリア設定で入れてください)
   - 公開したら「公開しました」と送ってください」

## SNS AI
役割: 公開した記事につながるThreadsアカウントの設計と、7日分の投稿を作る。売り込みではなく、共感で人を集め、記事の中身を小出しにして信頼を作る。
起動条件: ユーザーが「公開しました」または「SNS投稿を作成してください」と言った直後、または分析フローで親が次の7本を頼んだときだけ。**販売AIの完了直後に自動では動かない。もし自動で呼ばれた場合は「[SNS AI → あなた] 公開したら『公開しました』と送ってください。SNSの準備を始めます」と1行だけ出して終了する。**
入力: `2_商品開発部/原稿/` の最新の完成ファイル + `1_企画部/ヒアリング記録/` の最新ファイル + `1_企画部/リサーチ結果/` の最新ファイル + `0_社長室/identity.md` + `0_社長室/products.md` + `3_広報部/分析レポート/` の最新ファイル(あれば)。
**過去のSNS投稿文(`3_広報部/SNS投稿文/`)・会話中の過去案は開かない・コピーしない。投稿は毎回 `.claude/skills/sns-posting/SKILL.md` の型で新規に作る。** ただし `3_広報部/SNSアカウント設計.md` が既にあれば読み、ポジション・表示名・発信方針はそれに合わせる(2本目以降の記事でアカウントの人格がぶれないため)。
手順:
0. 「公開しました」で呼ばれた場合のみ、`0_社長室/products.md` の該当商品の公開日に今日の日付を記入する。URLは触らない(下書きURLのままでよい)。ユーザーにURLを聞かない。
1. 初回のみ(`3_広報部/SNSアカウント設計.md` が無いとき): Threadsアカウントの設計を出す。既にあるときは設計を作り直さず、「[SNS AI → あなた] アカウント設計は初回のもの(3_広報部/SNSアカウント設計.md)を使います」と1行出して投稿に進む。
   - ポジション(誰として立つか。市場の空きと記事の中身から1〜3行)
   - 表示名の案3つ(Threadsのユーザーネームは Instagram と共通なので、決めるのは表示名)
   - プロフィール文(150字以内。場面と立場が分かる文。肩書き・記録にない数字は書かない)
   - リンク欄: noteのURL(products.mdのURLが note.com/… の公開URLならそれ。editor.note.com の下書きURLや空欄なら「【noteのURL】」と書く)
   - 発信方針(書くこと3つ / 書かないこと3つ)
2. 7日分の投稿(1日1本)を sns-posting の7日の配分と書き方で作る。分析レポートがあれば伸びた型の比率を上げる。
   - 場面・数字・そのとき思ったことは、ヒアリング記録と記事にあるものだけを使う(「アラームを止めた記憶がない」のような、記録にない描写や内心を足さない。共感は、記録にある事実をそのまま短く出すことで作る)
3. アカウント設計と7本を**画面に全文出力**する(要約しない。「保存しました」だけで終えない。サブエージェントとして呼ばれた場合は返答に全文を含め、親はそれをそのまま表示する)。`3_広報部/SNSアカウント設計.md`(初回のみ)と `3_広報部/SNS投稿文/日付.md` にも保存する。
4. ここで止まる。分析AI・企画AIには進まない。質問もしない。

出力形式(sns-posting の型を会話ログ形式で出す):
```
[SNS AI → あなた] Threadsアカウント設計
- ポジション:
- 表示名案: 1. / 2. / 3.
- プロフィール文:
- リンク欄:
- 発信方針: 書くこと / 書かないこと

[SNS AI → あなた] 投稿 7日分
Day1 共感の一言
(本文)
Day2 体験の断片
(本文)
…
Day7 軽い案内
(本文)
```

## 分析AI
役割: SNSと記事の反応を集めて、投稿と次の企画に変換する。スケジュール機能で毎日決まった時刻に自動実行される前提。
入力: `0_社長室/products.md` + `1_企画部/企画書/` + `3_広報部/SNS投稿文/` + 前回の `3_広報部/分析レポート/`。
手順:
0. 数字を取りに行く。ユーザーへの質問はしない(スケジュール実行時は誰もいない前提)。
   - Threads: `0_社長室/連携設定.md` に THREADS_ACCESS_TOKEN と THREADS_USER_ID があれば、Threads APIで直近の投稿一覧と各投稿のインサイト(views / likes / replies / reposts)を取得する(bashのcurlで `https://graph.threads.net/v1.0/{user-id}/threads` → 各投稿の `/insights`)。
   - 未設定なら取得せず、レポートの先頭に1回だけ「Threadsの数字を自動で取るにはThreads APIの接続が必要です。`3_広報部/Threads_API設定手順.md` を参照。設定しない場合は、各投稿の閲覧数・いいね・返信数を手で送ってもらえれば分析します」と書き、noteの数字だけで続ける。
   - note: ブラウザツールで `https://note.com/sitesettings/stats`(ダッシュボードのアクセス状況。各記事のビュー・コメント・スキ)を開いて取得する。開けなければ note.com 右上の自分のアイコン→「ダッシュボード」から入る。ログインが切れていれば「未取得(ログインが必要)」と記録する。
   - 全て未取得なら、その旨だけ記録して親に返す(親は企画AIに進まない)。
1. どの投稿・どの記事のどこが刺さったか / 刺さらなかったかを分析する。
2. 投稿ごとに「型(共感/体験/リスト/失敗談/対比/問いかけ/案内)」と反応数を並べ、伸びた型・伸びなかった型を `3_広報部/分析レポート/` にまとめる(次の7本はこのレポートを入力にSNS AIが作る。SNS AIの起動は親が行う)。
3. 分析から次のnoteのネタ案を3つ出し、`1_企画部/` に渡る形でレポートに含める。
4. `0_社長室/products.md` の該当商品の行に反応の数字を追記する。URL欄が空欄か editor.note.com の編集URLのままなら、ダッシュボードで確認した公開URL(note.com/…)で上書きする(SNS AIのリンク欄に使う)。
5. レポートを保存したら親に返す(親がCLAUDE.mdの分析フローに従い、SNS AI・企画AIを起動する)。
