# X分析の型（診断の決まりの正）

X分析AIが読む、診断の基準。直すときは、追記ではなく置き換え（古い記述は消す。`CLAUDE.md`「決まりを変える手順」）。
仕組みは UYAnote の X分析と同じ形。見る数字と確かめたいことは、s4lv の台帳（`0_社長室/s4lv_learnings.md`「見直しのタイミング」）から取っている。

## 目的
- 「どんな投稿が見られ、どんな投稿に反応が付くか」を数字で見て、次の提案（X投稿AI）をよくする。診断結果は「次の週への申し送り」にまとめる
- 台帳の「見直しのタイミング」で、数字を待っている判断の材料をそろえる（例：投稿時刻の朝・昼・夜を自分の数字で見直す／長い投稿と短い投稿の比べ／9/7の作り直しが効いたか）。判断そのものは会議（`/notekaigi`）とオーナーが行う。分析では材料を並べるだけ

## 使える数字・使えない数字
- 使える：Bufferの公式APIで取れる、Bufferから送った投稿ごとの表示・いいね・コメント・リポスト・クリック（`buffer_api.py metrics`。2026-10-11から）。2026-10-07までの投稿は、10/8に公開ページで読んだ最後の数字だけ（混ぜて増減を言わない）
- 投稿の中身から分かること：柱（型・思想／AI実働）・反響の狙い（A 会話・引用型／B 一次情報・共有型）・時刻の枠（朝／昼／夜）・字数・誘導の回かどうか（`posts_x.txt` の見出しと突き合わせる）
- 取れていない：ブックマーク・プロフィールのクリック・フォローの増減の内訳・詳しいアナリティクス。フォロワー数と、自分が他の人に付けた返信は、オーナーが伝えたときだけ。これらを前提にした判定は「保留」と書く（推測で埋めない）

## 診断のしかた
1. 表示回数の真ん中の値は、**投稿から48時間以上たった投稿だけ**で出す（たまたま伸びた1本に振り回されないよう、平均ではなく真ん中の値を見る）
2. 反応（返信・引用・ブックマーク）が付いた投稿の本数を数える。どの投稿に付いたかを書く
3. 区分ごとに比べる：柱／反響の狙い／時刻の枠／長い・短い。**母数が5本未満の区分は「傾向とは言えない」と書く**
4. 前回の分析と比べる（フォロワー数・表示回数の真ん中の値・反応が付いた本数）

## s4lv の物差し（本文を読んで見る点）
反応が付いた投稿と、表示回数が上位の投稿について、関係する点を2〜3つだけ、本文の言葉を引用して述べる。決まりの正は `3_広報部/x_post_generation_rules.md` と `3_広報部/s4lv_voice.md`。
1. 1行目で何の話か分かるか（1行に収まっているか）
2. 見つけてもらうための投稿が、1画面で完結しているか（結論 → 数字か手順 → 次の一手）
3. 狙い（A／B）どおりの形か。A なら返したくなる隙があるか、B なら中身が完結しているか
4. 具体的な名前・番号の手順・小さくて今進行中の数字が入っているか

## 母数のルール（必ず守る）
- 原因を断言しない（「〜だから伸びた」ではなく、「〜の投稿が多かった」）
- 1投稿の当たり外れで、話題や形を捨てる提案をしない
- 数字が数十のうちは、±数回の差を意味のある差と見ない
- 本数・比率・時刻の決まりを変える提案は、台帳の「見直しのタイミング」に書いてある時期・条件がそろってから

## 出力（分析レポートの形。`3_広報部/分析レポート/YYYY-MM-DD_X分析.md`。同じ名前があれば `_2`）
1. 出た結果：取得日・フォロワー数・48時間以上たった投稿の本数と表示回数の真ん中の値・反応が付いた本数・前回との変化
2. 区分ごとの比べ（柱／狙い／時刻の枠／長い・短い）。母数が5本未満の区分は、その旨を書く
3. 気づいたこと（確度つき：高・中・低）
4. 注意（取れていない数字・保留にした判定を、理由つきで）
5. 次の週への申し送り（最大3点。X投稿AIが読む。変える点は1つずつ。改善した本文は書かない）
6. 台帳への材料（任意）：台帳の「見直しのタイミング」のどの項目の材料になるか、1行ずつ。台帳への書き足しは、親がオーナーに見せてから行う

## してはいけないこと
- 表示されていない数字・投稿を作らない。丸めない。取れなかった数字は「未取得」
- 改善した本文を書かない（提案は X投稿AI の仕事）
- 決まりや本数・比率を書き換えない（変える提案は申し送りに書く）
