# 投稿の見本（X・スレッズ共通）

## 使い方
- 投稿AIは、決まりのファイルより先に、これを全部読む。声（語尾の丁寧さ）・読点の少なさ・締め方を、ここに寄せる
- 寄せるのは書きぶりだけ。中身・ネタ・文は写さない
- 「直した前後」の「前」は、AIが書きがちな形。「後」が、オーナーの形
- 改行のしかたは `s4lv_voice.md`「書き方の形」が正（句点ごとに改行）。古い見本で1行に2文あるものも、改行は今の決まりに合わせる
- ツリー（続き型）の見本は、まだない。オーナーが通したら、最初の1本を足す
- 新しいものほど優先する。見本どうしや、見本と決まりが食い違ったら、いちばん新しい見本に合わせ、古いほうの見本は外す（決まりの文は「決まりを変える手順」で直す）

## 増やし方
- 提案を直したとき、またはオーナーが直して出したとき（「Xに出しました」「スレッズに出しました」）は、直し記録に1行足すのと一緒に、前後を1組「直した前後」の節の**いちばん上**に足す（言い回し・語尾・読点・締めの直しのとき。事実の訂正は台帳へ）
- オーナーがそのまま通した投稿で、ここにない形のものは、「そのまま通した投稿」に足してよい
- 全部で15本まで。超えたら、同じ種類が重なっている古いものから外す
- 決まりの文を変えるのは、同じ種類の直しが2回出たとき（`CLAUDE.md`「決まりを変える手順」）

## そのまま通した投稿

### 4. 手順型＋人間らしい本音の締め（X 10/2夜・オーナー書き直し版）
```
機械のチェックを全部通っても、AIっぽさは残る。
だから私は、AIっぽさを3段階で減らしています。

 1. 機械のチェックで、言い回しのかぶりと語尾を拾う
 2. 別のAIに、文の組み立てがAIっぽくないか採点させる
 3. 最後は自分で読み返して、話し言葉っぽく整える

AIはだいぶ人間らしく書けるようになったけど、自分の意図した言葉まではまだ出してくれない。

結局まだ自分の手で直すことになるんですよね。
```

### 5. 機能紹介型（X 10/2朝・オーナー書き直し版）
```
Claude Codeの「ルーティン」使ってますか？
決めた時間に、パソコンを閉じていても作業を回してくれる機能。

ブログ運営なら、こんな使い方ができる。
・古くなった記事を、週1回洗い出してもらう
・下書きを、決まったチェックリストで見てもらう

こういう見回りを、決まった時間に自動で回せる。
ただ、承認を聞かずに動くから任せる作業は絞ったほうがいいので注意。
```

### 6. 外の話題に、自分の見方を足す（X 9/24夜・オーナー確定）
```
AIで書いた記事は順位が下がるってよく言われるけど、Googleの公式の説明はちょっと違うんですよね。

AIで作ったこと自体は問題にしてない。
問題にしてるのは、役に立たないページを大量に作ること。

これはAI以前からある話。
私も昔、中身が薄いまま更新をたくさんし、サイト全体の評価を落とした時期があります。

だからAIかどうかより、中身が役に立つかどうか。

今は下書きをAIに作ってもらってます。
公開する前には必ず目を通して修正してます。
```

### 7. よく聞く主張に、条件をつけて返す（X 10/16朝・オーナー確定）
```
記事を出す回数を増やしたくて質を下げたことがある。
結果はサイト全体の評価まで落ちた。

「数を打つのが大事」とはよく聞くけど、私は条件つきだと思ってる。
1回ずつの質を落とさずに増やせるなら数は多いほうがいい。
落ちるなら増やさないほうがいい。

雑に10本出すより、狙った1本のほうが伸びている。
いまは回数で補うのはやめています。
```

### 8. 判断の基準を番号で見せる（X 10/16夜・オーナー確定）
```
狙うキーワードは、語数で扱いを変えています。

 1. 1語は個人ではまず無理なので狙わない
 2. 2語は競合が弱ければ普通に狙う
 3. 3語や4語の言葉はここが主戦場

2語に大手や公式やAIの回答が居座ることがある。
そのときは細かい言葉にずらせるかを見る。
ずらせるなら1回だけ直す。
ずらせないならすぐやめる。

昔はどうにか上位に出せるだろうと、無駄に時間をかけてた。
```

### 9. 自分のやり方を短いリストで（X 9/25昼・オーナー確定）
```
記事の一番上には、その記事の今の状態が分かる枠を基本的に置いてます。

行数は決めてなくて、3行分くらいの内容。
・今の状態（いまどの段階か）
・核心を1行で（結論だけ先に）
・最終更新日

記事を開いた瞬間にここを見れば、今どうなってるか分かる状態にすることで離脱されにくくしています。
```

### 10. 数字の言葉をふだんの言葉で説明する（X 10/2昼・オーナー確定）
```
最近私はnoteのアクセスについて、ページビューより先にインプレッションを見るようにしてます。

インプレッションは、noteの中で記事が表示された数。
ページビューは記事が開かれた数で、noteの外から来た人も入る。

外から来る人が多い記事は、インプレッションに対するページビューの割合が大きく見えるんですよね。
割合が高くても、記事が多くの人に届いているとは限らない。

自分の記事でも、割合が高い記事とインプレッションが多い記事は別でした。
```

### 12. 迷っていたことと、いまの線引き（スレッズ 9/9昼・スレッズで返信が付いた投稿）
```
ブログの記事づくりで、一部をAIに任せています。
ただ、どこまで任せるかで毎回迷って、結局自分でやってしまう時期がありました。

今は基準を1つに決めています。
機械のチェックで合否が出せる仕事はAIに渡す。
出せない判断は自分に残す。
戦略や設計、例外の処理はこっち側です。

この線引きにしてから、渡すときも受け取るときも迷わなくなりました。
```
