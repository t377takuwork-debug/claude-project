# Threads投稿の決まり（s4lv / @cfrms4lv）

**声と書き方は `3_広報部/s4lv_voice.md`、材料と事実は `3_広報部/sns_common_rules.md`。** このファイルは、Threadsだけの決まりを書く。広め方の仕組みの資料は `../brands/reference/threads_algorithm_2026.md`。

## 反響の狙い

- Threadsは、会話がどれだけ速く・深く続くかで広まる。閲覧のかなりの部分が、返信の画面から生まれる。重く数えられる順は 返信 ＞ リポスト ＞ いいね
- 投稿してから30分〜1時間の反応が、そのあとの広がりを決める
- 目的は「正しい解説」ではなく、タイムラインで止まり、続きが読まれ、返信が付く投稿を出すこと。ブログ教材の書き手ではなく、Threadsの編集者として書く
- 立ち位置：エンタメ特化ブログを個人で10年。記事設計・直し方・AI下書きの現場を書く。フォロワーはごく少なく、見つけてもらう道はおすすめ頼み。売るのは今の仕事ではない
- 話題は2本柱（型・思想／AI実働）の範囲で一貫させる
- 手間のいらない反応を求める文は使わない：「フォローして」「1ならリンク」「同じ人はいいね」「詳しくはnote」。中身に結びついた「保存しておいてください」は使ってよい
- このアカウントで重いのは、読者が**マネできる・自分に落とし込める要素**があること。考え方の説明だけで終えない。本文に、そのままマネできる具体（やり方・基準・順番）を1つ入れる。自分のやっていることの紹介が中心にならないようにする（「私は〜しています」は1行まで）
- 画像は使わないので、手順・設定の話は、文章だけで形が浮かぶように書く。操作の順番を並べるだけにせず、できあがりの中身（ファイルの文面・画面に出る言葉・前と後の例）を、そのまま1つ見せる
- 初心者・中級者でも分かる言葉で書く。ツール名（Claude Code など）は、そのまま書き、説明の括弧は付けない。ブログやSNSをやっている人にも通じにくい専門語だけ、言いかえるか、ごく短い一言を添える（例：内部リンク（同じサイト内の別の記事へのリンク））
- すでに発信した内容を繰り返さない。確かめ方は `sns_common_rules.md`「ネタを選ぶ順番」の1
- 外の話題（機能の更新・数字・他社の動き）を書くときは、公式のページで事実を確かめ、確認できた範囲だけを自分の言葉で書く。確認できない細部は書かない。**誰かの発信を基にしていることは、本文に書かない**（「〜という投稿を見かけました」「〜と言う人がいます」は使わない）。参考にした投稿と、言い回し・構成・例を重ねない

評価の順番

1. 何の話かが2文以内で分かる
2. 1行目で読み進めたくなる
3. AIっぽさがなく、人が話している声
4. 型を固めすぎない（決まった形が見えたら崩す）

正しさや網羅は、この4つのあと。実績アピールもあと。

## Threadsだけの決まり

| 項目 | 決まり |
|---|---|
| 長さ | 150〜300字。短い形（問い・一言）は80字から。上限は500字（超えると投稿に失敗する） |
| 本数・枠 | 正は `0_社長室/S4LV設定/project_s4lv_operation_system.md`「投稿量」。3本出す日は、役割を分ける（現場メモ・知見・失敗談） |
| 自己リプライ | 付けるのは、手順・やり方・チェック項目など、本文に収まらない中身がある投稿。意見・一言・問いの投稿は、付けなくてよい。付けるときのつなぎ方は、下の「自己リプライ」 |
| URL | フォロワー100までは、本文にも自己リプライにも入れない（機械チェックが止める）。noteはプロフィール欄だけ |
| 箇条書き | 1回に作る中の半分は、箇条書きを使わない文章の形にする |

## 1行目（Threadsで足すこと）

- 自分の現場か、具体的な事実から入る形を基本にする
- 職歴で始めない
- 1行目で答えを言い切らない。何の話かは見せて、結論は伏せる

## 役割の使い分け

- 1本ごとに役割を決めてから書く
  - **失敗談**：現場の失敗 → 今どうしている → 問い（付けるなら）
  - **知見**：結論 → 理由 → 言い切って閉じる
  - **現場メモ**：今日の詰まりか消えた作業 → 短く現状 → 自己リプライに中身
  - **例外山**：本文を単純にして、自己リプライで「ただし」を1つ
- 同じ骨格を3本続けない。「今は〜しています → ・を3つ → だからこう」の連打をしない。本文の最後で同じ結論を2回言わない
- 1投稿のメッセージは1つ。関連する話は、自己リプライか別の投稿に回す
- 見出しは `【9/27 21:30】型・思想／K5 …／失敗談` の形に、`／形：○○／入り方：○○／終わり：○○` を足す（ツリーのときは `／続き型` も）。**トピックは付けない**（`queue_from_posts.py` は「トピック：」が無ければ、トピックなしで入れる）

## 問い（返しやすい問いにする）

- ○ 今の習慣・やり方をそのまま聞く（経験ですぐ答えられる）。昨日やったことの報告で返せる
- × 今すぐ何かを調べないと答えられない問い
- × 失敗を思い出させる前提つきの問い（「〜して上がらなかったことありません？」）
- × 経験を思い出させる「〜したことはありませんか？」「〜したことってありませんか？」（機械チェックが知らせる）。問いを置くなら、いまのやり方をそのまま聞く形（「〜は何を見て決めていますか？」「〜はどうしていますか？」）にする

## 自己リプライ（2つ目の山）

- 80〜200字。**読んだ人が、自分の作業にそのまま移せるもの**を置く（ブックマークしたくなる中身）。次のどれか1つ
  - **手順**（番号つきで、順番どおりに）
  - **判断の基準**（「こうなら書く、こうなら見送る」）
  - **チェック項目**
  - **言い換えの例**（前と後）
  - **自分に当てはめて埋める1問**
- 中身は、台帳の事実か、集めたネタについての考え・公式で確かめた情報。体験として書くのは、台帳・ジャーナルの記録の範囲だけ。台帳にない数字・効果は作らない
- 例外（「ただしこの場合は当てはまらない」）や自分の抜けは、持ち帰れる中身を置いたあとに、短く添える。例外だけの自己リプライにしない
- 本文の結論を言い直さない。売らない。リンクを置かない
- AI実働の自己リプライを、毎回「エラーも出ず動かない」型にしない
- **ツリーにするときは、本文の文を終わらせずに自己リプライへつなぐ（続き型）。** 本文の最後は読点（、）で切り、自己リプライの1文目がそのまま受けて文を完成させる。切る所は、読んだ人が「それで？」「どうなる？」と思う手前（答え・やり方・理由の直前）。つなぎの言い回しは毎回変える（同じ言い回しが2本以上あると機械チェックが知らせる）。見出しに「／続き型」と書く
- 「続きはリプ欄で」「（続く）」のような予告は書かない（機械チェックが止める）。文の切れ目そのもので続きを読ませる
- 中身の薄い但し書きを、自己リプライを付けるためだけに足さない
- 中身が多いときは、最大4本までつなげてよい。最後の1本以外は、同じように文を終わらせずに次へつなぐ。何本かのときは「自己リプライ1（〜）：」「自己リプライ2（〜）：」と分けて書く（予約の道具は、この見出しで分けて読む。空行では分けない）
- Xでも、このつなぎ方を使う

## 出力形式

`3_広報部/投稿文/posts_threads.txt` の末尾に、次の形で足す（予約の道具と機械チェックは、この形で読む）。
```
【10/20 08:00】型・思想／元ネタ＝候補のURL（合う候補がない日は 台帳K◯・A◯／ジャーナル M/D）／失敗談／形：散文／入り方：事実／終わり：断言
--------------------------------
本文
--------------------------------
自己リプライ（2つ目の山）：自己リプライの本文
```
- 見出しの並びは「日時／柱／元ネタ／役割／形・入り方・終わり」（上の「役割の使い分け」）。ツリーのときは `／続き型` を足す。トピックは付けない
- 自己リプライを何本かつなぐときは、「自己リプライ1（〜）：」「自己リプライ2（〜）：」で分ける
- 何案か出すときは、役割が同じものを続けない

### リサーチの候補を元ネタにするとき
スレッズでも、元ネタは原則として集めたネタから選ぶ（選ぶ順番の正は `sns_common_rules.md`「ネタを選ぶ順番」）。借り方（型は必ず借りる／借りてよいもの・借りないもの／類似チェック）の正は `x_post_generation_rules.md`「リサーチ候補の使い方」。スレッズでは次の形にする。
- 見出しの元ネタは、候補のURL（`元ネタ＝https://…／材料＝台帳 K◯・ジャーナル M/D`）
- 見出しと、本文の始まりの線の間に、「借りる型」「伸びた理由と再現」「借りない点」「元ネタの核／自分の核」の4行を書く（機械チェックは、この間の行を読まない）
- 体験を足すなら、台帳・ジャーナルの記録の範囲だけ。XとThreadsで、同じ元ネタ・同じ角度を使い回さない
- 元ネタの出どころは、設計の表にだけ書く。**本文には書かない**（上の「反響の狙い」）
