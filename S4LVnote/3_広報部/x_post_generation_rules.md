# X投稿の決まり（s4lv / @cfrms4lv）

声と書き方は、`3_広報部/s4lv_voice.md` のうち **「使わない言い方」「書き方の形（読点・改行・記号）」「ばらつきの決まり」** だけを使う。それ以外の声の細かい決まり（語尾の表・主語・1行目の入り方・見本・提案前の自己チェック）は、Xでは使わない。基本の声は、肩の力が抜けた、あたたかい話し言葉。

## 守ること

1. 実際にあったこと・やったこと・数字として書く部分は、作らない。台帳の事実・ジャーナル・オーナーが確かめたことだけを使う
   - 意見・気づき・考え・一般論・外の話題への見方は、体験の裏づけがなくてよい。意見の裏づけに体験を書いてよいのは、台帳・ジャーナルに記録がある体験だけ。記録にない体験は足さない
   - 確かめていない情報を、確定した実績として言い切らない
   - 台帳の「事実」欄の細かさや言いかえ欄に合わせる必要はない。自分の言葉で書いてよい。オーナーが訂正した内容だけは、訂正どおりにする
2. 開示：番組名・タイムテーブルなど定期更新の記事だと分かる言葉・ブログ名・URLは出さない（正は `0_社長室/S4LV設定/personal_data.md`「開示ルール」）
3. noteの規約：性的な描写・言い切った統計・特定の人を傷つける書き方をしない
4. ふだんの言葉で書く。通報・ミュート・興味なしを誘う煽りは書かない
5. 同じテーマ・同じ角度を、直近の投稿（XとThreads）と重ねない
6. リポストのお願いや、キャンペーン型の投稿はしない

## 伸びる投稿の条件（公式の値から導いた分析）

値の正は `../brands/reference/x_algorithm_2026.md`。ここには、値から導いた「どんな投稿が伸びるか」だけを書く。
**この節は、Xの決まりの中でいちばん重く扱う。** 公式の値が更新されたら、そのたびに、この節と、この節に関わる決まり（反響の狙い・中身の種類・厳禁・審査の見方）を見直す（手順は `CLAUDE.md` の「Xアルゴリズムの更新」）。

### 値から言えること
| 公式の値 | 投稿づくりでの意味 |
|---|---|
| リンクをコピーして共有 20（いいねの約40倍）・DMで共有 5 | 人に送りたくなる、それだけで完結した中身がいちばん強い |
| 返信 5（相互フォローなら＋15）・引用 5 | 返したくなる隙（反論できる断言・予測・抜けている事実）がある投稿が次に強い |
| 開いたあとの滞在時間 0.4（予測した時間に掛かる）・投稿を開く 0.3 | 開かせるだけでは弱い。開いたあとに読み続けてもらえる中身が要る |
| 止まらず通過 −0.02 | 1行目で何の話か分からないと、軽いマイナス |
| 通報 −234・ミュート −58.8・興味なし −47.52 | 期待を裏切る投稿・煽りは、プラスを打ち消す |
| 同じ作者の2本目以降 ×0.625・3本目 ×0.44 | 薄い3本より、中身のある1本 |

**最重要：クリックさせることではなく、クリックしたあとに満足してもらえるか。**

### 反響の狙い（書く前に1つ決める）
| 狙い | 狙う行動 | 必ず入れる中身 |
|---|---|---|
| B 共有型 | コピー共有・DM共有 | 下の「中身の種類」のどれか1つを、それだけで使える形で入れる。「保存してください」とは言わず、中身が完結していることで閉じる |
| A 会話型 | 返信・引用 | 反論できる断言・予測・抜けている事実の指摘のどれか1つ。そのうえで、自分の理由を本文に書く |

- 比率（A・Bの割合）は決めない。1つの投稿に両方を混ぜない
- 狙うのは「フォローしていない人が返信・引用・共有したくなること」。いまのフォロワーとの会話だけを狙わない

### 中身の種類（B 共有型）
1. 保存して後で見返したいチェックリスト
2. 他の人にも教えたい最新情報（公式や元の情報で確かめたもの）
3. 自分で調べるのが大変なデータ（自分の数字は台帳の範囲だけ）
4. 具体例までまとまった解説

### 厳禁：1行目で煽り、中身が薄い投稿
- 「これはヤバすぎる」「知らないと損」などで期待だけ上げて、本文の答えがほとんどない投稿は書かない（開いたあとの滞在時間と、興味なしの予測を悪くする）
- 1行目で約束したこと（何が分かるか）に、本文で必ず答える。答えが本文にないなら、1行目を弱める
- 強い言葉を使うなら、本文の中身がそれに見合っているときだけ（機械チェックは、1行目の煽りの言葉を WARN で知らせる）

## リサーチ候補の使い方（2026-10-15〜）

ネタ・テーマは、リサーチの候補（`../research/data/shortlist/shortlist_s4lv_UYA_<日付>.md` の最新。上位の保存で選んだ行）から決める。台帳（`x_neta_daicho.md`）とジャーナルは、**合うものがあるときだけ**、中身に足す材料として使う。選ぶ順番の正は `sns_common_rules.md`「ネタを選ぶ順番」。
この節は、スレッズでも同じに使う（スレッズの見出しの形は `threads_post_generation_rules.md` の出力形式）。台帳へ移す手間が要らないこと（元ネタは候補のURLを見出しに書く）は、`sns_common_rules.md`「ネタの出どころ」が正。

| 材料 | 役割 |
|---|---|
| リサーチの候補 | テーマ（話題）と型（なぜ伸びたか）を借りる |
| 台帳・ジャーナル | 合うときだけ足す、自分の事実（なくてよい） |

**型（伸びた理由）は必ず借りる。中身（具体例・数字・結論）は、元の投稿のものを使わず、s4lvとしての考え・やり方で書く。**

### 借りてよいもの・借りないもの
| 借りてよい | 借りない |
|---|---|
| テーマ（話題そのもの） | 文・言い回し・語尾。元の投稿と3文以上、同じ順に並べること |
| 問いの立て方 | 金額・件数・期間・割合などの数字（自分の数字は台帳の範囲だけ） |
| 型（手順・比較・一覧・失敗談の形 など） | 元の投稿の具体例・たとえ・エピソード |
| 伸びた理由の仮説 | 元の投稿の主張を、そのまま言い直すこと |
| | 元の投稿者の名前・口調・絵文字の癖 |

### 書く前に決める4行（見出しの下に書く）
見出し（【…】の行）と、本文の始まりの `----` の間に、次の4行を書く（機械チェックは、この間の行を読まない）。
1. 借りる型：元ネタの形（一覧・手順・比べ方・断言＋理由 など）。**型は必須。テーマだけを借りるのは不可**
2. 伸びた理由と再現：元ネタが保存・共有された理由を1行。今回それをどう再現したかを1行
3. 借りない点：元の数字・具体例・主張のうち、使わないもの
4. 元ネタの核／自分の核：それぞれ1行。自分の核は、**元ネタと同じテーマの中で**、s4lvの見方（2本柱の角度）で作る。同じ主張になるなら、条件・反対の面・自分の事実（あれば）を足して、別の主張にする

自分の事実（台帳・ジャーナル）は、合うものがあるときだけ使う。体験として書くのは、その記録の範囲だけ。一覧の項目などは、考え・一般的なやり方・公式で確かめた情報で埋めてよい（自分がやったこととしては書かない）。

### 参考元が分からない形にする
- 元の主張に、s4lvとしての条件・限界・反対の面を足す。自分の事実を足すなら、台帳・ジャーナルの範囲だけ
- 数字は、元の数字を使わない。自分の数字がなければ、数字を使わない
- 同じ元ネタを、2本の投稿に使わない。同じ日の投稿に、同じ話題を重ねない

### 確かめる（投稿案ができたら、必ず）
1. 類似チェック：`py -3 ../research/export_sources.py <元ネタのURL…>` で元ネタの本文ファイルを作り、出たファイル名で `py -3 ../brands/tools/check_similarity.py <投稿ファイル> --sources <そのファイル>` を実行する。10字以上の連続一致は言い換える。20字以上は書き直す。結果（一致の最長の文字数）を、返答に書く。終わったら、その一時ファイルを消す
2. 「元ネタの核」と「自分の核」が同じ主張でないことを、自分の目で確かめる（機械では見られない）
3. 元ネタのURLは、見出しの「元ネタ」にURLだけ書く（本文は写さない）

## 形

- 本文にURLとハッシュタグを入れない（誘導の回は、自己リプライにURLを書く）
- 手順・やり方・チェック項目など、本文に収まらない中身は、ツリー（自己リプライ。最大4本）にしてよい。つなぎ方の正は `threads_post_generation_rules.md`「自己リプライ」の続き型
- 見出しには、日時・柱・元ネタ（URL）・材料（台帳 K◯・A◯／ジャーナル M/D）・狙い（A／B）・推奨の投稿時刻と、`／形：○○／入り方：○○／終わり：○○`（`s4lv_voice.md`「形の引き出し」の語彙）を書く（材料を見出しに書くと、`recent_forms.py` の「最近使ったネタ」に出る）
- 本数・時刻・柱の比率・投稿後の動きは、`0_社長室/S4LV設定/project_s4lv_operation_system.md`「投稿量」のとおり。いちばん強い1本を夜の枠に置く

## Note記事への誘導の回

- 週1本を目安に、型・思想の投稿のうち1本を誘導の回にする。1日に2本以上は入れない
- ネタ元は `0_社長室/note_article_index.md` の章。「直近X誘導日」が空欄か、いちばん古い記事を選ぶ。使ったら、その欄に日付を書く
- 本文は、章の考え方を見せるだけにする。売り込みの一文は入れない。有料記事は、考え方を見せるところまで（キーワードの選び方の決まりや、記事構成の型を、そのまま文章で渡さない）
- URLは本文に入れず、自己リプライに、そのままコピペできる形で書く。自己リプライには「読む理由」（何が分かるか）を1つ入れる
