# S4LVnote（s4lv の運用システム）

s4lv（X: @cfrms4lv／スレッズ: @cfrms4lv／note: note.com/salvami77）の、note記事・X・スレッズの提案と分析を、企画から記録までつなげて回すフォルダ。
仕組み(部署・AIの役割・止まる場所・記録の形)は `../UYAnote/` と同じ形にそろえる(UYAnote のファイルは読まない)。**記事や投稿の中身の決まり(声・書き方・立ち位置・読者・数字の出し方)は s4lv のものを使い、UYA. の決まりは使わない。**

## いまの状態(作っている途中)
古い場所 `../brands/s4lv/` から、段階ごとに移している。移し終わるまでは、古い場所も残してある(保険)。

| 1 | 土台(このファイル・人物とアカウントの情報・学びの台帳・記事の一覧・ネタ台帳) | 済み |
| 2 | X とスレッズ(提案→審査→直し→予約→記録→分析。X の予約は Buffer) | 済み |

## このシステムの前提(s4lv の決まり。判断に迷ったら必ずここに戻る)
- **捏造禁止**：`0_社長室/S4LV設定/personal_data.md` と、ネタ台帳の「事実」にあることだけを使う
  - 例外(投稿の柱3「意見・考え」だけ)：外の話題をきっかけにした意見・考えは、実体験に紐づかなくてよい。ただし、意見を裏付けるための体験談(「実際にこういうことがあった」)は足さない。決まりの全文は `3_広報部/sns_common_rules.md`
- **開示ルール**：`personal_data.md` の開示ルールを必ず確かめる(ブログ名・番組名・具体的なキーワードは出さない など)
- **note の規約を守る**：性的な描写・言い切った統計・特定の人を傷つける書き方をしない
- **ふだんの言葉で書く**：オーナーは専門用語やカタカナ語が分かりにくい。オーナー向けの発言も、作るファイルも、ふだんの日本語で書く。専門用語が要るときは横に(かんたんな説明)をつける。言いかえ表は `../docs/plain_language_glossary.md`
- 設定の変更は、オーナーの指示があったときだけ。頼まれていない「ついでの改善」はしない(気づいたら提案として最後に並べる)

## 決まりを変える手順
オーナーの指摘や新しい決定を反映するときは、必ずこの順で行う。
1. 上の一覧で、その話題の正のファイルを決める
2. 変える案を作る。正のファイルの該当する所を**置き換える**(書き足すだけにしない)。食い違う古い記述を検索して、**消す**案に入れる。「旧版」「いまは使わない」の注意書きや、経緯の一言で残さない(履歴は git にある)
3. ほかのファイルには決まりを写さない。要るときは「正は〇〇」と場所だけ書く
4. 変える全文をオーナーに見せて、確認をもらってから保存する。一度伝えた注意は繰り返さない
5. もう使わない言葉・ファイル名ができたら、`.claude/hooks/check_rules.py` のリストに足す
6. `python .claude/hooks/check_rules.py` を実行して、0件を確かめる(パソコンの中にだけある鍵のファイル2つは「実在しない」と出る。これは問題ない)

## フォルダの外で読んでよいもの
ファイルの作成・編集は、この S4LVnote フォルダの中だけで行う。例外として、次だけは開いてよい。
- ネタの置き場(UYA. と共通)：`../journals/content_seeds.md`(体験)・`../journals/external_seeds.md`(外の話題)・ネタの由来の `../journals/daily/YYYY-MM-DD.md`(選んだネタの分だけ)。読むだけ。**書いてよいのは、`3_広報部/sns_common_rules.md`「使ったあとの記録」の印だけ**(s4lv のこれまでの決まり。UYA. はここに書かない)
- 全アカウント共通の資料(読むだけ)：
  - `../brands/reference/`(X・スレッズの表示のされ方のしくみ・noteの資料など。オーナーが手で更新する)
  - `../brands/writing/`(note記事の文章の共通の決まりと、審査の採点表。s4lv の上書きは `2_商品開発部/note_article_checklist.md` が優先)
  - `../docs/rubrics/title_scoring.md`(タイトルの配点表)・`../docs/reference/`(note内検索の取り方・モデル別の書き方の補強)
  - **これらの共通の資料は、MBTICODE を同じ形に移すときに、いちばん上の共通の場所へ移す予定。** 場所が変わったら、この行と、資料の場所を書いたファイルを書き換える(`grep -rn "brands/reference\|brands/writing\|docs/" .` で探す)
- Windowsでは `python3` が無い場合がある。bashで `python3` が見つからなければ `python` または `py -3` で同じコマンドを実行する。ファイルの読み書きはUTF-8で行う

## 依頼の受付
- 「Xの投稿を作って」「X投稿を提案して」「◯日のXを3本」など → X投稿フロー(下)
- 「スレッズの投稿を作って」「Threadsを2本」など → スレッズ投稿フロー(下)
- 「SNS投稿を作って」(Xともスレッズとも言われていないもの)→ 「Xなら『Xの投稿を作って』、スレッズなら『スレッズの投稿を作って』と送ってください」と1行返して、止まる
- 「Xを予約して」「スレッズを予約して」→ 各フローの手順4(まず送る内容を見せる)。そのあとの「予約して」で、はじめて送る
- 「Xの分析をして」→ `.claude/agents/X分析AI.md` を起動する(手順は `3_広報部/社員.md` のX分析AIの項)。結果の要点3行と保存先を、そのまま画面に出す
- 「スレッズの分析をして」→ `3_広報部/社員.md` のスレッズ分析AIの項に従う(親が記録と表を作り、`.claude/agents/スレッズ分析AI.md` を起動する)
- 「Xに出しました」(手直しして出したとき)→ `3_広報部/投稿文/posts_x.txt` の該当する本文を、出した版に直す
- 「note記事を書きたい」「次の記事どうしよう」「有料記事を書きたい」など、note記事を新しく作る・テーマを決める話 → note作成フロー(下)の手順1から。聞き返さない。「有料」「無料」の希望が言われていれば、企画AIの起動指示に「種別の希望: 有料(または無料)」とだけ添える
- 「1番」「2で」のように番号だけの発話(タイトル案の選択)→ 最新の企画書の末尾に「選択: 案N(YYYY-MM-DD)」を足してから、note作成フローの手順4へ
- 「構成案でOK」「この構成で」など → note作成フローの手順5へ
- 「ログインしました」→ 販売AIを新しく起動する(起動の指示は「3_広報部/社員.mdの販売AIの手順に従う。オーナーはs4lvのアカウントでログイン済み」だけ)
- 「下書きを直した」「直したので確認して」(オーナーがnoteの画面で直した)→ 直した本文を貼ってもらい、原稿に写す(checklist 8章の1と同じやり方。ページの取得は使わない)
- 「公開しました」→ `3_広報部/社員.md` の「公開後」
- 「◯◯AIから再開してください」→ フォルダに残っている最新の成果物を入力にして、その役割の手順から続ける(前の工程はやり直さない)
- note運用の相談・数字の画面(スクリーンショット)→ 段階4で切り替えるまでは `/note-advisor` を使うよう1行で案内する

## X投稿フロー
止まる場所は、提案を見て直す点を言うときと、予約の前だけ。手順の正は `3_広報部/社員.md` の X投稿AI・審査・提案と直し・X予約 の項。
1. **作る**：`.claude/agents/X投稿AI.md` を起動する(1回の呼び出しで、材料選び→設計→作成→機械チェック→保存まで)。本数と投稿日は、起動の指示に書く
2. **審査**：親が `.claude/agents/sns-ai-reviewer.md` を起動する(原則1巡。2巡目は、BLOCKがあるか、FIXが3件以上のときだけ)
3. **提案と直し**：設計の表・本文・機械チェックと審査の結果を、1回で出す。オーナーの直しは、変えたあとの全文を先に見せて、確認をもらってから保存する。直しは `3_広報部/X提案の直し記録.md` に1行
4. **予約**：「Xを予約して」で `buffer_api.py send`(確認だけ)で内容と日時を見せ、**「予約して」と言われたときだけ** `--go` で入れる。**XやBufferの画面は、ブラウザの自動操作で動かさない**
5. **分析**：「Xの分析をして」と言われたときだけ

## スレッズ投稿フロー
止まる場所は、X と同じ。手順の正は `3_広報部/社員.md` の スレッズ投稿AI・審査・提案と直し・スレッズ予約 の項。
1. **作る**：`.claude/agents/スレッズ投稿AI.md` を起動する
2. **審査**：親が `sns-ai-reviewer` を起動する(X と同じ)
3. **提案と直し**：X と同じ。直しは `3_広報部/スレッズ提案の直し記録.md` に1行
4. **予約**：「スレッズを予約して」で `queue_from_posts.py … --dry-run` で内容を見せ、**「予約して」と言われたときだけ** `--dry-run` を外して入れる(以降は Apps Script が自動で投稿する)。**スレッズの画面は、ブラウザの自動操作で動かさない**
5. **分析**：「スレッズの分析をして」と言われたときだけ

## note作成フロー
止まる場所は4か所だけ(①ネタを選ぶ(任意)・材料の質問に答える ②読者像とタイトル3案を見て選ぶ ③構成案に合意する ④完成後に note の画面で最終チェック)。資料の食い違い(checklist 0章)があるときだけ、①のあとに1回だけ質問が入る。
1. **ネタ候補と材料の質問**：`.claude/agents/ヒアリングAI.md` を起動し(1回目)、ネタ候補と6問を画面に出す。オーナーの回答と資料を受けたら、全文そのまま渡して記録させる(2回目)。0章の質問が返ってきたら、それだけ画面に出して、答えを渡す
2. **キーワード確認**：`.claude/agents/リサーチAI.md` を起動する
3. **企画**：`.claude/agents/企画AI.md` を起動する。全文を画面に出し、「読者像が違えば指摘してください。タイトルは番号で選んでください」と1回だけ聞く(止まる②)
4. **構成案**：番号を選んだら、企画書の末尾に「選択: 案N(YYYY-MM-DD)」を足し、`.claude/agents/執筆AI.md` を構成案で起動する。構成案をそのまま画面に出して「この構成で進めますか？」と聞く(止まる③)。情報量が上限を超えると書いてあれば、そのことも聞く
5. **本文と審査**：合意を受けたら **執筆AI(本文)** → **編集AI(1回目。機械チェックと差し戻し。最大2往復)** → **親が `note-ai-reviewer` と `note-beginner-reader` を同時に起動**(1巡目。サブエージェントは他のAIを起動できないため、親が行う。渡すのは「対象パス／種別／アカウント＝s4lv／巡数」だけ)→ 2人の指摘を **執筆AI(3回目)** に全文渡して直させる → 直した範囲だけ、1巡目の審査役に続けて頼んで再確認(新しく起動しない)。**合計3巡で打ち切る**。初心者役が3点以下で原因が「情報量」なら、書き足さず、情報量を減らす案をオーナーに出して判断を仰ぐ → **編集AI(最終)**
   - 誤字・一語の言い換え・語尾・句読点・改行だけの直しは、再審査に出さない(機械チェックで確定してよい)
6. **下書き保存**：`.claude/agents/販売AI.md` を起動する(タイトル・本文・アイキャッチ画像を入れ、**下書き保存**で止まる。「投稿する」は押さない)。販売AIの報告と、審査の結果の要点(PASS・残ったNOTE)を画面に出して止まる(止まる④)

## 共通ルール
- note.com の「投稿する」は絶対に押さない。「下書き保存」までで止まる
- 販売AIが「ログインが必要です」と返したら、「[販売AI → あなた] Claudeのブラウザ(画面右のパネル)で、s4lv(salvami77)のnoteにログインしてください。終わったら「ログインしました」と送ってください」と依頼して止まる。「別のアカウントでログインしています」と返したら、いったんログアウトして s4lv でログインし直すよう依頼する
- 各AIは `.claude/agents/` のエージェント定義でサブエージェントとして呼び出す。各役割の手順の正は各部署の `社員.md` で、エージェント定義と食い違う場合は社員.mdに従う
- サブエージェントに渡す起動指示は、社員.mdの該当役割の手順に従う旨と、本数・日付・入力ファイル名だけにする(手順書に書いてあることを書き写さない)
- 子の報告は短く：検証の結果・確度が中や低の点・オーナーに聞くことだけ
- 小さな直し(語句・誤字・数文字)は、親が直接直す。そのあと機械チェックをかけ直す
- 質問への回答は音声入力で来ることがある。誤変換は文脈で補って解釈する
- 完了報告には検証の証拠(機械チェックの結果・保存先のパス)を含める。実行していない検証を「できたはず」と書かない
- コミットは、往復のたびにはしない。オーナーが確定した時点で1回

## 会話ログ形式(全AI共通)
各AIのオーナー宛ての発言は、1行目を「[発信AI → 受信AI] 用件」にし、本文は箇条書きか番号付きで書く。受信先がオーナーのときは「→ あなた」。装飾・絵文字は使わない。
- 役割名：ヒアリングAI / リサーチAI / 企画AI / 執筆AI / 編集AI / 販売AI / X投稿AI / スレッズ投稿AI / X分析AI / スレッズ分析AI / 審査役
- 1発言は画面1スクロール以内(長い成果物はファイルに保存し、発言ではファイル名と要点だけ)。例外：投稿の提案(設計の表と本文)・企画書(読者像とタイトル3案)・構成案は、画面に全文出す
