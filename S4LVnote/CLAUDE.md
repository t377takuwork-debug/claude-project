# S4LVnote（s4lv の運用システム）

s4lv（X: @cfrms4lv／スレッズ: @cfrms4lv／note: note.com/salvami77）の、note記事・X・スレッズの提案と分析を、企画から記録までつなげて回すフォルダ。
仕組み(部署・AIの役割・止まる場所・記録の形)は `../UYAnote/` と同じ形にそろえる。**記事や投稿の中身の決まり(声・書き方・立ち位置・読者・数字の出し方)は s4lv のものを使い、UYA. の決まりは使わない。**

## いまの状態(作っている途中)
古い場所 `../brands/s4lv/` から、段階ごとに移している。移し終わるまでは、古い場所も残してある(保険)。

## このシステムの前提(s4lv の決まり。判断に迷ったら必ずここに戻る)
- **捏造禁止**：`0_社長室/S4LV設定/personal_data.md` と、ネタ台帳の「事実」にあることだけを使う
  - 例外(投稿の柱3「意見・考え」だけ)：外の話題をきっかけにした意見・考えは、実体験に紐づかなくてよい。ただし、意見を裏付けるための体験談(「実際にこういうことがあった」)は足さない。決まりの全文は `3_広報部/sns_common_rules.md`
- **開示ルール**：`personal_data.md` の開示ルールを必ず確かめる(ブログ名・番組名・具体的なキーワードは出さない など)
- **note の規約を守る**：性的な描写・言い切った統計・特定の人を傷つける書き方をしない
- **ふだんの言葉で書く**：オーナーは専門用語やカタカナ語が分かりにくい。オーナー向けの発言も、作るファイルも、ふだんの日本語で書く。専門用語が要るときは横に(かんたんな説明)をつける。言いかえ表は `../docs/plain_language_glossary.md`
- 設定の変更は、オーナーの指示があったときだけ。頼まれていない「ついでの改善」はしない(気づいたら提案として最後に並べる)

## 決まりを変える手順
オーナーの指摘や新しい決定を反映するときは、必ずこの順で行う。
1. 上の一覧で、その話題の正のファイルを決める
2. 変える案を作る。正のファイルの該当する所を**置き換える**(書き足すだけにしない)。食い違う古い記述を検索して、**消す**案に入れる。「旧版」「いまは使わない」の注意書きや、経緯の一言で残さない(履歴は git にある)
3. ほかのファイルには決まりを写さない。要るときは「正は〇〇」と場所だけ書く
4. 変える全文をオーナーに見せて、確認をもらってから保存する。一度伝えた注意は繰り返さない

## フォルダの外で読んでよいもの(読むだけ。書き換えない・コピーしない)
ファイルの作成・編集は、この S4LVnote フォルダの中だけで行う。例外として、次だけは読み取り専用で開いてよい。
- ネタの置き場(UYA. と共通)：`../journals/content_seeds.md`(体験)・`../journals/external_seeds.md`(外の話題)・ネタの由来の `../journals/daily/YYYY-MM-DD.md`(選んだネタの分だけ)
- 全アカウント共通の資料：`../brands/reference/`(X・スレッズの表示のされ方のしくみの資料など。オーナーが手で更新する)
  - **この共通の資料は、MBTICODE を同じ形に移すときに、いちばん上の共通の場所へ移す予定。** 場所が変わったら、この行と、資料の場所を書いたファイルを書き換える(`grep -rn "brands/reference" .` で探す)
- Windowsでは `python3` が無い場合がある。bashで `python3` が見つからなければ `python` または `py -3` で同じコマンドを実行する。ファイルの読み書きはUTF-8で行う
