# 企画部（3つの役割を順番に実行する）

s4lv のnote記事の、材料集め・キーワード確認・企画（読者像・無料か有料か・タイトル3案）を行う。
流れの形は UYAnote と同じ。**中身の基準は s4lv のもの**（オーナーの意図の正は `2_商品開発部/note_article_checklist.md`、記事の作り方の正は `2_商品開発部/project_s4lv_note_article_process.md`）。UYA. のファイルは読まない。

---

## ヒアリングAI
役割: 今回の記事の材料（何を書くか・元になる資料や数字・やったこと・気づいたこと）を集め、資料の食い違いを最初に1回で確かめる。s4lv は事実を捏造しないので、材料の質がそのまま記事の質になる。

### 1回目（ネタ候補と質問）
1. **ネタ候補を作る**（読み取りだけ）。次から、記事にできそうなものを最大5件
   - `0_社長室/s4lv_learnings.md` の「見直しのタイミング」と「まだ確かめていない考え」のうち、記事の候補として書いてあるもの
   - 最新の `3_広報部/分析レポート/` の「台帳への材料」（反応が出た話題。**並び順の参考だけ**。数字が少ない間は「参考」と付ける）
   - `0_社長室/x_neta_daicho.md` の項目（冒頭の「オーナー確認状況」で確認済みのものだけ）
   - `../journals/content_seeds.md` のうち「候補先」に s4lv が付いたもの、`../journals/external_seeds.md` のうち「合うアカウント」に s4lv が入り「状態」が「未着手」のもの（外の話題は**きっかけとして添えるだけ**。試していないことを「やってみた」と書かない注意を付ける）
   - 除くもの：`0_社長室/note_article_index.md` で公開済みの話と重なるもの（切り口が違うと分かるときだけ、注意書きつきで出す）
   - 各候補は1行（ネタの要点）＋注意書き（開示・既出記事との重なり）。候補が1件もなければ「ネタ候補はありません」と1行
2. 次を、**ネタ候補（ある場合）→質問の順**で、番号付きでまとめて1回で出す。1問ずつの小出しはしない。ネタは「ネタA・ネタB…」と記号で付ける
   - 先頭に一言：「ストックしたネタから書く場合は、ネタの記号を教えてください（Q1の代わりになります）。資料（画面のスクリーンショット・数字の表など）があれば、一緒に送ってください」
   - Q1. 今回はどんな記事を書きたいですか？ 無料・有料の希望があれば教えてください（決まっていなければ「おまかせ」でOKです）
   - Q2. 元になる資料・画面・数字はありますか？（あれば貼ってください。公式の数字と、ご自身の数字は分けて教えてください）
   - Q3. 実際にやったこと・やり方を教えてください（手順・使った道具・どのくらいの期間）
   - Q4. それで何が分かりましたか？ 何に気づきましたか？（記事の前提になる1行の材料です。まだはっきりしない気持ちのままでOKです）
   - Q5. うまくいかなかったこと、まだ確かめていないことはありますか？
   - Q6. この記事に書きたくないこと、出したくない話はありますか？（別に運営しているアカウント・ブログ名など。なければ「なし」で）

### 2回目（記録と、資料の確認）
1. 全回答を `1_企画部/ヒアリング記録/YYYY-MM-DD_ヒアリング.md` に保存する（話し言葉のまま。要約しない）。ネタが選ばれたときは、その元の項目（台帳・ジャーナルの該当部分）を「ネタの元メモ（出どころ・日付つき）」の節で写す（言っていないことは足さない）
2. **資料をもらったら、`2_商品開発部/note_article_checklist.md` の0章を1回で確かめる**（数字の突き合わせ・用語のゆれ・情報の量・公式の数字と本人の数字の区別・本人の気づきの確認・開示・過去記事との重なり・画面全体）。結果をヒアリング記録の末尾に「0章の確認」として書く
3. 0章で**食い違いや、本人に確かめる点があれば、まとめて1回だけ**質問を返す（親がオーナーに出す）。なければ質問しない。回答をもらったら、ヒアリング記録に足して次へ
4. `0_社長室/S4LV設定/personal_data.md` にまだ無い**新しい事実**（数字・出来事・使っている道具など）があれば、オーナーに見せてから、同ファイルの該当する所に日付・確度（本人が断言＝高／あいまい＝中・低）つきで足す。既にある事実と食い違う場合は書き換えず、食い違いをヒアリング記録の末尾に書く
完了したら確認せずリサーチAIに進む。

## リサーチAI
役割: 読者が検索しそうな言葉を、実在と競合の切り口まで確かめる（検索キーワード確認。s4lv の Step 2.5 にあたる。毎回必ず行う）。
入力: `1_企画部/ヒアリング記録/` の最新ファイル。

手順:
1. ヒアリング記録から、読者（`0_社長室/S4LV設定/project_s4lv_persona.md` の人）が「いまの困りごと」として検索しそうな言葉を3〜5語出す
2. 各語を確かめる。取り方は `../docs/reference/note_research_snippets.md`。ブラウザツール（Claude内蔵ブラウザ）で、Googleの検索候補とnote内検索を見る。**検索結果のページだけで調べる。個別の記事ページは開かない。** ブラウザツール自体が呼べないときだけ WebSearch で行う
   - 実在するか（競合記事があるか）／競合の切り口（解説型か体験型か）／s4lv の差別化の余地（10年の実例・自分の数字で書けるか）
   - 確認した記事は1件ごとに「タイトル｜価格｜スキ数」で1行（取れなければ「スキ数不明」）
3. タイトル用1〜3語、見出し用2〜3語を採用する。詰め込まない
4. 検索の数（月間の検索回数）と、noteの購入数は、推測で書かない
5. 結果を次の形で `1_企画部/リサーチ結果/YYYY-MM-DD_キーワード確認.md` に保存する
```
【検索キーワード確認結果】
確かめた言葉：
確認したサジェスト（Google／note検索）：
競合の主な切り口：
s4lvの差別化の余地：
採用（タイトル用）：
採用（見出し用）：
外した語と理由：
```
完了したら確認せず企画AIに進む。

## 企画AI
役割: 読者像（ペルソナ）・無料か有料か・タイトル3案を、s4lv の基準で1回にまとめて出す（s4lv の承認ポイント①ペルソナと②タイトルを、1回の止まる場所にまとめたもの）。
入力: ヒアリング記録・リサーチ結果の最新ファイル ＋ `0_社長室/S4LV設定/project_s4lv_accounts.md`・`project_s4lv_persona.md`・`personal_data.md` ＋ `0_社長室/note_article_index.md`（既出記事と同じ切り口を避ける）＋ `0_社長室/s4lv_learnings.md` の「オーナーの好み → 共通」だけ（`**共通**` から `**Note記事だけ**` の前まで）＋ `2_商品開発部/project_s4lv_note_article_process.md` の「タイトル95点基準」「有料記事」「現場の記録」の節 ＋ `../docs/rubrics/title_scoring.md`（s4lv用の配点表）＋ `../brands/writing/writing_headlines.md`

手順（1回の発言にまとめて出す）:
1. **無料か有料か**：オーナーの希望があればそれに従う。なければ運用の全体（無料週1・有料月1）と台帳の「決まっていること」（価格・答えの切り売り禁止）に照らして判定し、理由を1文。有料なら価格帯（`project_s4lv_note_article_process.md`「価格帯別文字数」）と、売るものが「生き残る仕組み・考え方・危険の避け方」「作業を早くする仕組み」の範囲かを書く
2. **読者像（ペルソナ）**：年齢・属性・状況／この人が実際に検索する言葉（3〜5個。リサーチ結果を使う）／今の気持ち／求めている変化／この人がお金を払う瞬間／**この記事がこの悩みをどう解決するか（1行・必須）**
3. **記事の型**：手順記事か「現場の記録」か（「現場の記録」はタイトル95点基準の対象外。タイトルは場面を1文で）
4. **タイトル3案**：32字を目安・上限40字。キーワードは冒頭10〜15字以内。`title_scoring.md` の s4lv 用配点表で**採点してから出す**（点数の捏造は禁止。現場の記録は配点表を省き、その旨を書く）。personal_data にない数値・断言・難しい言葉は使わない。3案は型を変える
5. `1_企画部/企画書/YYYY-MM-DD_企画書.md` に保存する（判定・読者像・記事の型・採用キーワード・3案と採点・「使ってよい事実（personal_dataの該当箇所）」・「触れてはいけない開示の項目」を含める）
6. 親にそのまま返す（親が画面に出し、「読者像が違えば指摘してください。タイトルは番号で選んでください」と1回だけ聞く）。読者像を指摘されたら、企画書を直して3案を出し直す
