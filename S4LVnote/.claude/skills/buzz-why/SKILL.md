# buzz-why — バズ投稿の「なぜ」を取り出して、s4lv の投稿案にする（2026-10-15新設・S4LVnote 用）

**目的**：毎日集まるバズ投稿から、①なぜ伸びたか（理由）②ネタ（テーマ）を取り出す。ネタは、元の投稿とは別の切り口で、s4lv の投稿案にする。**投稿を写すのではなく、理由を取り出す。**

**書き方**：ふだんの言葉で書く（`../docs/plain_language_glossary.md`）。専門用語が要るときは横に（かんたんな説明）。

## いまのモード：制限なし提案（2026-10-15 オーナー指示）

最終的な目的は「決まりを守った投稿の質を上げること」。そのために、いまは決まり（声・書き方・材料・数字・開示・作り話の禁止）を考えずに、バズの要素を素直に入れた案を作り、まず「どんな案が出るか」を見る。

- **決まりのファイルは書き換えない。** 外すのは、この提案の中だけ。決まりへの反映は、あとで「決まりを変える手順」（`CLAUDE.md`）で行う
- **作った部分には「※創作」の印を付ける**（出来事・やりとり・数字・結果を作ったとき）。台帳（K・A）や実績データにある事実と、見分けがつくようにする
- **ブログ名・番組名・実際のキーワード・URLは、制限なしでも出さない。** 特定されると取り消せないため（オーナーが外せと言ったときだけ外す）
- 案を見たあとで、オーナーが「決まりを入れた版に直して」と言ったら、`3_広報部/社員.md` の X投稿AI の手順で作り直す

## 守ること（このスキルの外せない枠）

- **他人の投稿の全文を、リポジトリに保存しない。** 全文は画面に出して読むだけ（`research/data/` は git に入らない）。分析ファイルに残すのは、URL・数字・構造のメモ・1行目の短い引用（20字まで）だけ
- **元の投稿の言い回しを借りない。** 借りるのは「型」と「理由」まで。投稿案は、元の入り方・具体例・結論の並びのうち、2つ以上を変える（下の「元との距離」）
- **理由は、断言しない。** 数字と本文から言えることだけを書き、確度（高・中・低）と根拠を付ける。本文が題名とリンクだけの投稿（中身がリンク先・画像）は、「文章からは分からない」と書く
- フォロワーが大きいアカウント（既定10万人超）は、真似できない規模のため、分析から外す

## 手順

1. **材料を取り出す**（トークンを使わない）：
   ```
   py -3 .claude/skills/buzz-why/select_posts.py --top 10
   ```
   - 観察対象アカウントの投稿（最大3件）と、勢いの上位・フォロワーの割に伸びた比率の上位を出す。同じ投稿者は1件まで。本文の全文・数字・比率・長さ・ツリーの印も出る
   - 最初から外すもの：投稿日が7日より前／本文がURLを除いて30字未満（題名とリンクだけ）／分析済み・在庫に登録済み（`3_広報部/バズ分析/` と `0_社長室/ネタ在庫.md` にURLがあるもの）／MBTICODE向けの語・観察対象で拾った投稿
   - 特定の投稿だけを見るとき：`--url <投稿のURL>`。数を変えるとき：`--top 20`・`--accounts 5`。範囲：`--post-days 14`・`--min-followers 50`
   - 毎日の自動収集が止まっていないかは、`../research/data/status.json` の `last_ok_at` で確かめる（2日以上古いときは、そう伝える）
2. **使えない投稿を、最初に外す**（問いには答えない）：次のどれかに当たる投稿は、一覧に「使わない」と理由1行だけ書く
   - 分野外：ブログ・note・SNS運用・AI活用のどれにも結びつかない（ゲームの感想、生活の相談など）
   - 話題の力だけ：有名人・企業のニュース・事件など、型ではなく話題で伸びている
   - 中身が外にある：本文が題名と画像・リンクだけで、文章からは分からない
3. **残った投稿ごとに、下の「固定の問い」に答える**。全文を読んで、答えの根拠に本文の言葉か数字を書く
4. **横断でまとめる**：複数の投稿に共通する理由（最大3つ）、長さとツリーの傾向、s4lv で使えるもの
5. **在庫への登録案を作る**：ネタ（テーマ）と切り口を、`0_社長室/ネタ在庫.md` の書式・点数の基準で書く（点数5未満は登録しない。上限を超えるときは、点数のいちばん低いものと入れ替える）。投稿案（本文）は、頼まれたときだけ作る（下の「投稿案の作り方」）
6. **画面に出して止まる**：分析の要点と登録案を見せる。**保存は、オーナーの確認のあと**
7. **保存**：確認をもらったら、`3_広報部/バズ分析/YYYY-MM-DD_バズ分析.md` に分析を（他人の全文は写さない）、`0_社長室/ネタ在庫.md` に登録案を書く

## 固定の問い（残った投稿ごとに全部答える）

答えは「結論1文＋根拠（本文の言葉・数字）＋確度（高・中・低）」の形で書く。分からない問いは「文章からは分からない」と書く。

**A. 刺さった相手**
- Q1. 誰の、どんな状況・悩みに刺さったか。読む前と読んだ後で、何が変わるか（気づき・手に入るもの・感情）。本文のどの言葉から、そう言えるか

**B. 入口と形**
- Q2. 1行目は何をしているか（悩みの名指し／結論／問い／逆説／出来事／数字／所感）。1行目だけで話が分かるか（2行にまたがって切られないか）
- Q3. 長さと形（単発／長文／ツリー、画像・リンク・動画）は、中身に必要だったか。なくても成り立つか。縮める・割ると、どうなるか。ツリーなら、1つ目と2つ目以降に何を置いたか

**C. 中身**
- Q4. これだけで完結しているか。外に出ないと分からない部分はどこか
- Q5. 具体は何か（名前・数字・手順・固有の言葉）。それを抜いたら、どう変わるか
- Q6. 言い切りはどこか。反論や補足を入れたくなる隙はあるか

**D. 反応**（数字から）
- Q7. 強い反応はどれか（保存率・返信率・再投稿率・いいね率）。それは、読者のどんな行動か（あとで使う／誰かに送る／意見を言う／広める）。本文のどの部分が生んだか

**E. 規模・条件**
- Q8. フォロワーの割に伸びたのは、何のためか。次を切り分ける：型／話題の力／画像・リンク先／投稿者の過去の実績／時事
- Q9. 同じ型の投稿と比べてどうか。`../research/data/x_posts.jsonl` で、同じ言い回し（「まとめました」「〜な人へ」など）の投稿を数え、いいね・保存率・規模の割の比率の中央値を出す。型の効果か、話題の力かを分ける（集めたデータは、いいね100以上だけなので、伸びなかった投稿は入っていない点に注意）

**F. 再現**
- Q10. 再現できる要素と、できない要素を、分けて書く。s4lv が同じ型を使うなら、何の事実で満たせるか（台帳の K・A の番号／実績データ／外の話題への意見）

**G. ネタ**
- Q11. この投稿のネタ（テーマ）は、1文で何か。元の切り口（入り方・具体例・結論の並び）を、それぞれ1行で
- Q12. s4lv の別の切り口を3つ。読者・場面・結論・形の軸で書き、元と変える点を書く

## 長さ（文字数）とツリーの判断

オーナーは X のプレミアムに加入しているため、140字を超える長文を投稿できる。「長くできる」ことを前提に、中身に合う長さを選ぶ。

**集めたデータの傾向**（2026-10-15・936件。URLと改行を除いた字数）：

| 区分 | 中央値 | 140字以内 | 141〜280字 | 281字以上 |
|---|---|---|---|---|
| いいね500以上 | 76字 | 78% | 13% | 9% |
| 保存1,000以上 | 137字 | 56% | 24% | 20% |

- いいねが多い投稿は短く、保存が多い投稿は少し長い（手順・一覧・まとめの型が多い）
- 実測メモ：174字以上の投稿は「さらに表示」で折りたたまれ、137字は折りたたまれなかった（確度は中）。折りたたまれても、1行目で続きを読ませられるなら成り立つ
- **分析のたびに、この表を更新する**（集まったデータで、同じ集計をやり直す）

**単発かツリーかの判断**（案を作るとき）：

| 中身 | 形 | 理由 |
|---|---|---|
| 1つの意見・所感・気づき | 単発（140字前後） | 短いほど、1行目で全部伝わる |
| 手順や条件が3つ以上、保存してほしい一覧 | 長文の単発（200〜300字） | 公開資料は、ツリーより長文の単発が有利なことが多いとする |
| 281字を超える、または図解・画像が要る | ツリー | 1つ目だけで価値が伝わるようにし、2つ目以降は補足 |
| noteへ案内する回 | 単発＋自己リプライ（URL） | URLは本文に入れない |

**ツリーにするときの決まり**：
- 1つ目は、単体で意味が通り、1行目で止まる。続きを読ませるための「予告だけ」にしない
- 2つ目以降は、補足・手順・出典。URLは最後に置く
- 各ツリーに、何行目で何を言うかを書く
- 元のバズ投稿がツリーだったときは、2つ目以降の中身を、投稿のURLを開いて確かめる（収集は返信を除いているため、データに入っていない）。確かめていないときは「2つ目以降は未確認」と書く

## 投稿案の作り方

1. **反応を決める**：保存／返信／引用／リンクコピー共有のどれを狙うか。意識した重みを書く（正は `../brands/reference/x_algorithm_2026.md`。リンクコピー共有20・返信5・引用5・DM共有5・リポスト1・いいね0.5）
2. **理由を入れる**：分析で取り出した「再現できる理由」を、案の中で使うところを書く（Q番号で示す）
3. **材料を決める**：台帳（`0_社長室/x_neta_daicho.md` の K・A）か、実績データ（`0_社長室/S4LV設定/personal_data.md`）か、外の話題への意見。制限なしモードでは、足りない出来事は作ってよい（※創作の印を付ける）
4. **形を決める**：単発／長文の単発／ツリー。字数（URLを除く）を書く
5. **案の数**：既定は元の投稿1本につき1〜2案。全体で、依頼された本数

**案の出力の形**：

```
■ 案N（形：単発／長文／ツリー、◯字、狙う反応：◯、意識した重み：◯）
元：【番号】@アカウント（理由：Q◯）／材料：台帳 K◯／A◯・実績・意見・※創作
（本文。ツリーなら「1つ目」「2つ目」と分けて書く）
元との距離：入り方（変えた／同じ）・具体例（変えた／同じ）・結論の並び（変えた／同じ）
創作した部分：（あれば。何を作ったか）
```

## 元との距離（盗作・パクリに見えないための確認）

- **3つの軸**：入り方・具体例・結論の並び。**2つ以上を変える。** 変えていない軸があるときは、案を直す
- **同じ論点の型**（「Aではなく、B」「〜な人へ」など）は、型として使ってよい。**使えないのは、同じ具体例・同じ言い回し・同じ並びの組み合わせ**
- **機械の確認**（案が1本できるごとに、保存する前に行う）：
  ```
  py -3 ../research/export_sources.py <元の投稿のURLかID>
  python ../brands/tools/check_similarity.py <案を書いたファイル> --sources <できたファイル>
  ```
  「見つからない」と出た投稿だけ、Chrome で取り直す（`../docs/sop/sop_research_auto_collect.md` 「守ること」）
- 近いと出たら、その案は書き直す。直したあと、もう一度確かめる

## 出力（分析ファイルの構成）

```
## 1. 投稿別の分析
- 一覧の表（番号・URL・1行目の20字まで・フォロワー・数字・判定（使う／使わない＋理由））
- 使う投稿ごとに、Q1〜Q12 の答え（結論・根拠・確度）
- 型ごとの比べ（Q9の表）
## 2. 横断のまとめ
- 共通する理由（最大3つ）／長さとツリーの傾向／s4lvで使えるもの
## 3. 在庫への登録（T-番号）と、投稿案（頼まれたときだけ）
## 4. 確かめたこと・未確認のこと
- 類似チェックの結果／2つ目以降が未確認のツリー／確度が中・低の理由／手順の改善点
```

## やらないこと

- 投稿の予約・送信（それは `CLAUDE.md`「X投稿フロー」の手順4。オーナーが「予約して」と言ったときだけ）
- 台帳（`x_neta_daicho.md`）・決まりのファイルの書き換え
- 他人の投稿の全文の保存・転記
- 理由の断言（確度と根拠なしで言い切ること）
- スレッズ・MBTICODE の分析（このスキルは X の s4lv・UYA.向け。MBTICODE は `/mbticode-analysis`）
