# UYA. テーマ・タイトル設計

UYA.のNote記事テーマを評価し、有料・無料の判断・タイトル決定まで行うシステム。

使い方：`/uya-theme [テーマ案]`（テーマなしで起動した場合はStep 0の質問から開始）

---

## 必ず読むファイル（この順）

1. `uya/profile.md` ← 看板・読者像・トーン・s4lvとの違いの要点
2. `uya/rules/project_uya_positioning.md` ← 上記の決定理由・唯一の正（判断に迷ったらここに戻る）
3. `uya/shared/personal_data.md` ← 実体験データ・開示ルール（ここにない体験・数字は使わない）

---

## Step 0：テーマなしの場合

「最近考えていること・書きたいことを教えてください（働き方・お金の波・パチスロとの付き合い方・AIやブログで試したことなど何でも）」と1つだけ質問する。

---

## Step 0.5：有料・無料の判断

**この判断をせずに先に進まない。**

- **種別指定あり**：ユーザーが「有料」「無料」を明示した場合はその指定に従う
- **種別未指定**：**このnoteアカウント自体の読者がまだついていない間は無料記事を推奨する**（UYA.本人の実績が薄いという意味ではない。10年分の実績はすでに厚い。理由は、フォロワーがいない段階では有料記事は見つけてもらいにくく、無料記事の方が読者との最初の接点・信頼づくりの役目を果たすため。`rules/project_uya_positioning.md`の方針＝体験談は無料で信頼を貯める、が前提。2026-09-28、オーナー指摘を受け表現を訂正）
- **有料記事の条件**：`rules/project_uya_positioning.md`「マネタイズ方針」参照。実用（ブログ・noteの運営手順）か、生き方・意思決定寄りの中身で、読者が「今日から動ける」具体性があるかを確認する

```
【判定】：無料記事 / 有料記事
理由：（1文で）

＜有料の場合のみ追記＞
有料にできる根拠：
想定価格：（`docs/reference/note_monetization_reference.md`の相場＝実用系1,842円前後・読み物系983円前後を目安に）
無料パートで見せるもの：
有料パートに残すもの：
```

## Step 1：読者像の確認（テーマごとの微調整）

`uya/profile.md`「読者像」を土台に、このテーマで最も届けたい「今の状態」を1つ具体化する。

**絞り方の基準（2026-09-27オーナー確認）**：万人向けの広すぎる書き方にせず、かといって属性（年齢・性別・職業等）で絞りすぎて身元特定リスクを上げたり対象を狭めすぎたりもしない。**属性ではなく「感情・状況の組み合わせ」で絞る**（例：「出勤そのものが億劫」＋「人前でのプレッシャーが苦手」＋「それを甘えだと思って誰にも言えない」）。この組み合わせに心当たりがある人には刺さり、ない人には響かない、という程度の絞り込みを狙う。

出力する項目：
- 今どんな状況で悩んでいる人か（属性ではなく状況・気持ちで描く）
- この記事に出会う場面（いつ・どこで・どんな気持ちで読むか）
- この記事を読んで、何がどう変わってほしいか

「この読者像で進めますか？」と確認する。

---

## Step 2：テーマのシビア評価（3つの視点）

以下の3つの視点で審査する。忖度・曖昧な合格判定は禁止。

**【当事者性担当】** `shared/personal_data.md`に書かれた事実の範囲内で、「私」が実際に経験したこととして書けるテーマか。捏造・誇張になっていないか。読者が「自分もそうかも」と思える普遍性があるか。

**【差別化担当】** s4lvのような「体系立てて教えるノウハウ商品」に寄っていないか。当事者としてその都度記録するトーンを保てるテーマか。既存のs4lv記事と同じ切り口（ブログ設計・SEOの技術的な型）になっていないか。

**【開示ルール担当】** `shared/personal_data.md`「開示ルール」に触れる内容はないか（本名・顔・職種名・病名・パチスロで使った金額など、出さないと決めた項目）。noteの規約（`docs/reference/note_terms_prohibited_conduct_reference.md`）に抵触する要素（収益を煽る、必ず儲かる系）がないか。

```
【当事者性担当の評価】：
【差別化担当の評価】：
【開示ルール担当の評価】：

【判定】：採用 / 却下

＜却下の場合＞
却下理由：（ロジカルに・忖度なしで）
代替テーマ案：（1案・理由付き）

＜採用の場合＞
このテーマが読者に届く理由：（2〜3文）
```

却下の場合はStep 2を繰り返す（代替案をユーザーが承認したら次へ）。

## Step 2.5：検索キーワード確認（タイトル案の前に必ず実行）

**目的**：note内の検索と、Googleなどの検索の両方から読者に届く言葉を、読者像に合わせて選ぶ。

1. オーナーが渡したサジェストキーワード（複数）を受け取る。なければ、読者像の場面で検索しそうな言葉を3〜5語、こちらから案を出す
2. 各語を確認する（Claude in Chrome。取り方は `docs/reference/note_research_snippets.md`。1回のJSは約40秒で止まるので、語は5つ以内にまとめて取る）
   - 実在するか：Googleのサジェスト／note内検索（人気順・新着順は別々に取り、出どころを書く）
   - 競合の切り口：解説型か体験型か
   - UYA.の差別化の余地：体験を語る側で書けるか
3. 読者像に合わせて選ぶ
   - 読者が「いまの困りごと」として打ち込む言葉か
   - 本文で実際に答えられる言葉か（題だけ釣らない）
   - 体験記と合わない語（おすすめ・ランキング等）は後回し
4. タイトル用1〜3語、見出し用2〜3語を採用する。詰め込まない（公式2026年版も不自然な詰め込みは不要としている）
5. 検索の数（月間の検索回数）は無料では取れない。「実在・競合・サジェスト」までを確認範囲とし、数字が必要ならオーナーから受け取る

```
【検索キーワード確認結果】
渡されたキーワード：
確認したサジェスト（Google／note検索）：
競合の主な切り口：
UYA.の差別化の余地：
採用（タイトル用）：
採用（見出し用）：
外した語と理由：
```

## Step 3：タイトル設計

**順番を守る**：テーマ → Step 1の読者像を本人が確認 → Step 2.5のキーワード → タイトル。どれかが未確認なら、タイトルは出さない。
**基準の出どころ**：note公式（ヘルプ・編集部）。調べた内容は `uya/articles/title_research_1003.md`。

### 先に、公式の4問で材料を書く
1. 誰に向けた内容か（読者の場面）　2. どんな価値があるか（保証でなく範囲）　3. どんな内容か　4. どう伝えるか

### 共通の基準（無料・有料ともすべて満たす）
1. 前半25字前後に「何の話か」「誰のどんな場面か」を入れる。補足は「｜」の後ろ（全体30〜40字まで）
2. Step 2.5で採用したタイトル用キーワードを前半に入れる。不自然に詰め込まない
3. 変化の見え方を4段階で判定する
   - ◎ 前と後の両方が具体的に見える（例：1時間前後→約15分）
   - ○ 後だけ、または前だけが具体的
   - △ 方向だけ（楽になった・変わった）
   - × 変化が見えない

   足切り：3案とも○以上。△・×の案は、数合わせでも出さない。3案のうち少なくとも2案は◎。材料に前と後の両方がなければ、案を作る前に「前（以前はどうだったか）」を質問する。
4. 中身の形が分かる（体験記・手順・件数）。数字は具体性として入れる。技として先頭に置かない
5. トレンド性：関心の高いテーマ（AI・副業・SNS等）が自然に入っている
6. 期待と中身がずれない。導入・本文と矛盾させない
7. 「最強」「知らないと損」「衝撃」、記号での強調、期待の吊り上げをしない
8. 裸の「〜してみた」「〜の記録」「最近思ったこと」で終えない
9. 変化が静かに見える／体験談であることを隠さない（UYA.固有。`rules/project_uya_positioning.md`の決定）
10. 数字・立場は `shared/personal_data.md` の範囲内。開示ルールに触れない
11. 変化を2つ以上並べるときは、並びで書く（「AでBに」と読めて原因と結果が逆にならないか確かめる）
12. 硬い言葉・業界語は使わない（運用→運営、向上→上がる。`docs/plain_language_glossary.md`が正）
13. 結果が「一部の記事」「一部の場面」なら、「ほとんど」等で言い切りを防ぐ。題に入れないなら、導入の1行目で補うと決め、引き継ぎに書く
14. 材料にない事実（例：「順位を維持」）は題に使わない。使いたければ先に本人へ確認し、`personal_data.md`に足してから使う

### 無料記事のとき（追加）
- 「誰に」「どんな内容か」を前に出し、場面で「自分のことだ」と思わせる
- 広すぎる得（誰にでも当てはまる利益）は書かない
- 続きが気になる空白（結果の一部を言い切らない）を残してよい

### 有料記事のとき（追加）
- 4問の「どんな価値があるか」を必ず書く。書けなければ有料にしない
- 題に「何が手に入るか」の範囲を入れる（手順・判断の基準・やり方など）
- 成果の数字や保証で購入を促さない（note規約10.1(3)・UYA.の方針）。「月○万」「10倍」を約束の形で置かない
- 参考書型にしない。体験談であることを隠さない
- 無料パートの導入と、題の約束が合っているか確かめる（ずれは返金・不信につながる）

### 出し方
3案を出し、表で評価する。根拠のない加点はしない。

- 3案は型を変える（当事者型／数字型／線引き型など）。変化の質は落とさない
- 評価表は甘くつけない。基準を満たさない項目を○にしない
- 3案が揃わなければ、揃わなかったと正直に伝える。数合わせはしない

```
| 評価軸 | 案A | 案B | 案C |
|---|---|---|---|
| 前半25字で何の話か／キーワードが前半にあるか | | | |
| 誰の場面か見えるか | | | |
| 変化の見え方（◎○△×）／並びの正しさ（原因と結果が逆でないか） | | | |
| 中身の形が分かるか／期待と中身がずれないか | | | |
| 煽り・記号強調・裸の「してみた」がないか | | | |
| 材料の範囲内か・開示ルール違反がないか | | | |
| （有料のみ）払う理由が見えるか／成果の数字で煽っていないか | | | |
```

「どの案を選びますか？または修正指示をください」と確認する。
