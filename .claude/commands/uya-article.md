# UYA. 記事生成システム

`/uya-theme`の引き継ぎ情報を受けて、構成設計・本文生成・品質チェック・保存まで行うシステム。
引き継ぎ情報がない場合は「テーマ・種別・タイトルを教えてください」と確認してから開始する。

**構成案の提示と合意を飛ばして本文を書き始めない**（ルート`CLAUDE.md`の共通ルール）。Step 1で必ず立ち止まる。

---

## 開始時のお知らせ：yomiyasuを試すか聞く（2026-10-01オーナー依頼・終了条件あり）

`journals/external_seeds.md` のyomiyasuの行の状態が「提案中」のあいだ、**記事づくりの最初（テーマ・種別が決まった直後・構成設計に入る前）に、オーナーへ一言で伝えて聞く**：「前に見つけた、日本語のAI臭さを直すスキル『yomiyasu』を、この記事の下書きで試しますか？ 導入前後を並べて比べます。導入（`npx skills add nanaism/yomiyasu`）はご自身でお願いします」。

- **試す**：導入済みか聞く。まだなら導入を待つ（こちらから導入しない）。本文ができたら、元の下書きは上書きせず写しで直し、前後を並べて「手直しの手間が減ったか」をオーナーに聞く。結果を `external_seeds.md` のyomiyasuの行の状態に記録する（試した／見送り）
- **今回はやらない**：状態は「提案中」のまま。次の記事でまた聞く
- **「もう聞かないで」**：状態を「見送り」にする
- 状態が「試した」「見送り」になったら、このお知らせは出さない
- 使うのは**note記事の本文だけ**（X・スレッズの投稿には使わない。改行・黒点の型とぶつかるため）。`quality-guardrail` など他の文体直しのスキルとは同時に使わない

## 開始時に必ず読むファイル

1. `uya/profile.md` ← 看板・読者像・トーンの要約
2. `uya/rules/project_uya_positioning.md` ← 立ち位置・差別化・文章の書き方の決定（唯一の正）

4. `uya/examples_essay.md` ← 文体・語尾・句読点・改行の余白・引用/太字の使い方の見本（Step 2の前に必ず読む。口癖・語尾の傾向は再現してよいが、内容に紐づいた具体的な一文はそのまま使い回さない）
5. `docs/reference/note_paid_article_writing_reference.md` ← note公式のタイトル・画像・タグ・価格の基準（有料記事のときは特に）
6. `uya/rules/hashtag_candidates.md` ← ハッシュタグ選定の起点（Step 4で必ず読む）

## Step 1：構成設計

### H2設計ルール

**基本の流れ（当事者記録エッセイ）**：
場面・きっかけ → 何が起きたか（事実） → その時どう感じたか → 今はどう考えているか（変化）

**冒頭はH2なしで本文から直接始める**（つぶやきのように入る。「この記事では〜について解説します」で始めない）。

- 各H2に「何のシーンを・どこまで具体的に書くか」の執筆方針を付ける
- H2は3〜5本に絞る
- 全H2のうち最低1本に、読者の状況（会社に行くのがつらい・人前が苦手・収入の波 等）に触れるキーワードを含める
- H2だけを縦に読んで記事の流れが追えるか、設計後に確認する

### H3の使用判断

原則H3不要。1つのH2内に複数の独立した段階・情報があり、H3なしでは読者が迷子になる場合のみ使う。

## Step 2：本文生成

### 語り口のルール

- **一人称**：「私」
- **押しつけない、静かな語り口＋カジュアルな口調**。s4lvの「謙虚な実力者」的な抑えたトーンとは違う、素の言葉・砕けた言い回し（`rules/project_uya_positioning.md`参照）
- **捏造禁止**：`shared/personal_data.md`にある事実の範囲内のみ。不明な部分はユーザーに確認してから書く
- **感情軸は正直な体験談そのもので作る**。作り物の危機感・煽りは使わない（PASONA的な表現辞典は不採用。2026-09-27決定）

### Sonnet系モデルで書くときの補強（2026-10-01・UYA.の1テーマで検証。仮説を含む）

**Sonnet 5.5（medium／high）で本文を書くときは、`docs/reference/note_writing_model_tips.md`の「2. 補強の指示」（A〜E）を本文生成の依頼に加える**。要点：①各H2の要点とつなぎ方を先に決めてから書く ②材料の範囲で具体に言い換え、新しい出来事・気持ちは足さない ③少し楽になる一文で終える（格言にしない） ④文末「〜て。」を3割以内に ⑤保存前に字数を数える。初稿に声の薄さ・つなぎの弱さを感じたら、同じ指示をhighで1回だけ書き直す。手直しの1回（同ファイル3章）はまだ試していない仮説。

### 採用する機械的ルール（`brands/writing/writing_core.md`より。トーンに関係ない部分のみ）

- 疑問文には「？」を使う（「〜か。」にしない）
- 読点は目安2つまで。3つ以上になったら文を分ける
- 1文は目安70字まで
- CTA（読者に望む行動）は曖昧にせず具体的に書く（「ぜひ読んでみてください」ではなく「まず1つ、今日試せることを書いた」等）
- 「作る側の用語」（ペルソナ・フック・ベネフィット等）を本文に出さない

### 採用しないもの

- PASONAの「痛みを五感で描写する」「危機感を煽る」式の表現（`ライティング.txt`系）
- 「体験談に見えないようにする」書き方（UYA.は当事者記録が差別化ポイント）

### 見た目（改行・引用・太字）

**`uya/examples_essay.md`が唯一の正**。書く前に必ず読む。要点だけ再掲：

- 段落は1〜2文ごと。見出しの直前や感情が動く直前には、全角スペース（　）だけの行を挟んで広めに空ける
- 引用（`>`）は感情のこもった一言だけに使う（事実・数字の羅列には使わない）。目安800字に1箇所
- 太字は6〜7か所、文の終わりに置く（文の途中で切らない）。鍵括弧の内側全体を太字にすると崩れることがあるので、使うかはオーナーに確認する
- 太字・引用を入れたら、**必ずnoteのプレビューで実際の表示を確認する**（ソース上の見た目とnote側の表示は一致しない場合がある）

### 扱ってはいけない話題（`shared/personal_data.md`「開示ルール」参照）

- 本名・顔、年齢
- 過去の職種名（「体を使う仕事」等に留める）・けがの病名（「首の持病」等に留める）
- パチスロの立ち回り・勝ち方・設定判別・店名・機種の推し・使った金額／勝ち額
- 運営しているブログ・note名（ジャンル程度は可）

### 収益の数字を使うとき

- s4lvと同じ具体的な数字（1日170万円、確定約160万円 等）を使ってよい（2026-09-27オーナー確認）
- ただし**購入を煽る使い方はしない**。有料記事の販売文に置かない。報酬画面のスクリーンショットは使わない。低い月もセットで書く

## 有料記事モード（種別に「有料記事」が指定された場合のみ適用）

### 全体構造

無料パートで信頼と判断材料を渡し、有料パートで実行できる中身を渡す（`docs/reference/note_paid_article_writing_reference.md`「公式が示している事実」参照）。

- 無料パートは、この記事単体で判断材料が揃うようにする（目安：800〜1,500字。長文になる場合は無料側を厚くする）
- 有料ラインは1本のみ。誘導文は2〜3行・煽らない・何があるかを一言で

### UYA.固有の4つの判断（2026-09-27決定・`rules/project_uya_positioning.md`参照）

1. **「参考書型」「体験談を隠す」書き方はしない**。当事者としての語りのまま書く
2. **タイトルは変化が見えるものにする**（静かな言い方で。煽り文句にしない）
3. **継続更新前提の記事なら、冒頭のアップデート情報は大きな更新だけに絞り、スマホ1画面に収める**（該当する記事のときのみ）
4. **感情の部分は正直な体験談そのものが担う**。「論理だけの箇条書き」で終わらせず、実際にどう感じたかを書く。「自分にもできるかも」と思える再現性（具体的な手順・場面）も入れる

### 価格の目安

`docs/reference/note_monetization_reference.md`の相場：実用ノウハウ系1,842円前後、読み物系983円前後。文字数と売上の相関はほぼゼロなので、字数を稼がない。

## Step 3：品質チェック

本文生成後にチェック。問題があれば修正してから保存する。

**【事実確認】**
- [ ] `shared/personal_data.md`にない体験・数字を使っていないか
- [ ] 開示ルールで「出さない」とした項目（職種名・病名・パチスロの金額・本名等）に触れていないか
- [ ] 収益の数字を出す場合、購入を煽る場所・書き方になっていないか（スクショなし・低い月もセット）

**【トーン】**
- [ ] 一人称は「私」になっているか
- [ ] PASONA的な煽り表現（警告！・絶対に・知らないと恥をかく 等）が入っていないか
- [ ] s4lvのような「体系立てて教える」書き方になっていないか（当事者記録のトーンを保っているか）
- [ ] 冒頭がH2なしで本文から始まっているか

**【読みやすさ】**
- [ ] 疑問文が「？」になっているか。読点が1文2つ以内か。1文70字以内か
- [ ] H2見出しだけ縦読みで記事の流れが8割わかるか
- [ ] 1段落5行超が連続していないか
- [ ] （Sonnet系で書いたとき）文末「〜て。」「〜で。」が全体の3割を超えていないか／`shared/personal_data.md`と構成案にない気持ち・出来事を足していないか／`qa_article.py`の本文文字数が指示の字数に入っているか

**【有料記事 追加チェック】**（種別が有料記事の場合のみ）
- [ ] 「参考書型」「体験談を隠す」書き方になっていないか
- [ ] タイトルに変化が見えるか
- [ ] 無料パート単体で判断材料が揃っているか
- [ ] 感情の部分が正直な体験談で作られているか（作り物の危機感になっていないか）
- [ ] 有料ラインは1本のみか。誘導文が煽っていないか

**【機械チェック（必須）】**

```
python brands/tools/qa_article.py "uya/articles/drafts/<ファイル名>.md"
```

有料記事は `--paid` を付ける。**ERROR 0件**になるまで直す。WARNは内容を見て判断する。

## Step 4：ドラフト保存（本文出力と同ターンで実行・後回し禁止）

**保存先**：`uya/articles/drafts/`
**ファイル名**：記事テーマを簡潔に表した日本語

**ファイル先頭の管理情報**：

```
作成日：YYYY-MM-DD
種別：無料記事 / 有料記事（価格）
タイトル：
ハッシュタグ：
```

### ハッシュタグ選定（保存前に実施）

**公式ルール・検索の仕組みは`docs/reference/note_hashtag_reference.md`が唯一の正**。要点だけ再掲：

**手順**

1. `uya/rules/hashtag_candidates.md`を読み、**一般タグ**の中から記事の内容と一致するものを拾う。バンクにない新しいタグを思いつく場合は、実在確認（`note_hashtag_reference.md`§3）に加えて`hashtag_candidates.md`「新しい候補タグを見つけたときの採用基準」に照らしてから追加候補にする
2. **note.com/contests（お題＋期限付きコンテスト）を確認する。ただし`hashtag_candidates.md`の「最終確認日」が14日以内ならライブチェックを飛ばし、バンクの「お題」表から記事の内容と合うものを探すだけでよい**。14日を過ぎていたら次の手順で確認し、最終確認日を更新する（`note_hashtag_reference.md`§4）：
  1. `note.com/contests`を1回読み込む（`finished`は見なくてよい。もう使えないタグなので）
  2. UYA.に関係ないカテゴリ（エンタメ・マンガ・旅行・ゲーム・音楽・スポーツ・フード・美容・読書・アート・教育・育児等）は読み飛ばす。見るのは**上部の期限付きコンテスト一覧・ビジネス・ライフスタイル・創作**の3カテゴリだけでよい
  3. その中から、**その記事固有の中身と実際に重なる言葉**が入っているものだけを候補にする（アカウントのジャンルと合うだけでは不十分。今回の記事なら「退職」「仕事」「自己紹介」等）
  4. 候補になったものだけ`/hashtag/<候補>`を開いて`/contest/〇〇`になるか確認し、スキ数・並んでいる記事のトーンが近いか見る
  5. 期限付きコンテストは、内容が本当に合うときだけ候補にする（懸賞目当てで無関係な内容につけない）
3. 集まった候補から**本文の内容と実際に一致するもの**だけに絞る（2026-09-15〜、一般的なタグはnoteのAIが記事内容を読んで検索表示を判断する仕様のため。内容と無関係なタグは付けても表示機会が増えない）
4. **最終的に選ぶ個数は基本5個。お題やツール名タグが内容的に外せない時だけ最大7個まで**（2026-09-28確定）。note公式の目安（3〜5個程度）に沿う。プラットフォーム上限の10個は使わない方針
5. 先頭の#を除き30字以内、ハイフン不可
6. パチンコ・パチスロを直接連想させるタグ（例：#パチスロ #スロット）は、立ち回り・勝敗を扱わない方針と合わないため使わない
7. 候補をオーナーに提示し、選んでもらってから確定する（決め打ちしない）
8. バンクにない新しいタグを追加した場合は、`uya/rules/hashtag_candidates.md`に追記する

**件数についての注意**：`hashtag_candidates.md`に載っている件数は実在確認のためのものであり、**件数の大小は「需要」の指標にはならない**（`note_hashtag_reference.md`§3）。一覧に並ぶ記事のトーン・読者層が自分の記事と近いかを目視で確認する方が意味がある

## 注意事項

- テーマ・タイトルの見直しが必要な場合は `/uya-theme` を呼び出す
- 戦略的判断（立ち位置・価格・開示範囲の変更等）が必要な場合は `/notekaigi` を呼び出す
- 公開後は `uya/articles/published/` へ移動し `uya/articles/article_index.md` に登録する（削除前に必ずpublished/とindexを確認する。ルート`CLAUDE.md`共通ルール）
- 記事を重ねるたびに、`uya/examples_essay.md`に新しいクセ・判断を追記していく（1本目の実地確認で新設済み）
