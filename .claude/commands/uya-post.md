# UYA. X・スレッズ投稿生成

UYA.のX・スレッズ投稿を作るスキル。**軽量版**：専用審査エージェント・自動投稿キューはまだ作らない。機械チェックのうち、客観的に判定できるもの（文末の過去形言い切り・『』の使いすぎ・AI感フレーズ・X/スレッズ書き出しの重複等）は`tools/qa_post_uya.py`が担当する（2026-09-29新設。初回投稿で同じ問題を複数回繰り返したため前倒しで作成）。判断が必要なもの（自然さ・キレ・当たり前チェック等）はStep 3で人＝Claudeが見る。

運用ルール（頻度・型・X/スレッズの役割分担・パチスロと収益数字の扱い・note誘導・s4lvとの重複回避）の**唯一の正は`uya/sns_post_cheatsheet.md`**。本ファイルには数値・ルールを重複記載しない。

---

## 必須：実行前に読み込むファイル

1. `uya/sns_post_cheatsheet.md` — 運用ルール一式（唯一の正）
2. `uya/shared/personal_data.md` — 実体験データ・開示ルール（本文で使ってよい事実の範囲）
3. `uya/examples_essay.md` — 口癖・語尾・改行の見本（投稿でも同じ言葉づかいを使う）
4. `uya/rules/uya_learnings.md` — **学びの台帳（毎回必ず読む）**。cheatsheet・examples_essay.mdにまだ書く場所がない断片的な好みのみ（短い）
5. `uya/rules/sns_kutouten_kaigyo_rules.md` — 句読点・改行・記号
6. `sns_post_cheatsheet.md`「反響を意識するポイント」— プラットフォームの仕組みに沿った書き方（元は`brands/reference/x_algorithm_2026.md`・`threads_algorithm_2026.md`。深掘りが要るときだけこの2本を全文Read）

条件付き参照：直近1〜2週間に保存した`uya/posts/posts_x.txt`・`uya/posts/posts_threads.txt`（同じ話・同じフックの連発を避けるため。存在しなければ確認不要）／`brands/s4lv/posts/posts_x.txt`・`posts_threads.txt`（s4lv側で直近使ったネタと被っていないか確認するため）

## 実行ワークフロー

### Step 1：ネタを選ぶ

ユーザーが「これについて書いて」と具体的に指定した場合はそれを使う。指定がなければ、`sns_post_cheatsheet.md`「ネタを探すときの順番」のとおり：

1. `journals/content_seeds.md`のuyaタグ候補（未使用のもの）
2. `shared/personal_data.md`の時系列表から、まだ使っていないエピソード
3. どちらもなければ`journals/external_seeds.md`のUYA.向けの候補（種類が「試すきっかけ」「反応ネタ」。「意見ネタ」はs4lv用なので使わない。無ければユーザーに`/neta-research`の実行を提案する）

選んだネタと、対応する型（①実況ログ型／②過去の記録型／③記事誘導型）をユーザーに一言で提示してから書き始める。

**書き方パターンを1つ選ぶ**（`sns_post_cheatsheet.md`「書き方パターンのローテーション」6種から）。直近の`posts_x.txt`・`posts_threads.txt`があれば見て、同じパターンが連続していないか確認する（初回・投稿が少ない間は気にしなくてよい）。選んだパターンも一言で提示する。

### Step 2：スレッズ・Xを同時に書く

`sns_post_cheatsheet.md`「X・スレッズの役割分担」のとおり、1つのネタから2媒体分を同時に作る：

- **スレッズ版**：経過・迷い・生々しさを残す。会話前提でやや長め。リストの使用頻度はXより高めてよい（ただし毎回ではない）
- **X版**：結論・一言だけを切り出す。背景説明を削ぎ落とし、初見向けに短く。リスト使用は半分くらいの頻度に

`sns_post_cheatsheet.md`「意外性・キレを強める書き方」の5技法（思い込みの再定義・意外な因果関係・パラレル構造・具体性・断定/軽い問いかけでの締め）は**毎回守る**。Step 1で選んだ構造パターンは**毎回変える**（技法とパターンは別レイヤー）。特にネタが人付き合い・社会的プレッシャー系なら「思い込みの再定義」技法を優先的に検討する。ただし三人称の法則化（「〜な人は全員そう」）はしない。書いたら「客観的に見て当たり前ではないか」を必ず自己チェックする。

文体は`examples_essay.md`の口癖・語尾をそのまま使う（「なんだかんだ」「けっこう」「わりと」等、てる・てた調とですます調の混在）。パチスロ・収益数字・note誘導は`sns_post_cheatsheet.md`の該当ルールに従う。

### Step 3a：機械チェック（必須・先に実行）

X版・スレッズ版の本文をそれぞれ一時ファイルに書き出し（スクラッチパッド）、実行する：

```
python uya/tools/qa_post_uya.py <X本文一時ファイル> <スレッズ本文一時ファイル>
```

**ERROR 0件が次工程への条件**。WARNは自己判断でよいが、内容を見て気になれば直す。ERRORが出たら該当箇所を直し、再実行してから次へ進む。

### Step 3b：自己チェック（機械チェックでは拾えないもの・必須）

Step 3aを通過したら、以下は人＝Claudeが見る：

- **開示ルール**：`personal_data.md`「開示ルール」表と照合。本名・顔・年齢・過去の職種名・けがの病名・運営ブログ名・パチスロで使った金額、が出ていないか
- **パチスロ・パチンコ**：立ち回り・勝敗金額・設定判別・店名・機種の推しが出ていないか
- **収益数字**：具体額を出す場合、直近の投稿で使いすぎていないか（月1回程度の目安）
- **note誘導**：フォロワー100まではURLを本文に直書きしていないか
- **s4lvとの重複**：同じ具体的なネタをs4lvが直近1週間以内に使っていないか（条件付き参照のファイルで確認）。s4lv側の「教える」角度になっていないか（UYA.は一人称の実況のはず）
- **反響を意識するポイント**（`sns_post_cheatsheet.md`該当セクション）：死にやすい書き出しになっていないか。返信が自然に生まれる終わり方になっているか。問いかけの中身がその投稿固有の言葉になっているか
- **当たり前チェック**：再定義・気づきの部分が「客観的に見て当たり前」に見えないか。**特に「自分の使い方が原因で当然そうなる結果」を気づきにしていないか**（例：作業でAIを使っているから作業の話しか出ない）
- **冒頭1行**：タイムラインで1行目だけを見て、何の話か分かるか（話題の名詞が入っているか）。前置きだけの1行目になっていないか
- **締めの問い**：問いを置く場合、手前の流れから自然に出ているか。「〜ませんか？」「〜ですか？」「〜ますか？」をいきなり置いていないか。読む人が自分の経験で答えられる形か。自分の立場を下げる問い・汎用的な世論調査型の問いになっていないか（形・作り方は`sns_post_cheatsheet.md`「反響を意識するポイント」が唯一の正。自信がなければ問いを足さず独り言で締める）
- **証拠画像**：売れた画面・収益画面を添える案にしない（購入者名・金額・日時が写る。開示ルール参照）
- **ペルソナ適合（2026-09-30新設）**：`sns_post_cheatsheet.md`「ペルソナ適合」のとおり、プロフィール（`rules/project_uya_accounts.md`）の人物と読者像に合うかを見る。「この読者が共感・コメント・拡散したくなるか」「プロフィールと矛盾しないか」「直近の投稿に『AI・ネット』の柱が入っているか」「UYA.で実際にやっていないことを書いていないか」
- **人間らしさチェック**：断定締め（パターン5）がそっけないスローガン調になっていないか。フィラーを付けた場合、前置きと文末の温度感が噛み合っているか（`sns_post_cheatsheet.md`「テンプレート感・硬さの原因」参照）
- **`uya_learnings.md`に照らして、既知のパターンを繰り返していないか**（分量は短いので全文確認）

引っかかった項目があれば、ユーザーに提示する前に直す。

### Step 4：ユーザーへ提示・すり合わせ

スレッズ版・X版をセットで提示する。**おすすめの投稿時間を媒体ごとに必ず添える**（時間の初期値・理由・返信できない日の扱いは`sns_post_cheatsheet.md`「頻度・時間帯」が唯一の正。ここには数字を書かない）。**この段階は1回で終わらせない前提**：オーナー自身の言葉づかい・意図に仕上がるまで、何度かやり取りしながら直す（2026-09-28確認）。ただし同じ指摘への修正は2回まで（ルート`CLAUDE.md`の行動規範どおり）。3回目になりそうなら、現状・試したこと・残る仮説を短く報告して方針を相談する。

### Step 5：保存

オーナーの確認が取れたら、`uya/posts/posts_x.txt`・`uya/posts/posts_threads.txt`へ**追記**する（新規なら作成）。各エントリの形式：

```
【YYYY-MM-DD】型：①実況ログ型（例） ／投稿予定：HH:MM ／ネタ元：journals/daily/YYYY-MM-DD.md
（本文）
```

投稿自体は手動（自動投稿キューは作らない）。保存後、保存先パスを1行で報告する。

**投稿後の運用**：投稿したら、可能な範囲で自分ですぐ返信する（X・スレッズ共通。特にスレッズは投稿後30分〜1時間の反応が重要）。ネタ元・アルゴリズム対応は`sns_post_cheatsheet.md`「反響を意識するポイント」参照。

### Step 6：学びの書き戻し（必須・2026-09-29新設）

このバッチでオーナーが本文を直した・却下した箇所があれば、**その意図**（文言ではなく「何を嫌ったか／何を求めたか」）を1〜3行で`uya/rules/uya_learnings.md`「オーナーの好み」へ追記する。**先に`sns_post_cheatsheet.md`・`examples_essay.md`に書く場所がないか確認し、あればそちらに書く**（学びの台帳への重複記載を避ける・2026-09-29反省）。修正がなければ何もしない。**この積み重ねが、次回以降の提案の精度を上げる仕組みの本体**なので省略しない。
