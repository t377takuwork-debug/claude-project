## 起動ゲート（会議を開く前に必ず確認）

次の3つを**すべて**満たすときだけ会議を開く。1つでも欠けたら開かない。

1. **不可逆性** — 決めたら簡単に戻せない（価格・アイデンティティ/プロフィール・実名や実績の開示範囲・目標数値・媒体をまたぐ運用ルールの変更）
2. **トレードオフ** — 対立する2つの利益があり、どちらも捨てがたい（例：高単価で位置づける vs 入口を広げる／実名で信頼を得る vs 開示リスク）
3. **いま決められる** — 結論が「データ待ち」にならない

満たさない場合は会議を開かず、代わりに次を提案する：

- 定型作業（記事本文・投稿バッチ・トーン是正）→ 該当スキル（`/note-article`・`/s4lv-post`・`/mbticode-post`・`/vivant-post`・`/junk-article`・`/post-review` 等）
- データ待ち → 「観測する指標を1つ」指定して終了（例：「4週間のスキ率と SNS 経由の記事 PV を見てから再検討」）
- 単純な事実確認・照合 → そのまま実行

## 3レンズ（合議メンバー）

詳細な思考モデルは `note_monetization_reference.md` Part 2。各レンズは「同意するだけ」禁止。自分の視点から疑問・反論・修正を持ち込む。

- **① 需要・ポジショニング**（Amy Hoy「Sales Safari」＋ Kotler「STP」）
  市場の痛みは本物か（表面でなく"言われていないこと"まで）。読者の実際の言葉を挙げられるか。競合記事との差分を1文で言えるか。セグメントは絞れているか（Step 0 のペルソナと照合）。

- **② 成約・価格・導線**（Nathan Barry「Authority」＋ Justin Welsh）
  タイトルの語彙・価格の根拠（note実勢：実用ノウハウ系平均1,842円／読み物系983円／文字数は売上に無相関）・ペイウォール位置・CTA・公開後の売上の谷対策・3層価格やメンバーシップ化の余地。

- **③ CEO（意思決定・アイデンティティ）**（Adam Enfroy「一人メディア企業のCEO」）
  Step 0 で読んだ**対象アカウントのコンセプト／アイデンティティ**との整合。不可逆リスク。仕組み化・レバレッジ。**最終決定権を持つ。**

## 証拠規律（決定が乗る主張にだけ適用）

**最終判断の根拠になる主張**には根拠の区分を明示する。雑談レベルの発言には不要。

- **【実績】** 対象アカウントの実際の販売・成約データ（記事名・価格・件数を伴う）
- **【観測】** 対象アカウントの `reference/` 等に記録された実データ（読者反応・SNS議論・アクセス解析）
- **【一般論】** 業界知識・理論・他者事例。確信度（高・中・低）を付す。`note_monetization_reference.md` 由来なら信頼度ラベル（【公式一次】等）も併記

**n=1ルール**：販売1〜2件など極端に少ないサンプルを根拠にする場合、「検証済みの法則」ではなく「次のデータで検証すべき仮説」であると明記する。他ジャンル・他アカウントの事例を使う場合は、対象アカウントへの転用可能性を一言評価する（購買心理の前提が同じか）。

**vivant 等の情報ベース・アカウントの例外**：実体験データがない前提のため、【実績】は自アカウントの販売データのみを指し、コンテンツの主張は【観測】（一次資料・報道・公式情報）と【一般論】で構成する。捏造した体験談を根拠にしない。

## 議論プロセス（2ラウンド）

### Round 1：独立見解
①②③がそれぞれの視点からテーマを評価する。同調不要。この時点で対立が出てよい。

### Round 2：CEO裁定
- ①②の間に**実在する対立**があれば、CEO がその論点だけを短く衝突させてから裁定する。対立が無ければ衝突フェーズは省く（**反論のための反論は作らない**）
- CEO は「何を優先し、何を捨てたか」を明示して1つの決定に落とす

大型判断（価格・リブランド・開示範囲・目標数値）では、Round 2 の衝突を必ず1回は通す。比率・トーン・文面レベルの判断では省いてよい。

## 出力フォーマット（この順序）

**[論点整理]** — アカウント名、テーマ、起動ゲートの確認結果、①②③の見解と対立軸の**要約**（発言の全文再現はしない）

**[決定]** — CEO の裁定。何を優先し、何を捨てたか

**[戦略案]** — 決定を実行に落とす具体策（秒で着手できる粒度）

**[収益・改善プラン]** — 予測数値と運用の打ち手

**[更新]** — 決定事項をメモリに追記する。
**投稿設計・運用ルール（本数・型・比率・時間帯・CTA・価格・ペイウォール位置 等）を変える決定は、同日中に Step 0 の表にある対象アカウントの運用ファイルにも反映する。** memory だけに残すと次のバッチ生成で消化されず、決定が空振りする（例：2026-08-28 の MBTICODE 分析で「型C増配が2週連続未実行」と判明）。

## 前提思想（全アカウント共通）

- 需要ファースト（市場の痛みから逆算）
- 実績作りを最優先（交流より先に1円を稼ぐ）
- AI で仕組み化し、人間味でトドメを刺す
- アカウント固有のコンセプト（s4lv＝「凡人の皮を被った、AI武装の超実践プレイヤー」等）は Step 0 の参照ファイルから読む。会議の判断はそのコンセプトと整合させる
- note.com の構造（`note_monetization_reference.md` Part 1）：メンバーシップの伸びが有料記事の約3倍／文字数は売上に無相関／有料記事の価格は公開後も変更可（サブスクは不可）／実用ノウハウ系の平均価格は1,842円・読み物系は983円／1ユーザー月間平均支払い2,696円
