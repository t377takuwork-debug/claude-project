# AI経営戦略会議（notekaigi）

Noteで稼ぐことに関わる**あとから戻しにくい大きな判断**を、3つの立場で話し合って1つに決める。全 Note アカウント（s4lv／MBTICODE／vivant／junk_juice／新規）で共通に使う。

**3つの立場の考え方と note.com のデータは `docs/reference/note_monetization_reference.md` を参照**（価格の相場・売れているテーマ・公式のヒント）。どのアカウントでもそのまま使える。

**書き方**：ふだんの言葉で書く（`docs/plain_language_glossary.md`）。専門用語が要るときは横に（かんたんな説明）。

## 会議を開く条件（開く前に必ず確認）

次の3つを**すべて**満たすときだけ会議を開く。1つでも欠けたら開かない。

1. **あとから戻せない** — 一度決めると簡単には元に戻せない（値段・アカウントの見せ方やプロフィール・実績をどこまで見せるか・目標の数字・複数の媒体にまたがる運用の決まり）
2. **どっちかしか取れない** — 2つの良いことがあって、両方は取れない（例：高い値段で「本格派」に見せる vs 入口を広げる／本名で信頼を得る vs 情報が広まる危険）
3. **いま決められる** — 結論が「数字が出るまで待つ」にならない

満たさない場合は会議を開かず、代わりに次を提案する：

- いつもの作業（記事の本文・投稿の束・口調の直し）→ それぞれのスキル（`/note-article`・`/s4lv-post`・`/mbticode-post`・`/vivant-post`・`/junk-article`・`/post-review` など）
- 数字待ち → 「見る数字を1つ」決めて終える（例：「4週間分のスキ率と、SNSから記事に来た人数を見てからもう一度」）
- 事実を確かめるだけ・照らし合わせるだけ → そのまま実行
- s4lv の気軽な相談 → `/note-advisor`

## 3つの立場（会議のメンバー）

くわしい考え方は `note_monetization_reference.md` Part 2。どの立場も「同意するだけ」は禁止。自分の立場から疑問・反論・直す案を持ち込む。

- **① 需要・立ち位置の担当**（Amy Hoy「Sales Safari」＋ Kotler「STP」）
  読者の困りごとは本物か（表面ではなく「口に出していないこと」まで）。読者が実際に使う言葉を挙げられるか。同じテーマの他の記事と何が違うかを1文で言えるか。読者像は絞れているか（Step 0 の読者像ファイルと照らす）。

- **② 売り方・値段・案内の担当**（Nathan Barry「Authority」＋ Justin Welsh）
  タイトルの言葉・値段の根拠（note の相場：やり方説明の記事は平均1,842円／読み物は983円／文字数と売上は関係なし）・無料と有料の境目の位置・次の記事への案内・公開後に売上が落ちたときの手当て・3段階の値段や月額会員制にできる余地。

- **③ 決める人（CEO）**（Adam Enfroy「一人メディア企業の社長」）
  Step 0 で読んだ**そのアカウントの見せ方・考え方**と合っているか。あとから戻せない危険。仕組みにして楽になるか。**最終的に決める権限を持つ。**

## 根拠の書き方の決まり（決定の根拠になる発言だけに適用）

**最終判断の根拠になる発言**には、根拠の種類を書く。雑談レベルの発言には不要。

- **【実績】** そのアカウントの実際の販売・購入データ（記事名・値段・件数つき）
- **【観測】** そのアカウントの `reference/` などに記録された実際のデータ（読者の反応・SNSでの話題・アクセスの数字）
- **【一般論】** 業界の知識・理論・他の人の例。自信の度合い（高・中・低）をつける。`note_monetization_reference.md` からの引用なら信頼度のラベル（【公式一次】など）も並べて書く

**1〜2件だけの結果の扱い**：売れた1〜2件など、ごく少ない数を根拠にするときは「確かめられた法則」ではなく「次の数字で確かめる考え」と書く。他のジャンル・他のアカウントの例を使うときは、そのアカウントに当てはまるかを一言添える（買う人の気持ちが同じか）。

**vivant などの「調べた情報をもとに書く」アカウントの例外**：自分の体験データがない前提なので、【実績】は自分のアカウントの販売データだけを指し、記事の主張は【観測】（元の資料・報道・公式情報）と【一般論】で組み立てる。作った体験談を根拠にしない。

## 話し合いの進め方（2回）

### 1回目：それぞれの意見
①②③がそれぞれの立場からテーマを評価する。合わせる必要はない。この時点で意見が食い違ってよい。

### 2回目：決める人（CEO）が判断
- ①②の間に**本当に食い違い**があれば、CEO がその点だけを短くぶつけてから判断する。食い違いがなければぶつける段階は省く（**反論のための反論は作らない**）
- CEO は「何を優先し、何をあきらめたか」をはっきり書いて1つに決める

大きな判断（値段・見せ方の変更・実績をどこまで見せるか・目標の数字）では、2回目のぶつける段階を必ず1回は通す。比率・口調・文面レベルの判断では省いてよい。

## 出力の形（この順序）

**[論点の整理]** — アカウント名、テーマ、「会議を開く条件」を満たしているか、①②③の意見と食い違いの**要約**（発言を全部書き出さない）

**[決定]** — CEO の判断。何を優先し、何をあきらめたか

**[やること]** — 決定を実行に落とす具体策（すぐ手をつけられる粒度）

**[収益・改善の見通し]** — 予想される数字と運用の手

**[更新]** — 決めたことをメモリに書く。
**投稿の設計・運用の決まり（本数・型・比率・時間帯・案内の一文・値段・無料と有料の境目 など）を変える決定は、同じ日のうちに Step 0 の表にあるそのアカウントの運用ファイルにも書き込む。** メモリだけに残すと次の作業で読まれず、決定が空振りする（例：2026-08-28 の MBTICODE 分析で「型C増配が2週連続未実行」と判明）。

## 前提の考え方（全アカウント共通）

- 読者の困りごとから逆算する（需要ファースト）
- まず1円稼ぐ（交流より実績を先に）
- AIで仕組みにして、人間味で仕上げる
- アカウントごとの見せ方（s4lv＝「凡人の皮を被った、AI武装の超実践プレイヤー」など）は Step 0 のファイルから読む。会議の判断はその見せ方と合わせる
- note.com の仕組み（`note_monetization_reference.md` Part 1）：月額会員制の伸びが有料記事の約3倍／文字数と売上は関係なし／有料記事の値段は公開後も変えられる（月額の値段は変えられない）／やり方説明の記事の平均は1,842円・読み物は983円／1人が1か月に払う平均は2,696円
