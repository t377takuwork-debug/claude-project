# /mbticode-analysis — MBTICODEのThreads（必要ならX）投稿を数字で分析する（「MBTICODEの投稿を分析して」「今週の分析して」と言われたときだけ使う。アカウントが曖昧なら先に確認）

Threads（必要ならX）の投稿を、スプレッドシートの数字で診断する。**ユーザーが「分析して」と指示したときだけ実行する**（定期実行はしない。将来、自動化するときはこのスキルを予約実行から呼ぶ）。

診断の基準は `brands/mbticode/analysis/rubric.md`（唯一の正）。診断そのものは、投稿を書いた側とは別の目で行うため、専用のサブエージェント `mbticode-analyst` に任せる。

**完了の条件**：診断結果をユーザーに3点で報告済み（分かったこと・確度・次の1つの変更）＋ユーザーがOKを出した分だけ `brands/mbticode/analysis/log.md` に追記済み。

## 手順

1. **入力を確認する**（不足していても止まらない。任意のものは、あれば使う）
   - 診断する期間の開始日（省略時は7日前＝週1回の運用を想定。`brands/mbticode/analysis/log.md` に前回の分析があれば、その対象期間の翌日を提案する）。ユーザーが「先週」「9/20以降」などと言ったら日付に直す
   - フォロワー数（あれば）／Xのスクショのパス（あれば）
2. **分析用の表を作る**（読み取りだけ・シートは変更しない）
   ```
   python brands/mbticode/tools/export_analysis_table.py --since YYYY-MM-DD
   ```
   - 診断する期間は「開始日〜2日前」（公開直後は数字が育っていないため除く）。基準線は直近4週間の全投稿から取る（`--baseline-days` で変更可）
   - 出力先 `brands/mbticode/tools/output/analysis_table_YYYYMMDD.md`。診断対象の本数（最大8本）と、母数の注意（基準線が12本未満など）を確認する
   - 「診断する期間に投稿がありません」の場合は、期間を広げるかユーザーに確認する
3. **分析役を起動する**（Agentツール・`subagent_type: mbticode-analyst`）
   - 渡す：表のパス／Xスクショのパス（あれば）／フォロワー数（あれば）
   - **渡さない**：投稿を書いた経緯・過去の分析メモ（`threads_insights_notes.md` など）・こちらの仮説（独立性を保つため）
4. **結果を検査する**（司令塔の仕事）
   - 分析役が引用した数字を、表と2〜3件突き合わせる（合っていなければ差し戻す）
   - 診断を書き換えない。こちらの補足や反論があるときは、診断とは分けて「司令塔の補足」として添える
5. **ユーザーに報告する**（3点だけ・ふだんの言葉で）
   - 分かったこと（診断した本数を添える）
   - 確度（高・中・低）と、保留にしたこと
   - 次に変えること1つ（変数1つ）と、確かめる数字
6. **ユーザーがOKを出したら** `brands/mbticode/analysis/log.md` の先頭に追記する（日付・期間・対象本数・要点・次の1つの変更・表のパス）。パターンの見直しが必要なとき（新しい傾向が出た・外れた）は、`brands/mbticode/analysis/patterns.md` の該当候補の根拠・反例・確度を更新する（これもユーザーのOKを取ってから）。手順書やルールへの反映は、ユーザーが指示したときだけ行う

## 守ること

- 数字は取れているものだけを使う（Views・Likes・Replies・Reposts・Quotes）。保存数・プロフィールクリック・リンククリック・フォロー増は推測で埋めない
- 反響のなかった投稿は個別に診断しない（型ごとの機械集計と、対照サンプルだけ表に載る）
- 分析の結果を、ユーザーの確認なしに投稿の作り方（手順書・スキル）へ反映しない
