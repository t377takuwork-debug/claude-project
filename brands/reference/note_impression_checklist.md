# noteの表示数（インプレッション）を見るときの点検表

オーナー提供の調査まとめ資料（2026-09-10）から、`/note-advisor` が実際に使う3つの場面だけを抜き出したもの。**記事の材料ではなく、相談に答えるときと数字を見るときの参考**。

元資料の立場：「AIがそう答えた」を根拠にしない。noteの中の仕組みで外から確かめられないもの（スキ○件でおすすめ、公開後○時間が勝負 など）は断定しない。

---

## 1. 数字を見るときの切り分け（KPIスクショを受け取ったとき）

記事ごとに、この順で見る：

**表示された数（インプレッション） → 開かれた数（PV） → スキ → コメント → フォロー**

| どこで詰まっているか | 考えられる原因 | 直すところ |
|---|---|---|
| 表示された数が少ない | 記事が見つけられていない／検索に引っかからない／タグが合っていない／おすすめに出ていない／テーマの需要が小さい | テーマをはっきりさせる・タイトル・タグ・関連記事のつなぎ・話題性 |
| 表示はあるのに開かれない | 表示されたときに「読みたい」と思わせられていない | タイトル・見出し画像・記事の切り口・読者にとっての得 |
| 開かれているのにスキ・フォローが少ない | 開いてもらえてはいるが、読後の満足につながっていない | 中身・独自性・情報量・読みやすさ・結論・根拠 |
| 開かれてスキもフォローも増える | うまくいっている | そのテーマ・切り口をさらに広げる |

「表示が少ない＝記事の質が低い」とすぐ決めない。まず上の切り分けをする。

---

## 2. noteを伸ばす施策の優先順位（相談されたとき）

**最優先**
- 記事のテーマをはっきりさせる
- タイトルを分かりやすくする（タイトルだけで「何の記事か・誰向けか・何が分かるか」が伝わる）
- 関連性の高いハッシュタグを5個くらい
- 読者にとって価値のある中身
- 同じテーマの記事を続けて積み上げる（基礎・詳細・比較・まとめ など）
- 記事の中に「次に読む記事」への案内を置く（関連記事・過去記事・まとめ記事）

**次に**
- おすすめに出やすい記事の作り（何について・誰向けかを明確に）
- 見出し画像（テーマが一目で分かる・タイトルと合っている・小さい画面でも読める）
- プロフィールページを整える（何を発信している人か・代表記事・どれから読めばいいか）
- 公式のお題・コンテスト（自分のテーマと合うときだけ）
- 話題になっているテーマ・新情報が出た直後に公開する

**外部から人を呼ぶ**
- X などのSNS（「公開しました」だけでなく、結論・興味を引く点・読む得 を出す）
- Google検索（テーマを明確に・検索される言葉を自然に・中身を充実）

**やりすぎない（過度に優先しない）**
- 投稿時間の細かい調整
- 毎日投稿
- タグの数を増やすこと
- 公開後○時間にこだわりすぎる
- スキの数でアルゴリズムを攻略しようとする／相互スキ
- 表に出ていない「アカウントの強さ」を数値化して考える

---

## 3. 採用しない話（「アルゴリズム攻略」系の相談が来たとき）

複数の調査に出ていても、次は「noteの確定した仕様」として運用しない（確かめる対象としての「まだ確かめていない考え」にはできる）：

- 特定の投稿時間が絶対に有利
- 特定の文字数が必ず最適
- タグを○個以上でペナルティ
- 公開後○時間以内が決定的
- スキ○件でおすすめ掲載／コメント○件で優遇
- 投稿頻度が一定を下回ると不利
- 相互スキでアルゴリズム攻略
- 表に出ていない「アカウントパワー」を数値化する理論

見るのは、実際に確認できる数字だけ：表示された数・開かれた数・スキ・コメント・フォロー・どこから来たか。
