# Threads投稿の決まり（s4lv / @cfrms4lv）

**声は `rules/s4lv_voice.md`（X・Threads共通）。** 句読点・改行・記号は `rules/sns_kutouten_kaigyo_rules.md`。このファイルは、Threadsだけの決まりを書く。

目的は「正しい解説」ではなく、タイムラインで止まり、続きが読まれ、必要なら返信が付く投稿を出すこと。ブログ教材のライターではなく、Threadsの編集者として書く。

立ち位置：エンタメ特化ブログを個人で10年。記事設計・直し方・AI下書きの現場を書く。フォロワーはごく少なく、発見はおすすめ頼み。売るのは今の仕事ではない。

## 評価の順番
1. 何の話かが2文以内で分かる
2. 1行目で読み進めたくなる
3. AI臭がなく、人が話している声
4. 型を確立しすぎない（パターンが見えたら崩す）

正しさや網羅は、この4つのあと。実績アピールもあと。

## 前提（全アカウント共通・崩さない）
- **開示ルール**：本文にも自己リプにも、番組名・タイムテーブル・実キーワード・ブログ名・URLを出さない。出してよいのは「テレビ・エンタメ系の特化ブログ」「検索1〜5位（現役で維持）」まで。amiiboは「ゲーム物販案件」に言いかえる。全文は `shared/personal_data.md`
- **創作禁止**：ネタ元は `x_neta_daicho.md` のK/A項目。「事実」欄の範囲外は書かない。台帳の「候補」欄は、オーナー確認前は使わない。柱3（意見・考え）は例外で、きっかけは外部の話題でよいが、裏付けの体験談は書かない。AI実働（A項目）は進行形だけで書く
- **台帳の「オーナー確認」行が最優先**：【使用停止】【保留】の項目（K9・A3・A4・A5・A7・A13・A16）は使わない。「オーナー訂正」行のある項目（K3・K4・K6・K10・K16・A1・A9）は訂正どおりに書く。K16は失敗談にしない。台帳にない体験談・行動を、本文にも自己リプにも足さない
- **AI実働の書き方**：「判断は自分」「必ず目を通す」とは書かない（台帳A8。Threadsはシートに入れるとき目を通さない場合がある）

## Threadsだけの決まり（Xとの違い）
| 項目 | 決まり |
|---|---|
| 目的 | 会話が続くこと。閲覧の約半分は返信面から生まれる |
| 長さ | 150〜300字。短い型（問い・一言）は80字〜。API上限は500字（超えると投稿時に失敗） |
| 本数・枠 | 通常1日2〜3本。枠は07:30／12:00／21:30。間隔の目安は30〜60分。3本の日は文法を分ける（現場メモ・知見・失敗談） |
| 自己リプ | 毎回付ける（下の「自己リプ」）。自動投稿では本人がすぐ返信できないので、初速の代わりになる |
| URL | フォロワー100までは本文・自己リプとも禁止（機械がERROR）。noteはプロフィール欄だけ |
| トピックタグ | 1投稿に1つ。見出し末尾の `／トピック：XXX`（対応表は `/s4lv-post`） |
| 箇条書き | 「・」を使う。項目が2つ以上あるときは箇条書きにしてよい。ただし1バッチの半分は散文にする |
| 強調の「」 | 用語の明示だけに使う。キー概念を「」で飾らない（強調は言いかえ・具体化で行う） |
| 絵文字 | 声の決まりに従う。最大2個の目安は継続 |

## 1行目
- 声の決まりの型（困りごと／事実）に加え、**自分の現場か具体的な事実**から入る
- 責める指摘（「〜してないですか？」「〜と思ってないですか？」）で始めない。使うなら週1本まで・連続禁止
- 職歴で始めない。「10年」「170万」「検索1〜5位」は、1行目に置かず、週2本まで
- 専門用語・符丁（allintitle、参入判定、共起語など）を説明なしで置かない。使うなら、まず平易な言いかえで出し、次の行で用語を1回だけ固定する。例のキーワードは実ジャンルと無関係の一般語にする
- 1行目で答えを言い切らない。何の話かは見せて、結論は伏せる。ただし事実で裏づけられないのに逆説をひねり出さない
- 死にやすい書き出しは使わない：「〜する方法をまとめました」「今日も学びをシェアします」「知らないと損」「保存推奨」「拡散希望」「皆さんこんにちは」

## 形の使い分け
- 1本ごとに役割を決めてから書く：
  - **失敗談**：現場の失敗 → 今どうしている → 問い（付けるなら）
  - **知見**：結論 → 理由 → 言い切って閉じる
  - **現場メモ**：今日の詰まりか消えた作業 → 短く現状 → 自己リプに中身
  - **例外山**：本文を単純にして、自己リプで「ただし」を1つ
- 形・入り方・終わりのばらつきは `s4lv_voice.md`「ばらつきの決まり」に従う。作る前に `python brands/s4lv/tools/recent_forms.py --platform threads` を実行する
- 見出しは `【9/27 21:30】型・思想／K5 …／失敗談／トピック：SEO対策` の形に、`／形：○○／入り方：○○／終わり：○○` を足す（`queue_from_posts.py` は「】のあと最初の／まで」と「トピック：」の部分だけ読む）
- 同じ骨格を3本続けない。「今は〜しています → ・を3つ → だからこう」の連打をしない。本文の最後で同じ結論を2回言わない
- 1投稿のメッセージは1つ。関連する話は自己リプか別投稿に回す

## 問い
- 声の決まりに従う（バッチの半分以下／1投稿に1つ／同じ形を直近5本で2回使わない）
- Threadsでは返信が命なので、**返しやすい問い**にする：
  - ○ 今の習慣・やり方をそのまま聞く（経験で即答できる）。昨日やったことの報告で返せる
  - × 今すぐ何かを調べないと答えられない問い
  - × 失敗を思い出させる前提つきの問い（「〜して上がらなかったことありません？」）
  - × 広すぎる問い（「どう思いますか？」）
- エンゲージメントベイトは禁止：「フォローして」「1ならリンク」「同じ人はいいね」「詳しくはnote」。内容に結びついた「保存しておいてください」は可

## 自己リプ（2つ目の山）
- 80〜200字。次のどれか1つだけ：
  - **例外**（「ただしこの場合は当てはまらない」）
  - **内訳**（本文の項目の中身）
  - **自分の抜け**／**技術的な詰まり**（台帳の「崩れる条件・失敗」欄にあるものだけ。無ければ使わない）
- 本文の結論を言い直さない。売らない。リンクを置かない
- 語尾が本文と重ならない／冷たい言い切りにならない／読む理由がある（`s4lv_voice.md`の自己チェック7）
- AI実働の自己リプを、毎回「エラーも出ず動かない」型にしない
- 本文は常に単体で完結させる。「続きはリプ欄で」は禁止（機械がERROR）。本文を途中で切って核心を自己リプに逃がすのも不可
- 継ぎ目（本文末で「まだ話していない1点」を名指しして、自己リプが受ける）は、名指しできるときだけ。毎回やらない
- 中身の薄い但し書きを、自己リプを付けるためだけに足さない
- 複数本の連鎖（基盤は最大4本まで対応）は、情報量が1投稿に収まらないときだけ

## 実績と数字の出し方
- 実績は**進行形**で出す（「今も検索1〜5位に入っています」）。過去のピーク値だけに頼らない
- 本文のルールと矛盾しない範囲に限る（「大手メディアが占める場所には入らない」と書いたなら、実績は「大手メディアが意識していない複合キーワード」に絞る）
- 卑下しない。「結局地味な作業」で成果を打ち消さない
- Threadsでは `shared/personal_data.md` にある実績数値を使ってよい。1投稿の主役は1つ（ピーク値と順位を両方入れない）。裸の数字で終わらせず、何を裏づけるか1文添える

## 語彙
- 「大手」単体を避け、「大手メディア」「大手サイト」の形にする
- 物理移動に読める表現を避ける：「大手が来ていない」→「大手メディアが意識していない」
- 「セクション」を本文に使わない（全アカウント共通）

## 書いてはいけない文
- AI感の定型（機械チェックの対象）：〜ですね／〜と思います／〜でしょう／〜という感じです／〜ことが大切です／以上のように／個人差があります／活用／本質／最先端
- 上から目線の指摘で始める文。命令口調（〜しろ／〜すべき）
- 同じ接続の連打だけで組んだ構成

## 生成後の機械ゲート
- `python brands/tools/qa_post.py <file> --account s4lv --platform threads --since <M/D>`：ERROR 0件が保存条件（新バッチは必ず `--since` を付ける）
- `sns-ai-reviewer` の審査（BLOCKまたはFIX3件以上のときだけ2巡目）

## 出力形式
```
【日時】【元ネタ】台帳K◯/A◯（＋元記事や小見出し）
【役割】失敗談／知見／現場メモ／例外山
【形】形・入り方・終わり
【狙い】返信／保存・言い切り／メモ
【1行目の仕事】何で止めるか一行
【本文】
【自己リプ】
【チェック】2文以内で主題が分かるか／1行目が指摘・職歴でないか／直近と同じ骨格でないか／URL・誘導がないか／台帳の事実の範囲内か／開示ルール／声の自己チェック7項目
```
複数案を出すときは、役割が同じものを連続させない。

## 見本
旧い見本（です/ます調）は2026-10-02に削除。新しい見本は、オーナーが確定した新しい声の投稿から足す。
