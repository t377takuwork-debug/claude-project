# s4lv 声の決まり（X・Threads共通）

**このファイルが「声」の唯一の正。** 声とは、語尾・話し方・雰囲気・主語・読点のこと。XとThreadsで同じ声にする（役割による違い＝長さ・1行目の細かい作り・自己リプライ・問いの回数などは、各媒体の決まりが引き続き持つ）。

## どうやって決めたか（2026-10-02）

- 既存のXやThreadsの投稿は参考にしなかった
- 材料は、オーナーの音声ジャーナルの文字起こし（`journals/daily/raw/`）と、同じ内容を濃さを変えて書き分けた見本から、オーナーが「近い」「遠い」を選んだ結果
- 近い＝話し言葉に近い声（だ調ベース）。遠い＝短い断片を積み重ねる淡々とした声（冷たく固く感じる）
- 文字起こしからは、語尾・口癖・話の運び方だけを取る。内容（経歴・健康・趣味など）は声の材料に使っただけで、投稿の中身にはしない
- ジャーナルが増えたら、同じ方法で声を更新する

## 声の決まり

| 項目 | 決まり |
|---|---|
| 基本の声 | だ調ベースの話し言葉に、「〜してます」を混ぜる。肩の力が抜けた、あたたかい声 |
| 主語 | **「私」も「自分」も使う**（オーナーはどちらも使う）。省いてもよい。「俺」「僕」は使わない。1つの投稿の中では、基本どちらかにそろえる（「自分で読み返す」のような言い方は、どちらの投稿でも使ってよい） |
| 問いかけ | 「〜ってことありません？」「〜ませんか？」のような、少し丁寧な問いを基本にする（例：「選べないってことありません？」）。「〜ない？」も使ってよいが、好みは前者。問う文は1投稿に1つまで |
| 読点（、） | **1文に1つまで。** なくても通じるなら削る。長くなったら2文に分ける |
| 雰囲気 | あたたかく、肩の力が抜けている。冷たい・固い言い方はしない |
| 使う語尾 | 「〜してる」「〜してます」「〜よね」「〜だよね」「〜かな」「〜んだよね」「〜んですよ」（続けて言う形なら「〜んだよね」は可） |
| 使わない語尾 | 「〜じゃん」「〜のよ」「〜だわ」「〜である」「〜のだ」。なれなれしすぎる、または固い |
| 強める言葉 | 「かなり」「結構」「ほんと」はふつうに使う。「マジで」「やばい」は積極的には使わないが、違和感がない文脈では使ってよい |
| くだけた言葉 | 「しんどい」「だるい」「めんどくさい」は使ってよい |
| 絵文字 | 過剰でなければ使ってよい（1投稿に多くて1〜2個の目安。使わない投稿のほうが多くてよい。2026-10-02オーナー確認） |
| 驚き・ツッコミ | 自然で過剰でなければ混ぜてよい（「え、」「いや、」のような軽い反応。連発しない。2026-10-02オーナー確認） |
| 実況・一言の材料 | 音声ジャーナルに話した一言を使ってよい（オーナー確認 2026-10-02）。その場の出来事に基づく投稿は、オーナーの一言が材料になる |
| 画像・スクリーンショット | 今は対象外（いまは文章だけのテスト中・2026-10-02オーナー確認） |
| 避ける言い方 | 短い断片を3つ以上続けて積む。断言の連打。「〜を実施」「〜に該当」のような固い漢語 |

## 1行目（最初の一文）

- **わかりやすさと、目が止まる力を最優先にする。** 一目で何の話か分かること
- 型は2つを軸にする。
  - 読者の困りごとから入る（例：「AIで書いた記事って、読み返すとなんか違和感あるよね。」）
  - 事実から入る（例：「AIっぽさって、機械のチェックだけだと消えないんですよね。」）
- 自分の現場から入る型、共通の現状から入る型も使ってよい

## 話の運び方

- 結論や感想を先に言う → 具体例 → 「ただ、」で逆の面 → 私の気づき
- 良くない点も隠さず、素直に言う。自分を持ち上げる言い切りは使わない

## ばらつきの決まり（AIで回している感を出さないため・2026-10-02オーナー依頼）

投稿が毎回同じ形・同じ問い・同じ語尾にならないようにする。**見る範囲は、同じバッチの中と、直近の投稿（目安は直近10本）の両方。** 作る前に、直近の投稿の1行目・問い・語尾・締めを並べて見てから書く。数字は最初の目安で、使いながら調整する。

### 全体
- 同じ形が続くと「機械が回している」感じになる。**直近の投稿と、1行目の入り方・組み立て・問い・締めの語尾を、できるだけ変える**
- 「だから〜」「なので〜」で締める、「〜って〜よね」で始める、のような**決まった言い回しの使い回しを避ける**
- 新しい投稿を作るたびに、ぜんぶ新しく考える（前の投稿の言い回しを少し変えて使い回さない）

### 組み立て（骨組み）
- 同じ骨組みを3本続けない。次のような形を順番に使い分ける。
  - 文章で流す型（散文）
  - 番号の手順を並べる型
  - 2つを比べる型
  - 短い一言と補足の型
  - ある場面の話から入る型（台帳の事実の範囲で）
- 番号の手順を使う投稿は、1バッチに2本まで
- 長さも混ぜる（短い3〜5行／ふつう／長め）

### 1行目
- 同じ入り方（困りごと／事実／現場／共通の現状／意外な一言）を、直近3本と続けない。1バッチで同じ入り方は2本まで

### 問いかけ
- 問いかけを入れる投稿は、バッチの半分以下にする。**問いのない投稿のほうが多くてよい**
- 問いは1投稿に1つまで。**同じ形を直近5本の中で2回使わない**
- 形の引き出し（最初の案。要らないものは消してよい）：
  1. 〜ってことありません？
  2. 〜ありませんか？
  3. 〜じゃないですか？（話し言葉）
  4. つい〜してしまいませんか？
  5. 〜の人、いませんか？
  6. （問いにせず）〜んですよね。と共感だけを置く
  7. 〜と言われたらどうします？
- 「どう思いますか？」のような、広すぎる意見募集の問いは使わない

### 語尾
- **同じ語尾が3行続かない。** 1つの語尾（「〜してる。」など）が、1投稿の文の半分以上にならない
- 締めの語尾は、直近3本と変える
- 語尾の引き出しを順番に使う：「〜してる」「〜してます」「〜かな」「〜よね」「〜なんだよね」「〜んですよ」「体言止め」。体言止めは続けて使わない
- 「〜ました。」で終える文が続かないようにする

### 形の引き出し（2026-10-02・他のアカウント5つの投稿を読んで作った案）

文章の中身と声は変えずに、**形・入り方・終わり**を入れ替える。使うときは、投稿の見出しに `／形：○○／入り方：○○／終わり：○○` のタグを付ける（下の語彙のどれか1つ）。

| 区分 | 引き出し（タグの語彙） |
|---|---|
| 形 | 散文／リスト（番号・「・」）／段階（「最初はこう、次はこう」）／物語（台帳の事実の範囲で）／話題所感（他の人の話や言葉への感想）／問い／見出し箇条書き／矢印（↓で流れを見せる）／一言（結論なし）／日常一言／節目報告／連投 |
| 入り方 | 困りごと／事実／自分の現場／共通の現状／外部の話／物語／他者の言葉／呼びかけ／見出し／日常／報告／問い／一言 |
| 終わり | 断言／問い／決意／励まし／保存促し／引き（続く）／笑い／所感／体言止め／共感 |

- **連投**：使っても使わなくてもよい。使うなら、1本目だけで意味が通る形にする（Xの発見用は1画面で完結させる決まりのため）
- **日常一言**：使ってよい（オーナー確認 2026-10-02）。開示ルール（`shared/personal_data.md`）に従う。UYA.と同じ素材を同じ週に使わない
- **教訓や結論で毎回終えない。** 一言の反応・実況・箇条書きのまま止まる投稿も混ぜる（人が書いている投稿には、結論のないものが多い）
- 形は変えても、**声（語尾・雰囲気）とテーマは一定にする**。強い断言の連打・大きな数字・煽る言い方は、他のアカウントの形から取らない（s4lvの声に合わない）
- 見出しのタグには「引用」「リプライ」の字を使わない（機械チェックが他人への返信と誤判定するため。形の語彙は「話題所感」）

### 作る前に見る道具（毎回）

`python brands/s4lv/tools/recent_forms.py`（`--n 10`・`--platform x|threads|both`）で、直近の投稿の形・入り方・終わり・長さ・問い・締めの語尾を一覧し、**最近使っていない形**と**偏りの注意**を出す。その候補から次の投稿の形を選ぶ。

### 作ったあとに見る（必須）
- バッチの1行目だけを縦に並べて読む → 同じ入り方が続いていないか
- バッチの締めだけを縦に並べて読む → 同じ語尾・同じ形が続いていないか
- 問いの形を並べる → 同じ形が重なっていないか
- 直近の投稿とも並べて見る（`posts_x.txt`・`posts_threads.txt`）

## 見本（同じ内容を決まりどおりに書いた形）

```
AIで書いた記事って、読み返すとなんか違和感あるよね。
機械のチェックだけだと、そこまで拾ってくれない。

だから私は、別のAIにも「AIっぽくない？」って採点させてる。
最後は私が読み返して決めてる。
```

## 提案前の自己チェック（オーナーの意図・2026-10-02）

投稿案を出す前に、次の7つを自分で確かめる。2026-10-02の調整で、オーナーが直した点の蓄積。

1. **言いたいことを1文で言えるか。** 全部の行が、その1文につながっているか（話題・主張・やり方を1本に詰め込まない。詰めると「結局何が言いたいの？」になる）
2. **1行目や問いで、誰でも知っている当たり前のことを言っていないか。** 読者が「知ってる」と思うだけの問いは、共感にならない。読者がまだ知らない事実や、具体的な発見から入る
3. **すでにXで出したテーマでないか。** `posts_x.txt` と台帳の使用履歴で確認する。台帳のネタが全部既出なら、無理に作らず、ネタ収集（`/neta-research`）かジャーナルの一言を材料にする
4. **外部の話題・機能は、元のページを開いて確かめたか。** 確認の度合い（原文を読んだ／要約ツール経由／検索結果の要約だけ）を分けて考える。根拠のない過去の断言（「これまでは〜だった」）は書かない
5. **自分が試していない機能・方法を、効果の予測（「楽になりそう」「効果がありそう」）で勧めていないか。** 「進めているのにやっていない」と読まれる。試していないことは「〜できる」と機能の事実で書く
6. **語尾が重なっていないか。** 「だから〜」「〜んですよね」「〜してます」の連発を避ける。伝聞の語尾（「〜んだとか」「〜らしい」）は、人づてに聞いた話・自分が試していない話にだけ使い、自分がやっている話には使わない
7. **自己リプライ：** 読む理由があるか／語尾が本文と重ならないか／冷たい言い切りになっていないか／URLがそのままコピペできるか（Xの誘導回）

### オーナーが採用した型（使ってよい）
- **機能紹介型**：「この機能、使ってますか？→こういう使い方ができる→注意点」。いまさら感のある機能でも、使っていない人には新しいので可（ただし上の5を守る）
- **人間らしい本音の締め**：「AIはだいぶ〜書けるようになったけど、結局まだ自分の手で直すことになるんですよね」のように、認めてから本音を言う形
- **手順型**：「〜を3段階で減らしています」＋番号の手順（各項目の長さ・語尾をそろえすぎない）

## まだ決めていないこと（決めるまでは現行の決まりを暫定で使う）

- 改行・空行・箇条書き・記号の形（暫定：`rules/sns_kutouten_kaigyo_rules.md`。ただし読点の上限は、このファイルの「1文に1つまで」が優先）
- 締め方（「〜ました。」で終えない、疑問符で閉じない、など）
- 問いかけの扱い
- 機械チェック（`brands/tools/qa_post.py`）と審査の基準（`docs/rubrics/sns_ai_tone_rubric.md`）を、この声に合わせて直すこと
- 古い文体の決まり（`feedback_s4lv_x_writing_style.md`・`feedback_s4lv_threads_writing_style.md`）の整理

## 古い決まりとの関係

声（語尾・雰囲気・主語・読点）については、**このファイルを優先する。** 古い文体の決まりに「語尾は〜」「素の話し言葉で」などの記述があっても、食い違うときはこちらが正。古い決まりは、整理が済むまでは残す。
