# MBTICODE Threads インサイト反映メモ

分析を行うたびに、ここへ「次バッチで反映すべき結論」を1エントリずつ追記する（新しいものを上に）。
`/mbticode-post`実行時はこのファイルの一番上のエントリを必須参照し、型・FW配分やCTA判断に反映する。

**頻度は固定しない（2026-09-19改訂）**：以前は「週次」を前提にしていたが、22日間放置されていた実績があり、固定スケジュール自体が機能していなかった。今後は**ユーザーが「分析して」と指示したタイミングで実施**する。`check_analysis_due.py`は「何日経過しているか」を伝えるだけの情報ツールとし、「期限切れ」「遅れている」という促し方はしない。

**手順**：`python tools/threads_analyze.py` で前回分析以降を自動集計（n・Views統計・外れ値・構造型別/FW別/トーン型別/冒頭フック別・外部返信合計・日別本数）→ その数字を読んで下記フォーマットで「観測／反映／未解決の課題」を手書き → `python tools/threads_analyze.py --commit` で実施日を記録。集計スクリプトは算術のみ、解釈は人が書く。

**いいね率とNote誘導クリックは別指標として観測する**（2026-09-16notekaigi追加。断罪型の不採用判断の副産物：いいね率が高くてもNote購入に繋がるとは限らないため、両者を混同して「反響が良い＝誘導効果も良い」と判断しない。週次分析では構造型別・FW別のViews/いいね率に加え、URL事後型・週1回計画的Note誘導枠のCTAが実際にクリックされたか（Noteフォロワー増・購入数）を分けて記録する）

エントリ形式：
```
## YYYY-MM-DD 週次分析
- 観測：（数字から分かったこと）
- 反映：（次バッチで具体的に変えること）
```
