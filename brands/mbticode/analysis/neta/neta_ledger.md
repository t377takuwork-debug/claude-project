# ネタ台帳（/mbticode-neta が追記する・新しいものを上に）

**2層に分けて記録する。**
1. **自分のネタ（切り口に変換済み・投稿に使うのはこちらだけ）**：外部の元ネタを参考に、自分の切り口へ作り直したもの
2. **元ネタ（収集した外部の投稿の記録・参照専用）**：`neta_sources.md` に分けて記録する（出典・数字・構造の観察だけ。**投稿の本文には使わない**）。

**借りるのはテーマと切り口の発想まで。文言・具体例・数字・固有の言い回しは借りない。** 元ネタには全文を保存しない。ユーザーがOKを出したものだけを記録する。

## 1. 自分のネタ（切り口に変換済み）

`/mbticode-post` の案出しで参考にするのは、**状態が「未使用」のこの一覧だけ**。元ネタ（`neta_sources.md`）の文言を見ながら投稿を書かない。

エントリ形式：

```
### N○｜自分のテーマ（1行）
- 元ネタ：M1・T2 など（`neta_sources.md` のID。複数可）
- 自分の切り口：（何を、どの角度で言うか。元の投稿と変えた要素を最低2つ：場面／主張／構造）
- 取り入れた要素／変えた要素：（反響を生んでいそうな要素のうち何を取り入れたか。型・テーマ・タイプのうち、元ネタと**一致するのは最大1つ**。一致数＝◯）
- 根拠：（`reference/` のどのタイプ特性か・`analysis/patterns.md` のどのパターンか）
- 借りていないこと：（文言・具体例・数字を借りていないと確認した）
- 類似チェック（日付）：元ネタの核＝（1行）／自分の核＝（1行）／着想の近さ＝低・中・高（中は書き直す・高は使わない）／表現の重なり＝最長一致◯字（`check_similarity.py`。10字以上は言い換え、20字以上は書き直し）
- 形式：完結型／続き型／URL事後型（誘導する記事の番号）。強化版の要素（基本版に足した要素・1つ）
- 状態：未使用／使用（日付・投稿の日時）／見送り（理由）
- 自分の投稿での結果：（Views・Likes・Replies・Reposts・Quotes。取れたら）
- Note記事：（複数の指標で、複数回反響があったら「企画候補」）
```

**Note記事化の目安**：自分の投稿で、複数の指標（Views・Likes・Replies・Reposts・Quotes）で反響があり、それが複数回あったテーマを、Note記事の企画候補に昇格する。
