# s4lv SNS投稿の審査基準（sns-ai-reviewer の唯一の採点基準）

> **使いみち**：X・Threads投稿をオーナーへ提案する前に、`sns-ai-reviewer` がこの表で採点する。PASS が出るまで保存しない。
> **対象**：s4lv のX・Threads投稿だけ。それ以外を渡されたら「対象外」と返す。
> **このファイルが決めること**：「何を、どの重さで見るか」だけ。決まりの中身は正のファイルにある（一覧は `brands/s4lv/CLAUDE.md`）。ここには写さない。

---

## 0. 審査しないこと

- 声の好み・センス・訴求力（たとえの強さ、1行目が「強い」かどうかの感想）
- 100点満点の採点。返すのは PASS／FAIL と指摘表だけ

見るのは、決まりを守っているかだけ。それ以外で指摘を作らない。この節に項目を足す・外すのは `/notekaigi` で決める。

## 1. 判定の枠組み

| 重さ | 意味 | 提案してよいか |
|---|---|---|
| **BLOCK** | 出せない。作り話・開示の違反・機械チェックのERROR・根拠のない主張 | だめ。必ず直す |
| **FIX** | 出せるが質を落としている。決まりにはっきり反している | だめ。直してから（最大2巡） |
| **NOTE** | 判断が分かれる・運用上の注意・次回へのヒント | よい。指摘を添えて提案する |

- **PASS ＝ BLOCK 0件 かつ FIX 0件**。NOTE は残ってよい
- FAIL → 司令塔が直して再審査する。**同じ指摘への直しは2巡まで**。2巡のあとに残る FIX は、いまの状態・試したこと・残る理由を添えて、オーナーの判断に回す
- 機械チェックで ERROR が出たら、すぐ FAIL
- WARN は1件ずつ「直す（FIX）／許す（NOTE）」に振り分ける。許すときは理由を書く

## 2. 審査員の態度

- 褒めから入らない。「全体的に良い」で済ませない
- すべての指摘に、**投稿番号と行の引用**を付ける。引用できない指摘は出さない
- 根拠は、この基準の項目と、正のファイルの節で示す
- 見つからなければ「該当なし」と書く。無理に指摘を作らない
- **本文は書き換えない**。直し方は1文で示す

## 3. 採点項目

### A. 機械チェック（`brands/tools/qa_post.py`）

| 見ること | 重さ |
|---|---|
| ERROR が1件でもある | BLOCK（すぐFAIL） |
| WARN を1件ずつ振り分ける | 1件ごとに FIX／NOTE |

### B. 材料の根拠（正＝`sns_common_rules.md`「ネタの出どころ」「作り話をしない」）

| 元ネタ | 見ること | 重さ |
|---|---|---|
| 全部 | 見出しに元ネタが書いてあるか | FIX |
| 全部 | 本文・自己リプライに、元ネタにない体験談・行動を足していないか | **BLOCK** |
| 台帳K・A | 本文の主張・手順・数字・「私はこうしている」が、その項目の「事実」欄の範囲内か | **BLOCK** |
| 台帳K・A | 「オーナー確認」行の訂正どおりか。台帳にない番号や「候補」の項目を使っていないか | **BLOCK** |
| 台帳K・A | 「崩れる条件・失敗」を、実際より強い言い切りや体験談に仕立てていないか | FIX |
| 外の話題（柱3） | 意見の裏づけに、体験談を書いていないか | **BLOCK** |
| 外の話題（柱3） | 元の投稿と、入り方・具体例・結論の並びが2つ以上変わっているか。確かでない情報を言い切っていないか | FIX |
| ジャーナル | 本文の体験が、元の記録の範囲内か。「出してよい範囲」を守っているか | **BLOCK** |

### C. 開示（正＝`sns_common_rules.md`「開示」）

| 見ること | 重さ |
|---|---|
| 番組名・アーティスト名・タイムテーブル・実際のキーワード・ブログ名・URLが、直接にも間接にも出ていないか | **BLOCK** |
| 定期的に更新する表の形の記事だと分かる言葉が残っていないか | **BLOCK** |
| ジャンルが「テレビ・エンタメ系」より細かくなっていないか（音楽番組・特定のイベント） | BLOCK |

### D. わかりやすさ（正＝`s4lv_voice.md`「1行目」「わかりやすさ」「書き方の形」）

| 見ること | 重さ |
|---|---|
| 1行目で、何の話かが具体的に分かるか。定義・決まり・断言・業界の言葉で始めていないか | FIX |
| 断言を、読者が何の話か分かる前に置いていないか | FIX |
| 業界の言葉を、言いかえや例なしで使っていないか | FIX |
| 名詞に固めた言い方・遠回しな言い方を、ふつうの言い方に直せているか | FIX |
| 読点が1文に2つ以上ないか。疑問文が「？」で終わっているか | FIX |

### E. AIっぽく見える形（正＝`s4lv_voice.md`「ばらつきの決まり」「使わない言い方」）

| # | 見ること | 重さ |
|---|---|---|
| E1 | 全文が「悩み → 解決 → 教訓」の決まった流れになっていないか | FIX |
| E2 | 箇条書きの各項目が、同じ長さ・同じ形・同じ語尾でそろいすぎていないか | FIX |
| E3 | 締めの一文が、格言・教訓ふうになっていないか | FIX |
| E4 | 文の長さが全部同じになっていないか | FIX |

### F. 実績・数字・AIの話（正＝`sns_common_rules.md`「実績と数字の出し方」「AIの話の書き方」。数字の一覧は `shared/personal_data.md`）

| 見ること | 重さ |
|---|---|
| `personal_data.md` にない実績・数字・体験がないか。比較したデータのない成約率・効果を言い切っていないか | **BLOCK** |
| 数字が、手法・判断・現状と同じ文か隣の1文にあるか（数字だけで押していないか） | FIX |
| 大きい実績の数字・実績の言葉が、1行目にないか。同じ日に2回以上出ていないか。やり方とセットか | FIX |
| AIの話を、完了した実績のように言い切っていないか | BLOCK |
| 実際に目を通していない流れに、「判断は自分」「必ず目を通す」と書いていないか | BLOCK |

### G. 媒体ごとの決まり

| 媒体 | 見ること | 重さ |
|---|---|---|
| X（正＝`x_post_generation_rules.md`） | 反響の狙いが1つに決まっているか／1行目が1行か／見つけてもらうための投稿が1画面で完結しているか／誘導の回は1日1本以内か・本文にURLがないか・自己リプライに読む理由があるか | 各 FIX |
| Threads（正＝`threads_post_generation_rules.md`） | 役割が決まっているか・同じ骨格が続いていないか／1行目が職歴でないか・答えを言い切っていないか／問いが返しやすいか／自己リプライが決まりどおりか（本文が単体で完結・結論の言い直しなし・URLなし）／長さ | 各 FIX |
| 両方 | 2本柱の比率（型・思想6：AI実働4）から大きく外れていないか | NOTE |

### H. 声とばらつき（正＝`s4lv_voice.md`）

| # | 見ること | 重さ |
|---|---|---|
| H1 | 声：だ調ベース＋「〜してます」か。使わない語尾・使わない言い方がないか | FIX |
| H2 | 主語が「私」「自分」か。1つの投稿の中で、基本どちらかにそろっているか | NOTE（「俺」「僕」はFIX） |
| H3 | 冷たい・固い言い方になっていないか（短い断片の連続、断言の連打、固い漢語、解説記事の口調） | FIX |
| H4 | 問いが1投稿に1つまでか。広い意見募集の問いでないか | FIX |
| H5 | 絵文字が多すぎないか（1投稿に3個以上） | FIX |
| H6 | 同じ回の中で、形・入り方・終わり・締めの語尾・問いの形が、同じ組み合わせで3本続いていないか。見出しにタグが付いているか | FIX（3本続き）／NOTE（タグなし） |
| H7 | 教訓や結論で毎回終えていないか（4本以上のとき） | NOTE |
| H8 | 自己リプライ：語尾が本文と重ならないか。冷たい言い切りになっていないか | FIX |
| H9 | 言いたいことが1文で言えるか。全部の行が、その1文につながっているか | FIX |
| H10 | 1行目や問いで、誰でも知っている当たり前のことを言っていないか | FIX |
| H11 | 試していない機能・方法を、効果の予測で勧めていないか。外の話題の確かめた度合いと、言い切りの強さが合っているか | FIX |

## 4. 返す形（この形以外で返さない）

```
## 審査結果: PASS
（または）
## 審査結果: FAIL（BLOCK n件／FIX n件／NOTE n件）

対象: <パス>　媒体: <x|threads>　投稿数: <n>本
機械チェック: ERROR <n> / WARN <n>（WARNの振り分け: FIX <n> / NOTE <n>）

| # | 重さ | 区分 | 投稿・行 | 指摘（本文の引用） | 直し方（1文） | 根拠 |
|---|---|---|---|---|---|---|
| 1 | BLOCK | C | ②L3 | 「古い数字や日付を新しいものに直してもらう」 | 記事の種類が分かるので「古くなった記述を新しい情報に置き換える」に言いかえる | 基準C／sns_common_rules「開示」 |
| 2 | FIX | D | ①L1 | 「YMYLかどうかを先に判定します」 | 1行目を読者の状況から始め、業界の言葉は2文目から言いかえる | 基準D／s4lv_voice「1行目」 |
（BLOCK→FIX→NOTE の順。同じ重さの中は投稿番号の順）

### 総評（3行以内）
- いちばん効く直し: #n（理由を1文）
- 良い点: 1つだけ、投稿・行つきで（無ければ「特記なし」）
- 次回へのヒント: 1文（無ければ省く）
```

- 見出しの件数は、**表の行数**と合わせる（同じ種類の指摘は1行にまとめ、行の欄に該当箇所を並べる）
- 指摘が0件の区分は、表に出さない。全部0件なら表を省いて「指摘なし」と書く
- 2巡目からは、「前回#nの対応: 解消／未解消（理由）」を表の前に1行ずつ書く

## 5. この基準を変えるとき

- 見る項目や重さを変えるときは、このファイルを直す。決まりの中身を変えるときは、正のファイルを直す（手順は `brands/s4lv/CLAUDE.md`「決まりを変える手順」）
- 審査で「基準にないが、明らかにおかしい」ものが出たら、NOTE として指摘し、基準に足すかどうかを司令塔からオーナーに提案する（審査員が自分で基準を増やさない）
