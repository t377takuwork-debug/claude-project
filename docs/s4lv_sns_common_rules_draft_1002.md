### ネタを選ぶ順番
1. 既出を確認する。`posts_x.txt` と `posts_threads.txt` の直近、台帳の自動記録、可能ならXの実際のタイムライン。台帳の自動記録は遅れることがあるので、投稿ファイルを必ず見る。XとThreadsで、同じテーマを同じ角度で使い回さない
2. 「いまさら感のある基礎の話」や頻出ネタは避ける。K1は頻出のため当面使わない
3. 台帳が一巡・既出なら、外部の話題かジャーナルに進む。`/neta-research` はオーナーが指示したときだけ回す。足りないときは「回しますか」と聞く
4. 使ったら記録する

## 前提（崩さない）
- 創作禁止：台帳の「事実」欄にない体験談・行動を、本文にも自己リプにも足さない
- 開示ルール：出してよいのは「テレビ・エンタメ系の特化ブログ」「検索1〜5位（現役で維持）」まで。番組名・タイムテーブル・実キーワード・ブログ名・URLは出さない。全文は `shared/personal_data.md`
- 開示ワードを残さない：番組表／タイムテーブル／セットリスト／出演順／放送日・放送予定／「毎年おなじ時期に検索される」「去年書いた記事」「数字や日付の差し替え・更新」など。一般語に言いかえる。`qa_post.py` の `disclosure-tell` が検知する
- 検証前の情報を、確定した実績として書かない。AIの話は進行形で書く

## 実績と数字の出し方
- 数字は、読者が確かめられる手法・判断・現状と、同じ文か隣の1文に置く。単独で威圧しない
- 実績は進行形で出す。過去のピーク値だけに頼らない
- 本文の主張と矛盾しない範囲に限る
- 卑下しない。誇張もしない。数字は台帳より低めか、ぼかして書く
- トロフィー数字（170万PV、アドセンス月収65万、成約件数と報酬など）は、1行目に置かない。必ず「どのやり方でそうなったか」とセットにする。使う頻度は媒体の専用ファイルが決める
- 小さい現在進行の数字は、`shared/personal_data.md`「X本文で文脈つきなら自由に使える数字」の範囲で積極的に使ってよい
- 1投稿の主役の数字は1つ
- 使わない：比較データのない成約率・効果の断言、未達成・未検証の数字

## わかりやすさ（最優先）
- 抽象語の前に「何の話か」を置く。主語や対象を省かない
- 「大手」は具体化する（大手メディア／大手サイト／企業サイト／公式サイト）
- 業界語・符丁は、1行目に説明なしで置かない。まず平易な言いかえで出し、次の行で用語を1回だけ固定する。例のキーワードは実ジャンルと無関係の一般語にする
- 「1つ多く」「1つだけ」のような数の言い方で、「それだけやればいい」と誤読させない
- 分かりにくいカタカナ語・像を結べない語を避ける
- 「セクション」を本文に使わない

## 使わない言い方（トーンの共通）
- 命令口調／短い断片を3つ以上続けて積む／強い逆説のフック
- 「〜んだ。」で終える語尾（続けて言う「〜んだよね」は可）
- 「正直、〜ます。」型の告白風のヘッジ
- 格言・教訓風の締め
- 「どう思いますか？」のような広い意見募集の問い
- 次回誘導の多用（1日1回まで）
- AI感の定型：〜ですね／〜と思います・感じます／〜でしょう・ではないでしょうか／〜という感じです／〜ことが大切・重要です・お勧めします／以上のように・このように・まとめると／個人差があります・一概には言えません
- 煽り、嘘、中途半端な知識の断言、事実の誇張、全否定
- 「リード文（1行目）はAIでは書けない」という断言

## 外部の話題の確かめ方
- 元のページや公式の情報を開いて確かめる。確認の度合い（原文を読んだ／要約ツール経由／検索結果の要約だけ）を分けて考える
- 「Xの主張のみ」のものは、「そういう話も出ている」止まりにする
- 根拠のない過去の断言は書かない
- 自分が試していない機能は、効果の予測で勧めず、「〜できる」と機能の事実で書く
