2026-09-28、note公式ヘルプセンター（help-note.com）とnote実機（note.com/hashtag/...）で確認した内容。ハッシュタグを付けるすべてのNote記事（uya・s4lv・vivant・junk_juice等）で、この内容を土台にする。

## 1. 基本ルール（公式ヘルプ「ハッシュタグとは」）

- **タグ付けの4つの視点**
  1. どのようなタイプの記事か（例：#日記 #エッセイ #レシピ）
  2. 何のテーマについて語るか（例：#学び #暮らし #旅行）
  3. どのようなシリーズ・商品名か（例：#noteのはじめかた #ガンダム）
  4. 語るテーマの関連ワード（例：#マリオ → #任天堂 #nintendoswitch）
- **個数の目安**：「特別な理由のない限り3〜5個程度」（「より多くのひとに書いた記事を読んでもらうために」では「5つぐらいが効果的。大事にしたいキーワードから厳選」）
- **上限・文字数**：1記事最大10個。先頭の「＃」を除いて30文字まで
- **使える文字**：全角・半角のひらがな・カタカナ・英字・漢字・数字、一部記号（`_`〜`ー`）。**ハイフン（-）は使用不可**

出典：[ハッシュタグとは](https://www.help-note.com/hc/ja/articles/900004261886)／[ハッシュタグに使用できる文字](https://www.help-note.com/hc/ja/articles/40810212577945)／[より多くのひとに書いた記事を読んでもらうために](https://www.help-note.com/hc/ja/articles/360015040773)

## 2. 【重要】2026-09-15の検索仕様変更（デザインが古い記事はまだこれを知らない）

ハッシュタグで検索したときに表示されるページは2種類あり、**タグごとにどちらが出るか決まっている**（自分では選べない）。

| ページ | URL | 表示される記事 | 対象になりやすいタグ |
|---|---|---|---|
| **キーワードページ**（2026-09-15〜、一部タグに拡大） | `note.com/tag/〇〇` | **noteのAIが記事の内容を読んで**関連すると判断した記事。ハッシュタグの有無では決まらない | 投稿数が多い一般的なタグ（例：エッセイ、退職 等） |
| **ハッシュタグページ**（従来型） | `note.com/hashtag/〇〇` | そのハッシュタグが**設定されている**記事だけ | コンテスト・お題企画のタグ／投稿数が少ないタグ |

**意味すること**：よく使われる一般的なタグ（エッセイ・退職・働き方 等）を付けても、**記事の中身がそのキーワードと関係ないとAIに判断されれば、検索結果に出ない**。逆に、タグを付けていなくても内容が合っていれば表示されることがある。
公式も「**記事の内容に合ったハッシュタグを選ぶことが、読んでもらう機会をふやす近道**」と明言している。→ **タグは「話題のタグを付ける作業」ではなく「本文の内容と一致しているか」で選ぶ。**

出典：[検索したときに表示されるページについて](https://www.help-note.com/hc/ja/articles/62344323192857)／[ハッシュタグをつけた記事が、ハッシュタグページやキーワードページに表示されない](https://www.help-note.com/hc/ja/articles/40811733012889)

## 3. 実在確認の調べ方（実機で確認済みの手順。「需要」は測れない点に注意）

**重要：件数の多さは「需要がある」ことの証明ではない。**件数が表しているのは「そのタグ（キーワード）に該当する記事がどれだけ存在するか」という**供給量**であり、読者がそのページをどれだけ見に来ているか（アクセス数・需要）は公開情報からは分からない（「人気」順の並び替えはあるが、スキ数などの具体的な数値はページ上に表示されない＝2026-09-28に実機確認）。

候補タグを決めたら、保存前に1つずつ次を行う。**目的は「需要の高いタグを見つけること」ではなく「存在しない・誰も使っていないタグを外すこと」**。

1. ブラウザで `https://note.com/hashtag/<候補タグ>` を開く
2. **`note.com/tag/〇〇` にURLが変わり、件数と記事一覧が出た** → 実在する一般的なタグ（キーワードページ扱い）。件数の大小そのものは採否の決め手にしない
3. **URLが `note.com/hashtag/〇〇` のまま・記事がほとんど出ない／空白** → ほぼ誰も使っていない、または造語。避ける
4. 表示された記事一覧をざっと見て、**自分の記事と読者層・トーンが近いか**を目視で判断する（同じタグでも、想定と違う話題の記事ばかり並ぶことがある）。これが公開情報から確認できる、実質的に一番意味のあるチェック
5. **件数が数十万〜数百万件と極端に大きいタグは、実在は確実だが競合も非常に多い**（新着ソートではすぐ埋もれる）ことは考慮に入れる。大きい＝有利、ではない

**実機確認例（2026-09-28）**
- `退職` → `note.com/tag/退職`・247,894件（実在確認OK。人気/新着はあるがスキ数等の数値は非公開）
- `エッセイ` → `note.com/tag/エッセイ`（キーワードページ扱い。実在する一般タグ）
- 存在しない造語タグ → `note.com/hashtag/〇〇`のまま・記事なし（不採用の合図）

## 4. 「お題」「コンテスト」タグ（note公式が別枠で用意している仕組み）

note.com/contests に、公式が用意した専用タグの一覧がある。ハッシュタグとは別の3つ目のURL形式（`note.com/contest/〇〇`）を持ち、**個別記事のスキ数が数字で表示される**（通常の`/tag/`ページでは非公開）ため、実在確認だけでなく実際の反応も目視できる貴重な枠。

| 種類 | 特徴 | 期限 | 掲載場所 |
|---|---|---|---|
| **お題企画** | noteが独自開催。「書くネタに迷ったとき」向けの常設テーマ（例：#自己紹介 #仕事について話そう #とは）。ジャンル別に一覧化されている | **基本的に常設・期限なし** | note.com/contests「書きたいテーマを探してみよう」 |
| **コンテスト** | 企業とのコラボ。1〜2ヶ月の応募期間・審査・賞金/賞品あり | **期限あり**（応募期間終了後もタグ自体は使えるが、新規の受賞対象にはならない） | note.com/contests 上部「募集中」 |

**使い方の判断基準**
- お題企画のタグは、**内容が合っていれば期限を気にせず使ってよい**（`note.com/contests/finished`に載っている＝終了しているのはコンテストの方で、お題企画は基本的に載れ替わらない）
- コンテストのタグは、**懸賞目当てで内容と無関係につけない**。応募条件（フォロー必須等）が付くこともあるので、使うなら`さっそく応募`から概要を確認してから
- 調べ方：`note.com/hashtag/<候補>`を開いて`note.com/contest/〇〇`にURLが変われば、お題/コンテストタグ。個別記事のスキ数が見えるので、**近いテーマの記事がどのくらい反応を得ているか**を実際に確認できる

**毎回チェックする際の絞り込み方（2026-09-28確定。全件を読むと無駄が多いため）**

`note.com/contests`は200個以上のタグが並ぶため、記事を作るたびに全部読む必要はない。次の手順で絞る。

1. `note.com/contests`を1回読み込む（`finished`は見なくてよい。もう使えないタグの記録用でしかない）
2. アカウントに関係ないカテゴリ（エンタメ・マンガ・旅行・ゲーム・音楽・スポーツ・フード・美容・読書・アート・教育・育児等）は読み飛ばす。UYA.で見るのは**上部の期限付きコンテスト一覧・ビジネス・ライフスタイル・創作**の3カテゴリだけで十分
3. その中から、**その記事固有の中身と実際に重なる言葉**が入っているものだけを候補にする（アカウントのジャンルと合うだけでは不十分。記事ごとに判断する）
4. 候補になったものだけ個別ページを開いて実在確認・スキ数・トーンの近さを見る（全候補を深追いしない）

**実機確認例（2026-09-28、UYA.の自己紹介記事で検討）**
- `#自己紹介`（お題・496,164件・`note.com/contest/自己紹介`）：まさに自己紹介記事向けの公式お題。掲載記事はスキ数が数件〜千件超まで幅広い
- `#退職エントリ`（お題・4,878件・`note.com/contest/退職エントリ`）：「仕事を辞めた経験」がテーマそのもので、並んでいる記事（退職の経緯・その後の心境）がUYA.の記事のトーンと非常に近い。規模も大きすぎず埋もれにくい
- `#仕事について話そう`（お題・188,947件）：キャリア全般。UYA.の内容とも重なるが#退職エントリの方が内容一致度は高い
- 期限付きコンテスト（#AIとできたこと 等）は、この記事の主題（退職・パチンコ）とは合わないため対象外。本文が「AIを使って作業時間が短縮した」という切り口に寄るなら、将来的な別記事で検討の余地あり

## 5. UYA.など「当事者エッセイ」系アカウントへの当てはめ

- **視点1（タイプ）**：#エッセイ #日記 など、記事の形式を表すタグ
- **視点2（テーマ）**：#働き方 #生き方 #退職 #ブログ など、内容そのもの
- **視点4（関連ワード）**：#会社員 #フリーランス #在宅ワーク など、読者が検索しそうな属性語
- 視点3（シリーズ名・商品名）は、UYA.のように特定の作品・商品を扱わない記事では基本的に該当なし
- **本文中に出てくる言葉と一致するタグを優先する**（2の仕様上、内容と無関係なタグは表示機会が増えない）
- **お題企画のタグ（§4）は、内容が一致するなら積極的に候補に入れる**。個別記事のスキ数が見える分、他の一般タグより「読者に響いているか」を判断しやすい

## 6. 注意点

- 「AIコンテクストネットワーク」（書籍・映像などの作品名タグを付けると対応する作品ページに記事が載る仕組み）は、書籍・映像レビュー向けの機能。UYA.のような体験談エッセイでは基本的に関係しない（出典：[「AIコンテクストネットワーク」について](https://www.help-note.com/hc/ja/articles/56330534120729)）
- 「タグの数を増やすこと」自体は効果を保証しない（`brands/reference/note_impression_checklist.md`の既存整理と整合。やりすぎない項目として明記済み）
- パチンコ・パチスロを直接連想させるタグ等、アカウント固有の開示ルールに反するタグは、需要があっても使わない（`uya/shared/personal_data.md`「開示ルール」が優先）
